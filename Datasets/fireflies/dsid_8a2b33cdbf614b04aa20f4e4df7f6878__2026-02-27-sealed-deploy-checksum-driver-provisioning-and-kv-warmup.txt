[03:30] Speaker 2: (crosstalk) and grub entries?

[03:48] Priya Shah: Switching to runtime perf — KV cache warmup. For chat workloads the biggest p99 wins come from preloading KV caches for common prefixes. We recommend a two-stage warmup: (1) synthetic prefix replay to populate LRU caches and page mapping; (2) targeted warmup of hot prompts extracted from your logs.
[04:06] Tomás Ruiz: How do you run synthetic prefixes offline?
[04:10] Priya Shah: We build a small warmup harness that runs tokenized prefixes through a headless runtime. It replays prefixes in random interleaving with adjustable concurrency to prime KV shards. It emits CSV with first-token latencies and token-per-second throughput. We'll share the harness as part of the sealed bundle.
[04:26] Tomás Ruiz: Are there special flags for KV cache prefetch to avoid cache churn?
[04:29] Priya Shah: Yes, set aggressive cache TTL for warmup, and run a low-overlap schedule to avoid evicting hot entries. In practice: 1) set prefix_cache_multiplier=2 for warmup run, 2) run at 0.25x expected QPS for 10-30 minutes; 3) after warmup revert TTL to normal. These keys are in our runtime config file.

[04:48] Speaker 3: (mumbled) quant stuff?
[04:51] Priya Shah: We recommend starting with int8 quant on non-critical models — it's a good cost/latency tradeoff but watch degradations in some QA benchmarks. For customer models we supply a quant profile (per-layer sensitivity) and a validation harness. For latency-sensitive chat models, int8 reduced token latency by ~15-25% in our tests but increased nll on rare tokens; for embeddings we prefer fp16.
[05:17] Elena Mora: If int8 causes accuracy drift, can you fallback to a float variant automatically?
[05:20] Priya Shah: Yes — our smart routing supports per-request model variant selection. In Dedicated/on-prem you can set a policy: if quality metrics exceed threshold in monitoring, switch traffic to a non-quantized variant or route low-risk traffic to int8. We also support canary rollouts of quant profiles.

[06:08] Leila Ahmed: Any concern about replay attacks on the license blob if someone grabs it physically?
[06:12] Jared Lin: The offline license blob is single-use and contains a nonce tied to the host's attestation machine-id. Our license-manager validates TPM/HSM attestation on activation. If someone copies the blob it won't activate on another host. We also include a time-bound window in the activation metadata.

[06:32] Tomás Ruiz: For multi-GPU perf — is NVLink required or can you run over PCIe and still keep throughput?
[06:38] Priya Shah: PCIe is OK for many workloads but for large context models NVLink reduces inter-GPU allgather cost a lot. Our recommendation: for >100k token cache footprints or very large KV shards prefer NVLink; otherwise optimized NCCL over PCIe works if PCIe gen is high and topology is balanced.

[08:58] Jared Lin: Quick perf note — batching windows: for chat we see sweet spot ~30-50ms collection window for low-latency interactivity with batching; increasing to 80-100ms gives better throughput but adds latency. We expose batching.ms and max_batch_tokens in runtime config.

[09:19] Priya Shah: Continuous batching (streaming) reduces latency variance; we use a hybrid: prefer eager token emit once first token ready, while collecting subsequent tokens for batch compute. That setting is tunable per route.
