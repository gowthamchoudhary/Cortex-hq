Hi Olivia — great to hear the demo landed well. Thanks for the usage sample, that helps a lot.

High-level summary (and I'll attach the formal rate card PDF in a moment):

1) Chat Completions (structured chat API)
   - Billing unit: combined input + output tokens. We meter tokens on the full exchange (prompt messages + generated messages).
   - Example: 2k prompt + 1k generated = billed on ~3k tokens.

2) Responses (newer, consolidated endpoint)
   - Billing unit: we measure 'response units' that normalize streaming/structured outputs. For most workloads this also maps to input+output tokens, but we apply a different unit conversion for streaming and function-calling payloads (we surface it on the rate card as 'response units per 1k tokens').
   - Example (rough): your 2k prompt + 1k generated would convert to ~3 'response unit' blocks (see attached math table).

3) Legacy /completions endpoint
   - Old completions billing maps to legacy token buckets; historically teams treated input tokens separately. We provide a migration mapping in the rate card so you can translate historical invoices to the new units.

Important notes:
- For quoting and budgeting, the easiest is to convert to a single baseline (we recommend the Chat Completions token basis) — the attached PDF includes mapping tables and the per-unit prices by tier.
- Committed discounts: standard committed-usage tiers start at 3–6 month minimums for small pilots; meaningful discounts (10–20%) typically require a 12-month monetary commit or a committed QPS/throughput contract.
