Elena — thanks for the quick note. From a tech-ops standpoint I wanted to surface a few implementation details so your engineers can eyeball feasibility before we draft the SOW:

Auth / SDK setup:
- We support two auth flows for Private: 1) customer-managed API keys provisioned into your KMS + mTLS between your VPC and agent nodes; 2) OIDC with SCIM provisioning for user-level access.
- SDKs: Node (>=16) and Python (>=3.9) have a built-in streaming client and structured-output helper. We'll share the example repo (link in related_links).

Embedding / Reranker path:
- Indexing: our recommended flow is on-the-fly embeddings at ingest (using a cost-optimized embedding model) with a nightly re-embed job for changed content.
- Reranker: use a dedicated higher-capacity model pinned to the rerank route. We'll recommend a quantized 8-bit variant for cost if you tolerate marginal quality difference; otherwise we can run a 16-bit fallthrough.

Model routing / policy considerations (high level):
- Route-level policy: map routes to model classes (search-embed, search-rerank, booking-gen).
- Cost policy: per-route unit-cost threshold that triggers routing to a cheaper model variant when average cost/token exceeds X over a 5-minute window.
- Latency policy: p95 latency SLO configured per route; if p95 exceeds threshold and fallback capacity exists, automatic shift to lower-latency model variants or regionally closer nodes.
- Fallback chain example: primary (hosted-accurate) -> cost-fallback (hosted-quantized) -> reserved-dedicated -> private-onprem. Fail-open behavior can be disabled for PHI routes.

Elena / team — following up with a concise architecture proposal (summary below) to make the integration operational for a 2-week pilot. I'll drop the YAML and a sample Helm chart in the repo.

Architecture summary:
- Ingress: SDK clients call Redwood SDK; SDK authenticates with short-lived keys (rotated via your KMS) for Private.
- Inference plane: split by model-function: embeddings cluster (cpu+gpu mixed), rerank cluster (gpu-accelerated, reserved capacity), generator cluster (gpu, burst autoscale).
- Cache: prefix / KV cache for session-level tokens and common embeddings; TTL = 24h for embeddings cache in pilot.

Model routing policy (concrete):
- Routes:
  * /search/embed -> model: emb-small-v1 (hosted)
  * /search/rerank -> model: rerank-xxl (dedicated)
  * /booking/create -> model: gen-structured-v2 (private allowed)
- Policy triggers:
  * cost_threshold_usd_per_minute: 50 (per-route) -> switch to emb-small-q8
  * latency_p95_ms: 650 -> if exceeded for 2 consecutive windows, route to regional-closest pool or dedicated fallback
  * PHI_flag: true/false per-route (if true, fail-open = false and routing restricted to dedicated/private pools)
- Fallback chain (priority order): primary -> quantized-hosted -> reserved-dedicated -> private.

Observability & evals:
- We'll ship an eval harness that replays a 5k sample of your queries to compare reranker precision/recall across model variants.
- Cost reporting: token-level billing and per-route cost aggregation; set alerts at $X/day for pilot.
