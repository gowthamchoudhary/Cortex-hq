Hi James —

Appreciate the clear ask. Below is our proposed adjudication checklist and a pragmatic evidence-turnaround schedule tailored for RFP diligence. I’ve attached a lightweight evidence matrix template (evidence_matrix_template.xlsx) to make it easy for your evaluation team to index items.

Adjudication checklist (short form):
1) Event detection window: Redwood uses a rolling 1-hour window for availability events and rolling 5-minute windows for latency percentile breaches.
2) Primary signals: production ingress logs (per-token/route counters), per-region synthetic probe manifests, and our span-based error traces.
3) Probe primacy: For cross-checks, we treat customer-facing synthetic probes (those run from your test harness or jointly agreed probe endpoints) as authoritative for window alignment; otherwise Redwood’s global synthetic probes are used.
4) Evidence types accepted: a) server-side telemetry exports (CSV/Parquet) with timestamps and request IDs; b) synthetic probe manifests (JSON) including probe IDs and run parameters; c) sampling of trace IDs with timestamps and top-level errors; d) configuration snapshots showing routing policy at incident time.
5) Normalization and clock sync: All timestamps must include timezone/UTC offset. If discrepancies exist, our adjudication uses NTP-synced timestamps and a documented offset correction procedure (see measurement methodology below).
6) Redaction/PII: We accept redacted logs; requestor must provide unredacted data via an SFTP link or encrypted Drive share if required for legal review.

Evidence delivery schedule (for RFP diligence):
- Small requests (≤ 2 probes or ≤ 24h window): 72 hours from receipt.
- Medium requests (≤ 7 probes or ≤ 7 day window): 5 business days.
- Large evidence bundles (multi-region, >7 day windows, or legal preservation): 10 business days + agreed-upon staging.

James / Rachel / team —

Below is a concise technical appendix you can include with the adjudication checklist. I’ve tried to be explicit about computations so your SRE reviewers can reproduce results.

1) Window definitions and percentiles
- Availability: an instance (or route) is considered 'unavailable' if 50%+ of requests to the route fail during a rolling 1-hour window. Global availability is weighted by successful request counts per region.
- Latency: p95/p99 computed on successful requests only, using a rolling 5-minute window and aggregated to hourly roll-ups for billing/SLO calculation.

2) Synthetic probes vs production telemetry
- Prefer production telemetry for billing and credits. Synthetic probes are used for corroboration; if synthetic and production disagree, we run reconciliation using request IDs and probe manifests.
- We retain synthetic manifests for 90 days by default; longer retention can be added as a procurement add-on.

3) Clock sync and offset handling
- All Redwood servers are NTP-synced to stratum-1. If customer-provided probes show offset > 2s vs Redwood time, we publish an offset correction procedure. Reconciliation uses the probe's recorded offset labs and the server-side ingestion timestamp as ground truth for ordering.

4) Sampling and privacy
- Span sampling can be configured; when full traces are restricted for PII reasons we will provide trace-level summaries and error aggregates with correlated request IDs (redacted where necessary).

5) Evidence integrity
- Delivered evidence includes a SHA256 manifest and a short load-script used to recreate the analysis tables; we include an index of trace IDs and sample rows for quick checks.

6) Dispute resolution timeline
- Initial adjudication within 5 business days of evidence receipt. If additional investigation required, an outcome within 15 business days unless an agreed legal hold applies.

If helpful I can produce a one-page reproducibility checklist your auditors can run against our artifacts.
