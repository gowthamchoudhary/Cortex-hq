On Fri, Oct 16, 2026 at 9:07 AM Alice Park <alice@heliosoft.com> wrote:
> We started seeing a P99 latency spike around 08:45 this morning...

I've pulled the dashboards and the KV eviction heatmap — this looks like a classic hot-lane cascade + HOL blocking across batch lanes. Short summary of what I'm seeing:
- Eviction rate for the prefix-store jumped 12x at 08:44; median KV residency fell from 18s -> 3s.
- Batch lane utilization shows oscillating spikes: lanes fill very quickly then stall while KV fetches time out, causing backlog and lane swap thrash.
- Prefetch/readahead was disabled for this route due to a prior mem regression; that means the runtime is reacquiring keys on each request and we're thrashing the cache.

Temporary mitigations I'm about to apply (will announce changes):
A) Lower max_batch_delay from 12ms -> 4ms for the affected service (reduces queue buildup).
B) Increase prefix_store_shard_count to reduce hot shard contention (quick patch + graceful rollout).
C) Pin the top 5 keys for a 1-hour window using the KV affinity API (non-disruptive).
D) Enable prefetch for the route at a low concurrency cap (to validate memory behavior).

I expect to see P99 drop within 10-15 minutes after A + C. If not, we'll open a rolling eviction-safe restart path.

I'm also creating OPS-4128 in Jira with the full diagnostic payload and will attach the runbook link.
