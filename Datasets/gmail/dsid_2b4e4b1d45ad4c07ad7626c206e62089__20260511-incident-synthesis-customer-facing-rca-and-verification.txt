Team — please review the attached draft RCA and the validation packet. Key technical points to confirm:

1) Root cause: a regression in the cache-eviction controller (introduced in 2026-04-28 deploy) that incorrectly scheduled large-scale KV cache invalidation during rolling updates. The controller created a spike in memory pressure on inference workers, causing the runtime to restart workers that held hot KV state. When workers restarted, some in-flight requests that depended on cached prefix state observed token drop/partial outputs.

2) Why the fallback failed earlier: our automatic reroute policy attempted to fall back to a smaller model variant, but because the worker restarts coincided with a brief service registry lag, a subset of requests were routed to workers still rebuilding KV state.

3) Corrective actions (PRs and deploys):
  - Revert the eviction controller change and harden the scheduling (deploy completed 2026-05-09 02:45 UTC).
  - Add pre-checks to avoid eviction when live inference load > 10% of steady-state.
  - Add telemetry: per-worker KV eviction traces and an eviction-rate SLI.
  - Add an automatic hold during rollout if registry lag detected.

4) Customer verification steps (draft): run the included test harness (small request set) that includes requests with cached prefixes, verify 0% token drops for the sample ids, and confirm latency within baseline.

Please add or edit. I’ll consolidate and send to Tim and Anna after approvals.
