Hi Oliver —

Short answers: we can absolutely use 10.11.0.0/16 for the inference fleet; there is no /20 minimum for the short-term staging cluster. For production we recommend reserving at least /18 for autoscaling headroom if you expect high concurrency.

Edge agent ports (high-level):
- TLS control channel: 443 (outbound)
- Token refresh/metrics: 8443 (outbound)
- KV sync (internal): 10250–10260 (peer-only)
- Health and admin: 9100 (optional to expose to management subnet)

If you choose VPC peering: you are responsible for route propagation and cross-account route table entries; no NAT required between peered VPCs if CIDRs do not overlap. PSC: we can publish private endpoints and avoid peering, but it requires proxying and changes to DNS resolution.

For the on-prem package: we will provide onprem-installer-v2.1 (attached) which includes an offline bundle + install manifest. The installer requires a 500 MB ephemeral download for third-party libs if not using fully air-gapped mode.

Attachments: onprem-installer-v2.1.tar.gz (installer bundle)

Hi all —

A few operational points for the network review:
- TLS termination: We support client TLS with mutual auth for agent-to-cloud control plane; if you need HSM-backed certs we can integrate with your KMS (PKCS#11 flow).
- DNS: If you pick PSC we ask for an internal DNS zone (e.g., redwood.lumenix.internal) so our SRV records resolve for service discovery.
- MTU: if you have jumbo frames in your datacenter, set MTU >= 1500 on peering interfaces to avoid fragmentation.

Also attaching a short install checklist that our infra team uses for air-gapped installs. It lists required packages, container image whitelists, and manifest keys.
