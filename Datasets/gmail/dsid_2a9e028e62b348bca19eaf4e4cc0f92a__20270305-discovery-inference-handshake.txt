Alex / Priya — thanks again for the time today. Quick recap from our call and proposed next steps so we're aligned before the POC kickoff.

High-level goal
- Surface: support live anomaly scoring in-app (sub-second UX for analyst flows) while batching higher-throughput backfills.

Pain points you shared
- Current model endpoint has p95 around ~420ms for single-request scoring in non-batched mode (we saw latency spikes during concurrent bursts).
- Streaming/interactive UI accepts partial results and needs predictable token-arrival behavior (UX jitter is the blocker).
- Concurrency: peak interactive concurrency ~120 concurrent analyst sessions, expected to grow to ~200 during business-critical hours.

Current stack (what you told us)
- Inference endpoints run on ECS with Triton-backed model containers; some bespoke request multiplexing and a Redis-based KV cache for short-term prefixes.
- No centralized routing for fallback models — teams degrade to an older model when overloaded, causing inconsistent output.

Success criteria for the POC (proposed)
- Latency: end-to-end p95 <= 110ms for single-request scoring (non-streaming) at 150 concurrent sessions.
- Streaming UX: first-token latency < 80ms, steady token pacing with max jitter < 40ms for streaming interactions during peak load.
- Throughput: sustain 600 QPS with <1% request error rate and a graceful fallback policy that maintains user-facing responses within SLOs.

Redwood preliminary suggestions
1) Route interactive vs batch traffic to different capacity pools to avoid head-of-line blocking.
2) Use prefix/KV caching on hot prompts and enable small-window continuous batching for background workloads.
3) Configure a streaming-optimized model variant with reduced KV copy overhead; we can supply a quantized variant for cost testing.
4) Canary an automatic fallback that prefers an ephemeral CPU-based low-latency model only when GPU tail latency exceeds thresholds.

- A short list of 8–10 prompt templates we want to consider in the UX-sensitive paths.
- Any compliance constraints (data retention, keys) for Private deployment considerations.
