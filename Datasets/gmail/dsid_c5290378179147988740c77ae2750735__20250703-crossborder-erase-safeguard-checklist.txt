Hi all — technical notes for the runbook and options we should surface on the call. I'm listing the log/backups surface area and recommended approach: 

1) Data categories (examples):
   - Application event logs (app-prod-logs) — low cardinality, retained 30 days by default.
   - KV/embedding cache snapshots (kv-snapshots) — periodic immutable snapshots, normally 14 days.
   - Full backups (s3-managed) — incremental daily + weekly fulls, default retention 90 days (configurable).
   - Audit logs / token traces — retained 365 days for enterprise customers but can be scoped.

2) Approach for a scoped 90‑day investigatory window:
   - Tagging: add dataset tags (novus-pilot:retain-90d) at snapshot creation.
   - Isolation: keep EU data in EU buckets/regions only; snapshots encrypted with customer KMS and never egress to non‑EU regions.
   - Immutable snapshots & escrow: provide one immutable snapshot per week kept in an escrow container (read‑only) for the 90 days; can be exported on request.
   - Deletion workflow: deletion requests flow through a two‑step orchestration (mark-for-delete -> retention grace -> purge). For carveouts we set a hold flag that prevents the purge job.

3) Operational controls & audit:
   - Every retention-hold change will write an audit event (user, reason, TTL) and create a signed manifest.
   - We can surface a retention-hold report as a CSV if Legal needs evidence.

4) Constraints / tradeoffs:
   - Cost: immutable snapshot escrow increases storage and retrieval costs; we'll provide estimate.
   - Time to restore: searching within immutable snapshots is slower; expected retrieval SLA 6–12 hours for full export.

I'll attach the runbook draft and a small test checklist. Kimberly — if Novus confirms EU‑only constraint we'll mark the snapshots non‑egress and add the crossborder clause to the DPA addendum.
