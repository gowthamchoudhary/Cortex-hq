Marissa (cc Aditya) —

We need to lock an explicit overhead allocation policy for the Standard Cost Model outputs before Console/Optimize ship the new breakdowns. The recurring customer/support issue is “Console doesn’t match invoice” and internally we’re also seeing inconsistent “what counts” across dashboards vs FP&A.

Proposal (for v1 / Q1 reporting):

1) The Cost Model API must return BOTH:
- request-attributable cost (marginal): compute + request-specific runtime overhead (e.g., per-request scheduler time if you include it), excluding pooled/idle capacity and platform overhead
- fully-loaded cost: request-attributable + allocated overhead

2) Overhead definition (what’s included):
- capacity overhead: idle/buffer capacity for SLOs, failed/aborted jobs, warm pools
- platform overhead: control plane, observability, oncall/SRE allocation, networking egress where not directly attributable, shared storage where not directly attributable
- excludes: R&D / model onboarding / GTM, and anything we don’t treat as COGS

3) Allocation method:
- basis: GPU-hour equivalent (by hardware SKU) derived from runtime-reported “gpu_time_ms” (or equivalent) + approved adjustment for batch efficiency; allocate overhead as an uplift factor by deployment mode
- show explicit policy metadata in the API response so we can audit and so Console can explain it

4) How it should show up in Console:
- breakdown table must show separate line: “Overhead (allocated)” with tooltip text (policy + basis)
- default “Total” should be fully-loaded (so it’s reconcilable to finance rollups), but we should allow a toggle/secondary view for marginal cost for engineering users

I attached a 1-pager with the suggested language and the initial rate assumptions. These rates are adjustable, but we need the shape/versioning right.

Confirmed — we’ll implement this as the product policy for v1.

Summary of the agreement (for our release notes / internal doc):

A) Cost Model API outputs will include three top-level cost primitives:
- Request-attributable (marginal)
- Overhead (allocated)
- Total (fully-loaded)

B) Overhead is defined as capacity + platform COGS overhead (excluding R&D/GTM) and is allocated via a fixed uplift policy table keyed by deployment mode + hardware SKU (+ region only if needed). No real-time utilization dependency in v1.

C) UI/UX defaults:
- Console per-request detail: default marginal, with toggle to fully-loaded
- Console aggregate dashboards: default fully-loaded, with toggle to marginal
- Overhead shows as a single line item (not split across prefill/decode)

D) Optimize what-if defaults:
- Savings and ROI default to marginal deltas
- Fully-loaded projections may be returned with disclaimer language about scaling assumptions

E) Auditability:
- API will return policy metadata (policy id/version and effective dates + basis/method).
