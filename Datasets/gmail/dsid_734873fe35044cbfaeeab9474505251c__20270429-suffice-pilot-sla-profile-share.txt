Alex — quick technical follow-up with the numbers you asked for and a small caveat on measurement methodology.

End-to-end assumptions in our perf profiles:
- Tokenization included on the host (BPE); numbers reflect server-side tokenization cost.
- Network assumptions: 1x 10Gbps NIC, RTTs typical within same region (us-west) ~2–5ms; profiles do not include additional cross-region network delay.
- Measured with continuous-batching (16ms), KV cache hit-rate ~18% for repeated prefixes in test corpus.

Sustained throughput -> GPU mapping (approx):
- rw-medium-8bit-v1: one A10G-equivalent GPU supports ~250–280 tokens/sec under our mix (32 token prompts). For your 120 peak concurrent requests with average 60 tokens per request, that's ~7200 tokens/sec peak — implies ~26 GPUs if you require no batching. With Redwood batching & caching we typically cut token/sec demand per GPU by ~6–8x for this workload; conservatively plan for 4–6 GPUs for pilot peak coverage with autoscale/burst to 8 GPUs.
- rw-small-quant-v2: roughly double throughput per GPU; good candidate for classification-only paths.

Cost sketch for pilot (ballpark):
- 2 GPUs reserved (baseline): $12k / month (est) — should cover steady daytime QPS with heavy batching.
- Autoscale to 4 GPUs on sustained 70% utilization: incremental $6k / month.
- Burst capacity (on-demand) to 8 GPUs during launches: extra $10–15k depending on duration.

Attachments: redwood_profile_suffice_v1.pdf contains the raw percentile traces, test harness parameters, and the prompt set used for cached vs cold runs. suffic_prompt_set_v1.json has ~20 canonical prompts we recommend tracking for quality regression alerts.

Note on quality regression monitoring: we recommend running an initial labeled eval set (we can help seed 200 examples) and setting alerts for automated A/B checks with a 2% significance threshold — triggers an automatic rollback to the fallback model.
