Hi Ari — thanks for the clear list. Quick technical notes below; I’ll follow up with a 1-pager and the SOC2 packet.

1) Dedicated + Customer-Managed KMS:
- We support integration with AWS KMS (imported key material using KMS Import Key feature) and Google Cloud KMS with imported keys. Keys remain under your control; Redwood requests an envelope-wrapped DEK for runtime operations.
- Limitations: Cloud KMS imported keys do not equate to an HSM appliance in your data center; they are FIPS-compliant at the provider level depending on region and KMS config.

2) Private (VPC / On-prem) + HSM:
- Private allows colocating a hardware HSM (YubiHSM/Thales) or connecting to your on-prem HSM cluster via a secure tunnel. This meets FIPS 140-2 hardware requirements and gives you full control over key lifecycle and attestation.
- We can run an on-prem agent to keep keys off the cloud if required.

3) Retention and tamper-proof exports for 7 years:
- Short term: Dedicated can retain logs for X days (configurable per workspace). For 7-year obligations we recommend an ETL that exports signed log bundles to customer-controlled cold storage (S3 Glacier with Object Lock/WORM or on-prem immutable store).
- Private: we can deploy direct-to-cold-storage export and integrate with your SIEM/archival policies.
