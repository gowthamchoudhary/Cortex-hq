Alex / Vanessa — thanks, appreciate the telemetry. Quick answers and an initial pilot sizing proposal:  

Short answers to Alex's questions:
- Can Dedicated hit ~40ms server-side p95? Yes, with the right pod size (NVIDIA H100-class profile or equivalent inference-optimized instance), tuned batching disabled for autocomplete (token streaming), and KV cache warm. Our internal bench shows ~30–45ms p95 for similar 13B setups in Dedicated with single-request routing and small batching disabled. We'll set an acceptance target of <= 45ms p95 server-side for the pilot to account for variance.
- Autoscale/burst behavior: Dedicated supports fast vertical scaling (add GPUs to pool) and warm standby capacity. For 4–5 minute spikes we recommend configuring a short burst window with warm standby instances and a fast fallback to Hosted API if capacity is exhausted. Cold-start penalty for new instances is typically 10–30s for model load; with warm-standby that goes down to sub-5s.

Pilot sizing proposal (high level):
- Dedicated pool: 3 x inference-optimized nodes for steady 50 qps with headroom (estimated sustained), with 2 warm standby nodes to cover burst headroom up to ~180 qps when combined with request routing and traffic shaping.
- Config: no batching for autocomplete; small token limit (128); KV cache enabled; quantization profile medium (FP16/4-bit mixed where safe).
- Canary: route 10% traffic to Dedicated first, monitor p95 and error rate for 48h, then gradually increase.
- Acceptance criteria: server-side p95 <= 45ms, success rate > 99.5%, no user-facing errors during pilot window.

Estimate and artifacts: attached a rough cost estimate (redwood_dedicated_estimate.xlsx) and a short pilot playbook (pilot_playbook.pdf) that lists runbook steps, monitoring dashboards, and rollback steps.

Risk notes and alternatives:
- If Dedicated capacity cannot be approved, Hosted API with aggressive prefix caching plus an L2 cache at the edge can approximate latency targets for some traffic patterns but will require repeated testing and is more expensive at scale.
- If procurement requires a shorter/cheaper pilot, we can run a 30-day focused pilot on a single autocomplete shard at lower cost to validate p95.
