Hi Alice — thanks for the clear list. Looping in Soojin (infra) for technical detail; answering at a high level here and attaching a draft SIG answers workbook + attestation PDF. More granular files are attached in a follow-up.

Quick answers (summary):
- Prompt/generation logs: default hosted retention = 30 days for full request/response records. Customers on Dedicated/Private can configure retention; hosted customers may request shorter TTLs via support ticket and we can apply per-tenant retention as a config flag (Console + API).
- KV cache / prefix caching: KV cache entries are ephemeral and scoped to serving instances and workload; by default entries expire between 1–6 hours depending on model & config. We keep a debug window of up to 7 days for error investigation (rotating ring buffer, restricted access).
- Training on customer data: Redwood does not use customer prompt/generation data from a customer’s private or dedicated environment for base model training. For hosted customers, unless explicitly opted-in via a written agreement, we do not incorporate customer prompts into training.

Hi Tom / Alice — quick technical matrix below (hosted defaults). Attaching a CSV with per-model variations.

Host plan TTLs (defaults):
- Full request/response logs (hosted API): 30 days (retention measured from ingest timestamp).
- Aggregated telemetry/metrics: 365 days (used for platform health, aggregated; not customer PII).
- KV cache / prefix cache default expiry: 4 hours (typical); range configurable 1–6 hours.
- Debug window (ring buffer with restricted access): up to 7 days for a rolling snapshot; access requires an approved support ticket and is audited.

Operational notes:
- Per-tenant shorter TTLs: We can set a per-tenant retention down to 0 days (ephemeral) on hosted with a support ticket.
- Dedicated/Private: retention fully customer-configurable and typically set via config in the Console or on-prem flags.
- Access & auditing: any access to the debug window is logged in the audit trail and surfaced in the Console.

Suggested contract language (two short variants you can use):
A) Provider will not use Customer Prompt, Completion, or Conversation Data to train or improve Provider models unless Customer provides prior written consent.
B) Provider will not incorporate Customer Data into model training pipelines and will honor per-tenant opt-out controls; any exception requires a documented, signed opt-in.
