Adding implementation notes from the runtime side:
- IP allowlist: We expose a controlplane.ingress endpoint that can be fronted by an internal ALB with Source IP filtering. For on-prem/VPC deployments we accept a single CIDR or single IP; Acme should provide the NAT EIP for the jumpbox.
- mTLS for SCIM: Redwood supports client cert validation. For Private customers we recommend using a short-lived client cert pinned to the jumpbox and rotated via your internal CA or Hashi Vault.
- Service accounts: SCIM provisioning should be done with a dedicated service principal; we surface the principal in audit logs as user=scim-service@acme.

Known caveats:
- If Acme plans to use a highly restricted egress (no DNS), the control plane needs to be able to resolve our internal validation endpoints. We can provide an internal resolver address if necessary.
- SCIM rate limits: default 20 req/s for provisioning; we can increase with a Dedicated commit.

I'll prepare the sample mTLS client cert rotation playbook and a minimal firewall rule set.
