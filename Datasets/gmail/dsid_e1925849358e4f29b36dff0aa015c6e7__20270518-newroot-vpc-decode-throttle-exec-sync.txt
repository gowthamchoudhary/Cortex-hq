Quick triage notes (initial):

- Error pattern shows a fallback to a non-quantized kernel when a specific attention size is hit (approx seq_len 1024). That fallback path is triggering an unexpected decode error on ~6% of requests.
- Disk IO for KV cache warms spikes at the same time window; we see serialization stalls when multiple requests try to materialize KV shards.

Immediate mitigation options I've validated locally:
- Reduce default batch size from 16 -> 8 for the affected route (low risk, reduces throughput but stabilizes latency).
- Disable KV prefetch on the node group experiencing stalls (medium risk but should eliminate the serialization window).
- Roll back to model variant v1.3.4 (known-good kernel mapping) — highest confidence but requires config flip and brief warm-up.

I've attached a short triage notes doc with snippets. Will keep digging on root cause; asking Michael/Aditya to weigh in on kernel patch feasibility.
