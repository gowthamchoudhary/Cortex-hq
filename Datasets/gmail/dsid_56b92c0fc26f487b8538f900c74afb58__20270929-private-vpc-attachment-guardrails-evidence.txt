> Demarc: Control plane ... management CIDR with TCP/HTTPS only; dataplane ... tenant overlay IPs egressing to Helix egress via NAT64/IPv4 NAT.

We should be explicit about port expectations for the control plane: 443 + 5222 (if we run push-notify for ephemeral agent connections) — if Helix blocks 5222 we need a fallback. Also add that control-plane probes must allow our KMS and S3 endpoints for encrypted artifact fetch.

> MTU: We recommend 1500 for the initial attachment.

Agree. Add a short diagnostic step to run path MTU discovery from Helix to an inference node during the maintenance window and attach the output to the change ticket.

> Redundancy: Recommend BFD with 50ms fast timers...

Note: many colo fabrics rate-limit BFD; include a low-volume keepalive fallback (3s TCP probe) in case BFD is filtered.

Proposed canary (minimal):
1) Create a single tenant slice with test model (cpu/1, gpu=0) and route a fraction (5%) of inference traffic via Helix attachment.
2) Monitor latency P50/P95 and error-rate for 1 hour; if no regressions, expand to 20% for 3 hours.
3) Full cutover with incremental scaling and a post-cutover traffic sweep.

I'll add two brief validation commands to the runbook (traceroute+tcpdump snippet and an application-level completeness check). Once Tom confirms the MTU/BFD plan we'll finalize.
