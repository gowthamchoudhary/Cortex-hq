Quick update from infra side (initial triage):
- Pulled recent perf traces from the affected clusters and attached a CSV (perf-report-2026-03-29.csv).
- Observed a matching bump in KV cache miss rate for v2.3.0-quant across the customers who adopted the profile; this correlates with increased seq rebuilds and token decode latency on GPU kernels.
- Memory footprint is ~8-12% lower for the quantized variant, but the runtime is doing more frequent KV repopulation which increases tail latency.
- Error spike looks related to OOM throttles on some smaller instances where the runtime attempted aggressive prefetching under the new kernel path.

Immediate mitigations I recommend:
1) Switch NovaGrad back to v2.2.7-nq (non-quant) via routing policy — this is a config flip (low risk).
2) In parallel, apply a conservative quant profile patch that reduces prefetch and disables speculative KV repop (diff-quant-profile.patch). Test on a canary pool with identical workload.
3) Short-term: increase small instance memory reservation or move customers with tight memory to larger instance shapes to avoid OOM.

I can flip routing now if we have customer sign-off. I’ve attached the CSV and the patch. More detailed trace fragments are in the Grafana link.
