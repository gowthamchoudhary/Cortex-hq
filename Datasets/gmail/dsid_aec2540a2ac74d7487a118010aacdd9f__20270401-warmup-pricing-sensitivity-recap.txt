Key assumptions and calculations (conservative → optimistic):
- Baseline monthly tokens (Sara’s numbers): ~93M tokens/month.
- Base list price we’ll use for modeling (example host model): $14.00 per 1M tokens.

Caching/hitrate impact:
- No cache (0% hit): cost = 93 * $14 = $1,302 → effective $/1M = $14.00
- Conservative cache (25% hit): effective tokens charged = 93M * (1 - 0.25) = 69.75M → cost = 69.75 * $14 = $976.50 → effective $/1M = $976.50 / 69.75 ≈ $14.00 still on per-1M billed tokens but effective cost per original 1M user tokens becomes $976.50/93 ≈ $10.50 per 1M observed tokens. Note: this is the unit customers care about (what they *effectively* pay per 1M of their generated tokens).
- Optimistic cache (40% hit): effective tokens billed = 55.8M → cost = 55.8 * $14 = $781.20 → effective $/1M observed tokens ≈ $781.20/93 ≈ $8.40 per 1M observed tokens.

Clarifying note on definitions (we should call these out explicitly in the one-pager):
- "Billed tokens" = tokens sent to the model runtime after cache hits (what Redwood bills against).
- "Observed tokens" = the raw tokens generated by user prompts (what the customer measures internally).
- Effective $/1M observed tokens = total monthly bill / (observed_tokens/1M). This is the number most procurement folks understand.
