Elena / Team — attaching the compact packet per Jonas' plan. Key highlights below (we've kept answers concise for the RFP team):

1) SAST / Secure SDLC
- Tooling: We run a SAST pipeline (Snyk + internal static analyzer) integrated into PR gates and CI.
- Coverage: 90% of repo footprint scanned (all public services + customer-facing SDKs).
- Cadence: Pull-request scanning (real-time), weekly scheduled scans for main branches, nightly dependency scanning for new transitive vulnerabilities.
- Evidence: build artifacts and scan reports are included (redwood_sast_snapshot_20261031.json) in the full packet.

2) DAST / Runtime Testing
- Approach: Automated DAST (ZAP-based + custom runtime hooks) against staging environments with authenticated test accounts; complemented by smoke checks in canary environments post-deploy.
- Frequency: Monthly DAST runs for high-traffic endpoints; ad-hoc runs prior to major releases.
- Mitigation: Dynamic findings triaged into tickets with SLA targets by severity.

3) Penetration Testing (executive summary)
- Vendor: SecureProbe Ltd.
- Most recent test: Oct 12–15, 2026 (external black-box + authenticated web app).
- Findings: 3 low, 2 medium. No critical findings. All medium/low findings have either been mitigated or have mitigation plans with timelines. See pen-test-summary-2026-10.pdf (attached) for details.

4) SBOM and third-party provenance
- Format & generation: We produce CycloneDX 1.4 SBOMs at build time and at release time for runtime images. The included CSV is an export subset (redwood_sbom_20261031.csv) showing package, version, license, and checksum.
- Scope: SBOM covers application code, runtime dependencies, and base image layers used in hosted and dedicated offerings. Private/deployed-on-prem SBOM exports can be scoped to customer artifacts on request.

5) Patch SLAs and triage
- SLA table (patch-sla-table.csv attached):
  - Critical: 48 hours (hotfix or documented mitigation + emergency patch)
  - High: 7 calendar days (priority patch and scheduled maintenance window)
  - Medium: 30 calendar days (planned release)
  - Low: next quarterly release or tracked backlog
- Exceptions: documented through our Risk Acceptance Board; exceptions include compensating controls and monitored compensations.
