Sizing assumptions (derived from your distribution):
- Baseline throughput target: 1,200 rps steady state -> ~6 GPU T4-equivalent nodes with continuous batching (batch windows tuned to 40–80ms to control tail latency).
- Burst sizing: to cover 5.5k spikes with 99th <= 400ms, we estimate needing a burst headroom of ~18 GPU-equivalent units if using int8; using fp16 variant increases GPU need by ~40%.
- KV cache hit-rate: with a warm cache for the top 10% of prompts we expect a 22–30% reduction in token compute which reduces steady GPU counts.

SLO mapping and enforcement:
- Canary: 100 concurrent requests canonical test harness -> measure 95/99/99.9 pctiles for 30 minutes. If 99th exceeds 220ms -> block GA and trigger config change (larger batch window or model variant).
- Fallback policy: sustained (>3m) queue depth increase triggers routing to the fp16-faster-variant until autoscale completes or a manual rollback.

Operational runbook highlights:
- Incident detection: heatmap anomaly (5%+ deviation from baseline 30-min median) triggers automated alert to PagerDuty team Atlas-Infra-PD.
