Marissa / team — draft content below. I focused on clear, SIG-friendly language and mapped artifacts we can realistically provide. Please edit for tone.

--- Draft for SIG reply (short bullets per mode) ---
Hosted (Redwood API - multi-tenant hosted):
- Data plane: Customer requests enter via TLS to Redwood-managed API endpoints in our hosted regions. Request metadata and transient tokenized payloads are processed in Redwood runtime; we do not persist customer PII unless explicitly opted in for extended logging.
- Controls/evidence: SOC 2 Type II report (hosted controls), network flow diagrams for hosted regions, runbook for incident response, sample telemetry scrubbed of customer data.
- Guarantees: Standard hosted SLA; data residency by region (customer selects region at provisioning), logical separation via tenant IDs. No dedicated GPUs are provisioned per customer in this mode.

Dedicated (reserved capacity - Redwood-managed HW reserved for customer):
- Data plane: Customer traffic is routed to a pool of GPUs reserved for the customer (logical isolation). Route ingress is still via Redwood-managed endpoints unless Private VPC Peering is enabled.
- Controls/evidence: Dedicated capacity architecture diagram, proof of isolation (resource allocation logs), capacity SLA and audit logs for tenancy, SOC 2 sections relevant to capacity management.
- Guarantees: Stronger throughput/latency SLOs and audited isolation at the resource and tenancy layer. Data at rest encryption with customer KMS integration available.

Private (VPC / on-prem - customer-controlled):
- Data plane: Control plane connectivity differs by option: (a) VPC: customer configures VPC peering or PrivateLink so inference requests remain on customer networking and only a minimal control plane handshake crosses Redwood-managed control endpoints; (b) On-prem: full offline or air-gapped deployment, no Redwood-managed data plane.
- Controls/evidence: Deployment checklist (VPC peer + route table screenshots), KMS integration screenshots, SOC 2 addendum template for private deployments, audit trail showing control-plane access logs.
- Guarantees: Customer owns network boundary and data residency; Redwood provides the package and automation, but the customer retains network controls and can enforce their own isolation policies.

Hosted:

- Overview: Reserved compute pools managed by Redwood but logically allocated to a single customer. Ingress is normally via Redwood-managed endpoints; optional PrivateLink/VPC peering reduces exposure to public networks.

Private (VPC / on-prem):
- Overview: Customer-controlled network and/or on-prem deployment. For VPC deployments we provide automation and a minimal control-plane endpoint; the customer manages network routes and can restrict control-plane access. On-prem installations can be air-gapped with no Redwood-managed data plane.
- Key evidence: redwood-vpc-setup-checklist.docx; kms-integration-sample.png; sig-evidence-index.xlsx
