Thanks for the quick escalation. Summary of technical triage so far:
- The v4.2 quantB profile reduces model size but triggers mixed-precision kernels for certain attention shapes common to Halo's long prompts. On our test rigs we see the int8 path hit a codegen guard that forces a slower float fallback for sequences > 1024 tokens. That fallback path induces additional memory allocations and increases latency.
- The memory pressure then causes occasional request retries on a minority of hosts; the retry behavior surfaces as increased 5xxs and lowers throughput under sustained load.

Immediate mitigations:
A) Roll back HaloAnalytics traffic slice from v4.2 to v4.1-quantA (safe, tested). Estimated time: 20 minutes to complete for the current fleet slice. Expected result: p95 back to baseline and 5xxs drop.
B) If rollback is not acceptable, we can deploy a temporary config that forces the int8 kernels for the affected shapes (requires a quick kernel pin and a short restart window). Risk: small accuracy deviation in a narrow prompt profile.

Recommended action: Rollback + postmortem. I'll schedule a quick ops window now.
