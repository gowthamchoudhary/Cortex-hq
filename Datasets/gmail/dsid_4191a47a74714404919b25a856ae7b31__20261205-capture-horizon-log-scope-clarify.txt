Sara —

Appreciate the spreadsheet, that’s helpful. Quick summary first, then details below.

TL;DR (summary)
- Default capture windows at Redwood (hosted API): raw request payloads (prompts + system messages + request metadata) are retained for 30 days by default.
- Model-generated outputs (the responses we return) are retained for 60 days by default.
- Derived artifacts: embeddings and reranker vectors are retained for 90 days by default unless you turn off derivation storage for the project.
- Ephemeral items (KV cache for streaming / in-flight prefixes): kept up to 12 hours and then dropped.
- Aggregate telemetry (usage/latency metrics): retained for up to 365 days for dashboarding/SLAs.

Options and notes
- Residency: hosted customers in our US region have defaults above. For EU or APAC you can pick regional residency (data stays in-region) at sign-up or via an enterprise contract.
- Immediate purge: self-service purge is available for Dedicated/Private customers (via console or key rotation for Private). Hosted customers can request an immediate purge via a support ticket; we require the ticket + account ID and DPA reference.
- Pseudonymization and access: within Redwood we separate access to raw artifacts from telemetry; only our security/infra team can access raw payloads and we log access.

Below are a few clarifications tied to items in your spreadsheet (referencing tab names):
- Tab "Prompts vs Outputs": the classification is the same across APIs — prompts are part of the raw request object. Outputs are a generated artifact stored separately and subject to the 60-day window.
- Tab "Embeddings": embeddings produced via the embeddings endpoint are considered derived artifacts and follow the 90-day default. If you never call the store API or configure "no_store" at the project level, embeddings aren't persisted.
- Tab "Streaming / KV cache": the runtime keeps a short-lived prefix/KV cache to serve subsequent tokens quickly — this is intentionally short (12 hours) and not included in backups.

Sara —

Following up with the finalized answers and next steps. Thanks for the patience while we verified internal purge and residency flows.

Final confirmation (hosted API, US region unless otherwise requested):
- Raw request payloads (prompts, system messages, request headers) — retained 30 days by default; accessible to infra/security with logged access.
- Model outputs (responses, completions) — retained 60 days by default.
- Derived artifacts (embeddings, reranker vectors) — retained 90 days by default; you can disable derivation storage at the project level.
- Ephemeral runtime state (KV cache/streaming prefixes) — kept for up to 12 hours; not backed up.
- Aggregate telemetry (latency, token counts) — stored up to 365 days; this data is sampled/aggregated and does not contain full payloads.

How to request changes or an immediate purge
- Hosted customers: open a support ticket (link below) with: account ID, project ID, time range for purge, and DPA reference. Our security team will validate and perform the purge; expected SLA for hosted purge is 5 business days after validation.
- Dedicated: admins can run project-level purge from the console and configure auto-expiry windows per project.
- Private (on-prem/VPC): you control retention via your deployment config and KMS key rotation; we provide runbooks.
