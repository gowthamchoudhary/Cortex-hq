Summary below and quick answers to your bullets.

Quick answers:
- Event types: Our tenant audit stream includes authentication events (auth.login, auth.fail, token.rotate), API lifecycle events (api.request_start/end with request_id and duration), model lifecycle (model.deploy/rollback), admin actions (config/change_role), and billing events. We include server-side metadata and request-level metadata where available (request_id, client_ip, user_agent, tenant_id).
- Export contents: Exports (S3 presigned bundles and bulk API) include full event records (JSON) subject to configured redaction rules. We do not include full customer-generated PII within request bodies unless the tenant chooses to opt-in — by default request bodies are truncated and replaced with a hashed placeholder where applicable.
- SIEM integration: We support HTTPS webhook forwarding (near-real-time) for customers that want streaming into their SIEM. We do not ship native syslog out-of-the-box; customers can use the webhook endpoint or pull exported bundles to an intermediary that converts to syslog. For Dedicated customers we offer partner connectors to push to syslog endpoints.
- Customer access & on-demand extracts: Customers can request on-demand exports via the Console > Data > Audit Exports (generates a presigned S3 GET valid for 24 hours) or via the Bulk Export API (token-scoped, rate-limited). We also provide read-only tenant audit views in the Console (time-windowed).
- Redaction controls: Default hosted behavior: mask sensitive fields, remove full request bodies, and hash IPs to /24. Dedicated and Private customers can request custom redaction profiles (field-level allowlists/denylists) at onboarding.

Operational playbook (high level):
1) Customer requests evidence -> open support ticket with request parameters (date range, event types, desired export format).
2) Engineering prepares export -> run bulk export job (background) -> place gzipped JSON bundle into customer-specific S3 bucket (internal) -> generate presigned GET and attach to support ticket.
3) Delivery options: presigned GET (24h), bulk API delivery (direct), webhook forwarding (real-time).
4) Verification: include log count summary and hash manifest in support ticket for integrity verification.
5) Long-term archiving: for retention beyond 90 days, we provide an archiving export (bulk) on contract; otherwise hosted retention purges at 90 days.

Notes / limitations:
- Syslog export not natively supported for hosted tenants today.
- Response bodies are treated as potentially sensitive; we will not export them verbatim unless tenant approves.
- For SOC/SIG evidence we can supply a manifest and excerpts (redacted) if full raw event export is restricted.
