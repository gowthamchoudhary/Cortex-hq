Hi — thanks for the clear list. Looping in Marissa (observability product) and Karthik (on-prem ingestion) to give the detailed options. Quick summary up-front so you have a single recommendation for procurement:

1) Preferred (push with customer-managed forwarder): Run a lightweight forwarder inside your VPC (customer-managed EC2/container) that pulls from Redwood's private forwarder endpoint over mTLS. Forwarder writes to your SIEM (syslog/TCP) or S3; minimal inbound rules because it's an outbound TLS connection.

2) Alternate (brokered pull via S3/Firehose): Redwood writes JSON batches to a customer-owned S3 bucket (via a short-lived role we assume). You configure an event/Firehose to feed SIEM. This requires a tightly scoped IAM role and explicit bucket policies.

3) Fallback (agentless scrape): If neither is possible, we can deliver periodic encrypted archive drops via an enterprise SFTP gateway. Higher latency and operational overhead, but procurement-friendly for locked-down environments.

Thanks Jonas — details below and attaching a mapping template (siem_mapping_template.yaml) and the tracehook snippet (tracehook-snippet.txt).

Port/IP/CIDR guidance (preferred push model):
- Outbound TLS (443) from customer forwarder to our private forwarder endpoint: fw-us-1.private.redwood.ai (IPs: 52.14.78.0/24)
- Mutual TLS: client cert required (we provision short-lived certs via our control plane).
- If you use syslog/TCP in the customer subnet, allow inbound from the forwarder host (recommended to keep forwarder inside the subnet where SIEM ingest runs).

Schemas / payloads:
- Audit logs: newline-delimited JSON, fields: timestamp, request_id, actor_id, action, resource, outcome, request_payload_hash. No request/response bodies are included unless explicitly requested and agreed in scope (PII mitigation).
- Metrics: Prometheus-style aggregates + periodic JSON summaries for per-route token usage. TTL on metrics in the export: 30 days (you can request longer retention via contract).
- Traces: OTLP over gRPC/HTTP. We provide a small hook that redacts full prompt text by default and instead emits a prompt_hash + metadata. Tracehook-snippet shows header injection and sampling controls.

Operational notes:
- Rotation: certs rotate every 24h by default; we support a longer rotation window if your PKI requires it.
- Replay: forwarder supports idempotent chunked retries; we attach a sequence token to each batch.
- Backfill: for compliance audits we can generate archived batches for a defined retention period (adds cost).
