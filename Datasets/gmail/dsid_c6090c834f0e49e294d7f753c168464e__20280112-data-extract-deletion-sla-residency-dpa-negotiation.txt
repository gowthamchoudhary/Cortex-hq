Hi Lara — thanks for the clear list. Quick responses below, and I attached a redline (Aurum-Redwood-DPA-redline-v2.docx) that shows our proposed edits.

1) Deletion SLA: We can confirm a 30-day certified deletion for production data. For backups and immutable snapshots we propose a 45-day certified erasure window (we call this out in the redline). In practice: regular delete within 30 days, any backup snapshot purge certified within 45 days.

2) Embeddings & derived artifacts: By default, embeddings are treated as Customer Data for the purpose of deletion obligations. Operationally, embeddings in cache are ephemeral: we retain KV caches for 24–72 hours for performance, and embedding indices stored for retrieval are included in the deletion schedule. We added explicit language that Redwood will provide a deletion certificate for embeddings upon request.

3) Residency: We can commit to EU-only processing and EU-hosted backups for data labeled as "Aurum EU-Personally Identifiable Data". We also added an exception procedure for emergency cross-border routing (e.g., disaster recovery), which requires prior written escalation approval from Aurum procurement + a documented mitigation plan.

Ava / Priyom — a few quick technical points to support the consumer-facing language:

- Embeddings: our storage has two classes — short-lived KV cache (TTL 24–72h) and persistent index (used for semantic search). I've pulled verifier metrics: persistent index is stored in an encrypted S3 bucket per-region; we can implement a region scoping flag per-customer to ensure EU-only buckets. Deletion flow for index requires a background job plus reindexing, which is the reason for the 45-day snapshot window.

- Backups: snapshots are incremental. We can flag Aurum’s snapshots for accelerated retention removal (sink/expedited delete) for an additional one-time ops pass — this is an ops cost we should be transparent about if procurement pushes for shorter than 45 days.

- Certification: we have a standard erasure attestation template but can add fields for embedding indexes and backup manifests. Priyom, can legal ops sign off on the attestation wording?
