Marissa / Jordan —

I did a focused pass on networking patterns. A couple of technical asks to add to the review doc: 

1) Network policy model: are you relying on cloud-provider SGs/NACLs only, or also CNI/networkpolicy for pod-level controls? For private deployments we prefer defense-in-depth: provider-level ACLs for coarse boundaries + CNI-enforced networkpolicy for east-west.

2) Route table ownership: as Marissa noted, pick a single module owner (core-vpc) and expose a managed list to consumers. Avoid cross-module state references unless using remote state references with strict read-only roles.

3) Peering and CIDR collisions: include an automated check in CI that validates proposed customer CIDRs against a maintained verboten list and produces a clear error (non-zero exit) if overlap is detected.

4) BFD/MTU considerations for SR-IOV/on-prem links — doc the fallback MTU & test plan in Ansible (change MTU, verify KV-cache stability).

I'll add short terraform snippets for remote-state read-only role and an example terratest case to the review doc.
