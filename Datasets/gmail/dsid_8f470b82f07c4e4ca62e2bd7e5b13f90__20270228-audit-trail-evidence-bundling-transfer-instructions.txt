Thanks — below is a proposed export plan (operational details). I am attaching a small schema CSV (export_schema.csv) and a sample manifest (sample_manifest.txt).

Exported log types (full):
- admin_activity (create_user, update_role, remove_role, login_as, console_login_failed)
- api_keys (create, rotate, revoke, assign)
- policy_changes (rbac_policy_update, quota_change, retention_change)
- data_exports (export_initiated, export_completed, export_failed, export_destination)
- sys_events (service_restarts, deploys, infra_changes tied to control plane ops)

Per-record fields (we include these columns in each row):
- timestamp (ISO8601 UTC)
- request_id (uuid)
- actor_id (internal id)
- actor_email
- actor_role
- action_type
- resource_type
- resource_id
- resource_path
- change_summary (text diff for config changes where applicable)
- client_ip
- user_agent
- outcome (success/failure)
- payload_sha256 (for exported payloads)

Retention/backfill notes:
- Primary audit store retains 18 months of raw events internally; we can backfill older data from cold-store snapshots up to 36 months with a 48–72 hour turnaround (cost + ops approval).
- Events older than 18 months may require snapshot reconstruction; we'll flag any partiality in the manifest.

Packaging/delivery options (choose one or more):
1) Full snapshot: Parquet partitioned by month + top-level manifest (JSON lines) + SHA256 checksums. Bundle as .tar.gz, PGP sign. Delivery via S3 presigned PUT (objects encrypted with AES256 and KMS).
2) Incremental feed: daily deltas delivered to a dedicated S3 prefix; we can also push to an S3-compatible endpoint or Splunk HEC.
3) Live stream: Firehose -> S3 (if you want near-real-time ingest). Not necessary for historical SOC2 but available for continuous monitoring.

Security controls on export:
- Objects encrypted at rest with KMS CMKs; we can use customer-provided KMS key for delivery if requested.
- ACLs limited to a short-lived export role; CB must approve IAM role for the transfer.
- Audit of the export operation itself is recorded in the manifest and in a separate 'export_audit' collection.

Checksums & chain-of-custody:
- Each bundle contains SHA256 checksums for each object and a signed manifest (PGP or KMS-signed).
- We can also provide a signed attestation PDF from the ops lead confirming the export window and object list.

Operational timeline (we can meet EOD 2/28 if we start today):
- 2/25: scoping + approval for KMS/transfer method (today)
- 2/26: run initial extraction, validate schema, produce sample bundle for reviewer
- 2/27: finalize and encrypt full bundles, run checksum, upload to agreed location
