Emily / team — following up with the technical clarifications and a draft SSQ response attached (ssq-response-draft.docx). Key points below; the doc includes a one-page access matrix and a short subprocessor list.

CDN / Edge persistence:
- CDN (CloudFront) access logs: metadata only (request path, status, edge location, headers subset) retained for 7 days by default. No raw request bodies are stored by the CDN.
- Edge compute (our edge workers) may temporarily buffer request bodies for processing (<5 sec) but do not persist them to durable storage. Any tokenization output (non-PII token references) is routed into central KV caches.

Tokenization & placement:
- Tokenization happens in the regional gateway instance closest to the customer’s region (edge pre-processing). For Medica Health tenants in the US region, tokenization is performed in the us-east region before streaming to central inference clusters. This ensures PII is replaced with ephemeral tokens prior to longer-term processing.

Subprocessors (edge routing & caching):
- CDN provider: Amazon CloudFront (logging metadata only)
- Edge compute: FastEdge Inc. (ephemeral execution, no persistent storage)
- Metrics/analytics: StatsStream (aggregated telemetry only; no PII)
- Central logging: Redwood central logging (PII redaction applied at ingest)

Access matrix summary (see attached):
- Platform Ops: can view anonymized telemetry and aggregated metrics; no raw PII.
- Site Reliability / On-call: can access transient logs for debugging; raw PII views are gated and require approved incident case + audit log entry.
- Support: can view customer identifiers (token references) but not unmasked PII.

Retention:
- CDN metadata: 7 days
- Edge ephemeral buffers: <5 seconds (no durable storage)
- Central KV cache (non-PII tokens): 30 days by default, configurable per-customer
- Audit logs (access events): 365 days
