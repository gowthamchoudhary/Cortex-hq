Alex — good questions. Quick technical answers + an attached minimal tool-definition snippet in the Drive link below. High level: yes to deterministic fallback and redaction. Details: 

SDK/auth
- Server-only SDK: the SDK includes a pre-send hook where you can implement PAN redaction/tokenization. We recommend doing deterministic hashing (HMAC with an internal salt) prior to sending anything to Redwood so full PANs never leave your environment.
- Token exchange: VectorPay's token service (OIDC client credentials) will exchange for a short-lived Redwood session token via our /v1/auth/exchange endpoint. We'll provide code samples for Node and Go.

Routing & Dedicated pool
- Policy-based routing: requests tagged 'settlement' or with high-risk indicators go to Dedicated (us-west). Default route uses hosted standard model. We surface per-route SLOs in the Console so you can set up alerts.

Function/tool calling pattern (concrete)
- Tool definitions (example):
  * external_risk_api: sync HTTP POST -> returns structured JSON {score, explanation, evidences[]}. Timeout 150ms, circuit-breaker trips after 3 errors in 10s.
  * local_reranker: runs a micro model on the same node to normalize outputs and add a deterministic 'uncertain' flag when inputs are incomplete.
- Execution semantics: run both tools in parallel; accept the first fully-formed response that meets a confidence threshold (>=0.75). If none meet the threshold within 200ms, return local_reranker's deterministic fallback with 'uncertain': true and include a call-to-action to queue for async enrichment.
- Error handling:
  1) transient external_risk_api error -> retry once with jitter (50ms) while local_reranker proceeds; if retry fails, circuit-breaker opens and we mark subsequent requests for 30s to use local_reranker only.
  2) persistent degradation -> route to a lower-cost, higher-latency model (fallback route) and create an Ops alert.

Embeddings & rerank
- For real-time decisions we do not recommend calling the heavy embedding service inline. Use a cached nearest-neighbor index on a dedicated node for fast similarity. We'll provide a suggested embedding TTL and reindex cadence.
