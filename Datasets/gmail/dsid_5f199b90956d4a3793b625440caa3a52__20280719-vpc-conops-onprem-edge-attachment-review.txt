Quick technical notes after skimming ACME's ConOps and our annotated diagram:

- Control plane: must be treated as "outbound-only" from the customer's VPC. We will use mTLS over port 443 to our control endpoints. No inbound management ports should be required on customer NAT. If ACME requires private peering for control-plane API, we can map a dedicated control VIF but that increases operational surface.

- Data plane (inference workers): live in customer subnets behind a NAT gateway or equivalent. We recommend a dedicated subnet per environment (canary/staging/prod) to enable traffic shaping and quota enforcement on our side.

- Routing: prefer BGP over IPsec for dynamic failover if you have a Direct Connect / ExpressRoute equivalent. For simpler setups, static routes over IPsec are fine but include keepalive and route health checks.

- Firewall / ports (minimum):
  * Outbound 443 TCP to control.redwood.ai (mTLS)
  * Outbound 5222 TCP for health-check pubsub (if you opt in)
  * Outbound 80/443 to S3/OSS for model artifact pulls (or use VPC endpoints)
  * If you use model-serving esystems with vector indexes, allow outbound 9200/9300 to our managed index endpoints (TLS only).

- KMS integration: if ACME uses a customer KMS/HSM for key unwrap, we need the KMS endpoints reachable from worker subnets. Consider a dedicated KMS subnet with strict egress.

I'll prepare a short appendix with port/route examples and a suggested NAT/egress policy.

Ops checklist / canary suggestion below — adding details so ACME can validate against procurement timeline:

Canary plan (recommended):
- Step 0: Pre-checks: validate IP ranges, ACLs, and identify a /26 dedicated subnet for canary workers.
- Step 1: Deploy 2 worker instances in canary subnet, use NAT egress to control.redwood.ai; ensure mTLS handshake completes.
- Step 2: Gradually shift 5–10% of traffic via route injection (BGP community or traffic steering at load balancer).
- Step 3: Monitor latency, error-rate, and token cost; rollback via BGP withdraw / route priority change.

Firewall template (columns in attached spreadsheet): source, destination, protocol, port, justification, monitoring. We should lock down SSH and other admin ports; any admin debugging should be run from a bastion with time-limited access and recorded sessions.

Operational notes:
- Logging: we require flow logs (S3 or Log Analytics), and API request logs forwarded to our Ops SaaS for SLA correlation.
- Alerting: set an early-warning on 5xx spikes and elevated tail latency (>95th percentile threshold).
