Quick triage summary (first 10min):
- Observed: short bursts of high tail latency originating from a single dedicated GPU pool region (us-west-2). p99 jump aligns with a burst in concurrent arrivals starting 08:53 PDT.
- Root cause hypothesis: request queueing + concurrency cap enforcement -> backlog accumulation -> long head-of-queue waits. Also seeing KV-cache thrash for personalized prompts (cache miss rate up ~18%).
- Evidence: metrics attached (snippet) and sample logs (tail_spike_logs_0729.zip). No model rollout occurred at that time.

Immediate recommended mitigations (fast, reversible):
1) Temporarily raise per-instance concurrency cap for FastCommerce's pool from 8 -> 16 for the next 60 minutes (rollback planned at T+90m).
2) Enable aggressive prefix caching for checkout flow (reduces recompute for repeated prompts).
3) Apply a short-lived routing rule to send 10% of traffic to a smaller, warmed model variant to shed load.

I can implement 1 & 3 within ~8–12 minutes if we get authorization; 2 requires a small config change and a cache warm-up window (~20min).
