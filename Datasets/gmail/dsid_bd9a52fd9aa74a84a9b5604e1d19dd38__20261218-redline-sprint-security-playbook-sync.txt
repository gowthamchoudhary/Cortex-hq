Quick answers up front:
- We offer a bounded inspection path (staged access + evidence handoff) rather than broad, unfettered production inspection. We typically provide a combination of:
  * SOC 2 report (most recent) and SOC 2 bridge letters when available;
  * A remote evidence collection lane (scoped, sampled artifacts delivered via secure drive); and
  * Time-boxed staging access for high-risk tests under an approved plan + NDA.
- Pen test: we are open to customer-provided testers where they meet our vendor security and contractual requirements; typical notice is 30–60 days and we require pre-approved scope.
- For cadence: default is quarterly evidence windows for customers with ongoing inspection needs; one-off customers get a single evidence delivery unless agreed otherwise.

Thanks — a couple of practical clarifications from Security so Brightway has operational expectations and to help Procurement finalize requirements:

- Staging environment: we can provide an isolated staging stack that mirrors production but excludes ePHI/PHI. Customers must use the staging instance for active pen-tests; production tests are explicitly disallowed except under a rare, mutually agreed addendum with a forensic plan and narrower scope.
- Notice & blackout windows: standard is 30–60 days notice plus a 48‑hour blackout window before/after major infra deploys. We will provide a calendar of available staging windows once contracted.
- Evidence samples: typical deliverables include architecture diagrams, change logs, SOC 2 control identifiers & mapping, and redacted logs where relevant. We do not provide raw production logs or backups.

Suggested small edit to Laura's pen-test language to add an approval gating item: "...and prior to any test, Redwood's security team will confirm the tester acceptance criteria (insurance, references, and technical capability) and an agreed runbook for escalation and post-test remediation."
