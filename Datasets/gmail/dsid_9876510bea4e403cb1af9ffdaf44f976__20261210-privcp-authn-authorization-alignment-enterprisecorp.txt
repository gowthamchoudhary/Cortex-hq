Thanks for sending these over and for the context. Looping in Priyom (identity integration lead) and Ben (solutions lead) so we can get the technical mapping nailed before the Friday session. Initial notes: 

- SAML attributes: Redwood Private Control Plane prefers a namespaced claim named "redwood:roles" for explicit role assertions, but we also accept standard RFC groups for group->role mapping. If your IdP is sending groups only, we can map group names to roles via SCIM group membership.
- SCIM scoping: scoped groups (project-1234-operators) are supported. We recommend a group naming convention: <org>-<project>-<role> to minimize ambiguity. Priyom will include the exact regex and an export-friendly CSV.
- Service accounts: we treat service accounts as users with a machine tag; provisioning should come through SCIM with an attribute `x-redwood-type: machine`. Avoid assigning global-admin to service accounts.

Attached is a quick CSV with our suggested mapping examples (redwood-privcp-role-proposal.csv).

Hi Samir —

Quick technical notes ahead of the call. Apologies for the terse message; I'll expand if you want a written runbook after the call.

1) Attribute mapping we recommend:
   - SAML attribute: `redwood:roles` (multi-valued). Values map 1:1 to Control Plane roles: `redwood:admin`, `redwood:operator`, `redwood:auditor`.
   - Fallback: Use `groups` with the mapping table: `enterprise-global-admins` -> `redwood:admin`, `proj-<id>-ops` -> `redwood:operator`.

2) SCIM behavior and scoping:
   - We support SCIM 2.0 group resources. For scoping, include a custom `meta.scope` attribute in the group resource (string: `org`, `project`, `env`).
   - When SCIM provisioning creates a user, include `urn:ietf:params:scim:schemas:extension:redwood:2.0:user` with `type` = `machine|human` and `assignments` = array of role strings.

3) Service accounts and long-lived credentials:
   - Recommended: mark as `machine` and require a human owner attribute. We rotate machine API keys automatically but require a separate approval workflow for global-admin keys.

4) Audit and least privilege enforcement:
   - We log every SCIM patch and SAML assertion; for Private CP we can stream audit events to your SIEM via syslog/HTTPS. We will provide a sample mapping for your SOC team.

Please see annotated examples in the call. If you want the JSON schema for the recommended SCIM extension before the meeting, I can paste it.
