Hi Maya — thanks for the clear questions. Short answers up front, and I9ve attached a worksheet with the three recommended combos and pro-forma pricing.

1) Fallback behavior:
- We offer automatic routing fallbacks by policy. If Dedicated capacity is exhausted we can:
  a) Route to a pinned hosted variant with throttled concurrency (recommended for non-latency-critical batch ops), or
  b) Queue requests up to an SLO window you define (useful for predictable short bursts), or
  c) Return a 429 when you prefer hard limits.
- For MetroHealth I9d suggest policy (a) with a floor SLA: route to hosted model replica in the same region with a max concurrency cap so your user experience degrades gracefully.

2) Feature bundling:
- Observability add-ons (audit logs, retention) are provided as account-level features and can be applied to Dedicated or Hosted independently. You can absolutely have Dedicated compute with Hosted observability.
- Some features (HSM-backed key management, private VPC peering) require Private deployment and are not available on the standard hosted slab.

3) Short-term step-up discount:
- We can do a 10% one-month step-up discount if you commit to a 6-month pilot and a minimum reserved throughput. I put a model in the attached worksheet showing effects on unit cost if you step up for a single month versus sustained commit.
