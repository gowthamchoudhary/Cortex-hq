Emma — thanks for the great questions. Short answers first, then a worked example and the concession we typically offer for pilots.

Short answers:
- Metering unit: Redwood charges per-token (input + output) with a configurable context-window aggregation that can group requests from the same session if the requests share a common session_id and occur within a rolling window (default 60s).
- Minimums/quantum: We do not round up to a fixed token quantum (e.g., 128 tokens) across the entire invoice, but we do apply a per-request minimum when requests are sent as independent, non-aggregated calls. The per-request minimum is configurable at the account level; default is 1 token (so effectively no hidden quantum).
- Aggregation behavior: If your widget attaches a persistent session_id and the calls happen within your configured aggregation window, we aggregate and bill the combined token count (no extra min per sub-call). If calls are independent (no session_id) they are billed individually.

Worked example (attached spreadsheet: metering_examples.xlsx):
- Scenario A: three independent calls, each 300 tokens -> billed tokens = 3 * 300 = 900 tokens.
- Scenario B: three calls tied to session_id X within 30s, aggregation window = 60s -> billed tokens = 900 tokens (same total) but aggregated for KV-cache reuse and may reduce compute latency; no per-call minima applied.
- Scenario C: streaming call that sends a 50-token prompt and receives 50-token response across a long-lived stream -> billed = 100 tokens.

Important caveats:
- Conversation history: if you include a long context (e.g., 4k) and then make short turns, the billed tokens include the context you supply with each request unless you enable prefix/KV caching; caching reduces repeated context billing when requests are aggregated.
- Minimums: for customers on committed Dedicated plans we can set a per-session minimum or negotiate blended per-call rates (useful for high-volume microcalls). For Hosted pilots we typically leave default minima to avoid billing surprises.

Pilot concession we recommend:
- For the initial 3-month pilot we can apply a microcall smoothing credit equal to 30% of billable tokens for any invoice line where average call size < 600 tokens and session aggregation is enabled.
- We'll also share an example invoice and a tokenization breakdown so procurement/legal can validate.
