Diego / Kim —

Operationally we have two safe options that avoid touching the normal purge path:

1) Isolated snapshot + immutable object store:
  - Create an isolated snapshot of the S3-style objects that match the ACME event filters (we can use their spreadsheet to build the filter).
  - Copy to our immutable bucket (WORM) in the US region and apply a tag 'acme_temp_hold_2026-01'.
  - Keep retention metadata off the main index so normal TTL workers ignore it.
  - Pros: simplest verification path for later deletion; minimal impact to normal KV log indexes.
  - Estimated incremental storage cost: $1,200 per 30 days for the requested scope.

2) Prefix-level delay + purge exemption flag:
  - Exempt specific prefixes from the purge worker for up to 60 days by setting an exemption flag in service registry.
  - Requires a short change in our purge scheduler and extra monitoring.
  - Pros: faster restore for engineering-led forensics. Cons: slightly higher risk if exemption flag isn't removed on time.

I recommend option (1) for auditability. If legal wants faster retrieval, we can do (1) + a short-term prefix exemption for same day restores.

- Formal attestation/email from DPO (Lisa) confirming scope.
