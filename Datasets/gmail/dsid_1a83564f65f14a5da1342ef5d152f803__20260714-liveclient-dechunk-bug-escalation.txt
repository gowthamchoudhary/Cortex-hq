All — final engineering summary and mitigation plan after code dive:

Root cause: a bug in sdk-js dechunker v2.3.1 where header reassembly logic fails when certain chunk boundaries split multi-line headers; the dechunker returns "hdr_reasm_failed" and the SDK retries the request, which, under load, triggers head-of-line retries and amplifies upstream p99 and error rates. This manifests as intermittent 400/502 on ingress.

Immediate actions taken:
- Deployed server-side tolerant parser on Checkoutly's route at 12:05 PDT (accepts split header reassembly for 72 hours).
- Deployed a temporary traffic routing policy to increase per-request timeout and reduce client-side retry aggression.
- Built and validated an SDK patch (v2.3.2) that corrects header reassembly; can cut a release and post to NPM after a short test.

Validation plan:
1) Patch rollout to 5% of Checkoutly traffic tonight (smoke tests),
2) If green, ramp to 100% over 2–3 hours,
3) Keep tolerant parser enabled for 72 hours then remove after monitoring window.
