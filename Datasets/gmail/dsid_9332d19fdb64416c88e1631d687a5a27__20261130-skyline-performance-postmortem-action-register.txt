Quick investigation summary (preliminary):
- Findings: sudden growth in KV cache size for Skyline's primary model shard led to frequent GC stalls and degraded GPU throughput; combined with a misconfigured autoscaler policy (scale-down threshold too aggressive) we observed transient under-provisioning. A small percentage of requests hit a fallback path that returned 5xx when the worker pool was saturated.
- Evidence: traces attached to SUP-4567 show a cluster of 500s aligning with heap/kv memory pressure; docker host metrics show CPU pinned and NVidia GPU utilization dropping with queue backlog. Support logs attached.

Immediate mitigations implemented (15:50 PST):
1) Temporarily increased reserved capacity for Skyline Dedicated pool (+25% capacity) — reduced tail latency.
2) Disabled aggressive cache eviction rule that triggered full cache rebuilds.
3) Rate-limited non-critical background batch jobs for Skyline to reduce jitter.

Proposed action items (owners & ETA):
- A1: Adjust autoscaler thresholds + add cooldowns (owner: vivek_kulkarni, ETA: 2026-11-30 18:00 PST)
- A2: Introduce KV cache size guardrails + circuit-breaker (owner: marcus_lin, ETA: 2026-12-07)
- A3: Add per-customer backpressure at the ingress (owner: laura_bennett, ETA: 2026-12-02)
- A4: Post-incident rewrite of spooler to avoid full-cache rebuilds (owner: infra-team, ETA: 2027-01-15)
