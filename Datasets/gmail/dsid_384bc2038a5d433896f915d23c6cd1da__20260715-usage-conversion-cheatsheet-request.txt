Hi Emma —

Great questions, summarizing quickly and attaching a tiny conversion cheat-sheet + a few example prompts you can drop into your logs. TL;DR answers below, full details in attached PDF.

1) chars -> tokens: rough rule-of-thumb is ~4 chars per token for English prose (so 1,000 chars ≈ 250 tokens). That varies by language and prompt structure (lots of punctuation or code -> different ratio). Use the attached CSV to map actual samples from your logs.

2) caching: Redwood caches model prefixes/KV where applicable. Cached prefix tokens are not re-generated by the model, but billed tokens are measured on the served tokens. In practice: if a prefix is 100 tokens and served from cache such that the model doesn’t re-evaluate them, you will not pay generation tokens for repeated identical prefixes. However, initial prompt tokens and any dynamic user tokens are billed. Important caveat: some integrations (browser-side dedup, request-level cache) can avoid request overhead but billing is tied to the model-run. We can share a short design doc if your infra team needs specifics.

3) budget mapping: using $/1M tokens metric — if we assume $30 per 1M tokens at the hosted tier (example), $10k/month => ~333M tokens/month and $20k/month => ~666M tokens/month. If you plan to use heavy caching and have ~50% repeated prefixes, observed billed tokens could be commensurately lower.
