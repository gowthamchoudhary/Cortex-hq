1) Shortlist (recommended trio) — rationale (cost / latency / quality tradeoffs)
- Redwood-Edge-4B-INT4 (low-cost, high throughput): best fit for high-volume routings (summary/embedding pre-filter). Bench (512-token typical request): p50 latency ~85 ms per token, estimated unit cost ~$0.0006/token. Quality: baseline F1 0.78 on your prompt set (acceptable for short generative answers).
- OpenCore-7B-INT4 (balanced): primary candidate for day-to-day chat. Bench (512 tokens): p50 latency ~120 ms/token, unit cost ~$0.0011/token. Quality: F1 ~0.86 on Novus evals, notably better on follow-up coherence.
- Atlas-70B-fp16 (high-quality fallback): for answers requiring high factuality or longer-form reasoning (reports, legal excerpts). Bench (512 tokens): p50 ~310 ms/token, unit cost ~$0.0045/token. Quality: F1 ~0.92, best on multi-turn reasoning.

Recommendation: default route ~70% traffic to OpenCore-7B-INT4, 25% to Redwood-Edge-4B for cheap/short paths, and reserve Atlas-70B for low-confidence fallback or targeted features. This balances cost while keeping a path to high-quality outputs when needed.

Alex — great questions, answered inline below. Keeping the runbook pragmatic so your on-call/ops folks can own steps without heavyweight process overhead.

1) Regression monitoring and triage (who/what)
- What we ship: continuous eval harness that runs the canonical prompt-set (attached) on every model version and daily production sampling.
- Alerting thresholds: automated alert if end-to-end answer similarity drops >5% vs baseline or if the rate of high-entropy/unknown responses increases >8% over a 24-hour window.
- Triage ownership: initial alert routes to Novus on-call + Redwood SRE (we'll add both paged contacts). Redwood can auto-roll back to the previously pinned model variant if a critical threshold is hit and the incident is acknowledged within the canary window.

2) Fallback UX and latency impact
- Graceful fallback strategy: we recommend a policy-first approach — only invoke Atlas-70B when the primary model signals low confidence (token-level entropy + heuristics) or a verified content failure is detected. That keeps the majority of requests on the primary path.
- Latency mitigation: when fallback is required, use speculative execution (start Atlas in parallel for the top-n requests) or partial-response streaming (send best-effort primary output while Atlas completes). Both approaches add overhead but reduce perceived latency; we can implement speculative starts for high-value flows.

3) Pricing / committed tiers
- Ben is cc’d and has prepared an initial tier sheet. Rough thresholds that get you to ~30–40% off: 3–6 month commit at 1.5–2.0M tokens/day effective usage or an annualized equivalent. We’ll send a tailored quote once you confirm expected steady-state daily tokens.

4) FedRAMP / compliance
- Caveat: FedRAMP requires an isolated control plane and more stringent evidence than standard SOC2. We can support the artifacts and provide an on-prem / private deployment option; timeline will be longer (we can scope in the alignment call).
