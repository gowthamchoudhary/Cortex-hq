Kevin / Naomi —

Wed 5/20 14:00 PST is confirmed on my calendar. Quick technical clarifications to make the call productive:

- Auth: For the canonical reference design we'd like to validate OAuth2 client credentials + short-lived tokens (our runtime supports automatic token refresh and a token-rotation hook). mTLS is fine if Lighthouse requires it for egress restrictions — call that out and we'll enable on our side.
- API paths: We expect a POST /v1/infer and a streaming SSE /v1/stream endpoint; please confirm those paths in the sandbox. If Lighthouse exposes a different path we can map via a route shim.
- KV cache behavior: please confirm whether your connector will preserve client-provided conversation IDs and whether prefix caching is available on your side (we may rely on prefix caching to keep tail latency within SLA).
- Rate limits: what's your per-minute client quota for sandbox keys? We need to tune batching windows.

I've started a short tech note in the shared doc for the call: https://docs.google.com/document/d/1a2b3cLighthouse-Integration-Plan (see section 'token mapping' and 'canary criteria'). I'll bring sample cURL + small python snippet to demo the token-exchange flow.
