Hi Laura — thanks for the clear list. Short answers first, then a one-page summary below. Attaching a compact retention matrix (retention_matrix_v2.pdf).

Short answers (hosted API default):
- Prompts / requests (user inputs): retained for 30 days by default for operational debugging and abuse analysis.
- Model outputs (final generated completions): retained for 90 days by default (helps with quality monitoring and regression detection).
- Streamed fragments: transient; we keep short-lived buffers for up to 7 days for debugging partial-stream issues, but these are not used for long-term analytics.
- File uploads / attachments referenced in requests: metadata (filename, mime type) is captured; file content should be stored in customer-managed storage or passed to Redwood via signed URLs — Redwood does not persist uploaded binary content by default.

What customers can change:
- Opt-out: customers can request no retention on inputs and outputs (zero retention) via an account setting or API flag; for hosted customers this is subject to technical verification and billing implications.
- Region/residency: hosted customers can choose a region; retention still follows the same time windows unless an enterprise contract specifies otherwise.
- Dedicated/Private: for Dedicated and Private deployments, retention defaults can be set by the customer and enforced by config (often zero or short TTLs).

See the attached matrix for a compact view and a couple of example timeline scenarios.

Hi Laura — adding more detail from Security/Product. Short answers to your follow-ups: 

1) Residency (EU customers):
- Hosted customers may select an EU region at account creation. For accounts pinned to an EU region, persisted logs (requests/outputs) are stored in that region.
- For customers requiring strong residency guarantees we recommend Dedicated or Private deployments where the entire stack (control plane + data plane) is under the customers region/VPC.

2) Proof of deletion: 
- We can provide deletion evidence for hosted accounts: timestamped purge logs and S3 object lifecycle events (or equivalent) showing the purge operation. For enterprise contracts, we can add a contractual deletion attestation clause and provide periodic reports.

3) What counts as outputs: 
- Final completions means the canonical final text returned to the API caller.
- Token traces and extensive debug traces are considered debug artifacts and are not part of the standard 90-day retention unless a customer enables enhanced logging for debugging; enhanced logging is off by default.

Operational notes:
- Encryption: all persisted logs are encrypted at rest with customer keys available for Dedicated/Private or Redwood-managed KMS for hosted.
- Access controls: log access is limited to an internal, audited service role and sent to customer SSO ACLs for enterprise.
