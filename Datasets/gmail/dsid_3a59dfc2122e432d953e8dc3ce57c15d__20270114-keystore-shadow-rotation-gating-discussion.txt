Ravi —

Thanks for the diagram and clear asks. We've taken a first pass and sketched a gating matrix (attached). Quick summary of our position:

- Shadowing model: we recommend an "audit-only" shadow copy for awareness, not live fallback. Live failover increases blast radius unless strict split custody is enforced.
- BYOK operator model: two paths: 1) Attested HSM: customer holds root keys and we store wrapped subkeys; minimal operator privileges; 2) Cloud KMS: wrapped key material under customer's KMS with our service account as allowed unwrap principal.
- Rotation gating: automated rotations OK if telemetry shows successful wrapping/unwrapping in staging and no errors for N consecutive rotations (we propose N=3) + attestation proof for HSM path. Manual approval required for any topology change (e.g., switching from audit-shadow to primary).
- Egress controls: shadow copies must be stored within customer VPC and encrypted with a different KEK; cross-region replication needs explicit customer approval.

I'll triage this with Marissa and Kim — they'd like to define the exact telemetry signals. Can you confirm the target staging window (dates) and whether Acme needs additional evidence for SOC2?

I've filled out the gating matrix with concrete telemetry signals and pass/fail thresholds. Highlights:

Marissa / Neha / Ravi —

Confirmed: the on-prem agent supports a local enforcement policy that can set KMS key usage to "unwrap-only" for the Redwood service account. For attested HSMs we rely on the HSM's access control + our operator model (we never request unwrapped root keys). Implementation notes:

- The agent will record a signed audit entry for every wrap/unwrap operation and stream hashes of those entries (not the keys) to the customer's audit sink.
- We can optionally require an HSM-signed nonce before a rotation completes (this is the attestation hook Marissa mentioned).
- For shadow storage we can offer two modes: "hashed-pointer" (min metadata, lower egress) or "full-metadata" (for customers that need richer debugging traces).

I'll add a small FAQ to the design doc describing tradeoffs; prefer hashed-pointer by default to minimize surface area.
