I pulled the traces (attached) and started a session with the inference runtime logs. Early findings:
- catalog-v2.14 introduced a new model alias mapping that prefers a 13B fp16 variant on certain request shapes. For short-context inputs that previously hit a small-optimised quantized variant, routing is now going to a slower fp16 kernel due to a mismatched sequence-length heuristic.
- KV cache hit rates look normal; the issue seems to be kernel selection for ~32-token requests — we see a 2.5–5x step increase in token step time on affected host shards.
- No OOMs or queue saturation in the cluster at time of spikes.

Immediate mitigation options:
1) Hotfix catalog to map short-context shapes back to the quantized variant (fast fallback).
2) Apply a runtime heuristic tweak to force the small-seq path for <64 tokens for the next 30m.

I recommend #1 for fastest customer relief while we validate #2 for a rolling runtime update. I'll prepare a catalog patch and a short validation run in staging.
