Hi Samir —

Appreciate the clear questions. Short answers up front, then a brief operational note:

1) Territory attestation: Redwood will not perform permanent writes outside of the pinned region (US-East) for data marked under the pin. We do allow temporary, time-bounded transient processing in nearby regions only for a narrow set of operational events (scale-up cache rehydration, urgent node failover). Maximum controlled window is typically 30 minutes for rehydration and up to 4 hours in extreme failover cases; we can agree to a contract bound (e.g., 4 hours) in the DPA addendum.

2) Transient-sync behavior: Ephemeral KV-syncs may touch our cloud provider's adjacent-region networks (e.g., us-east-2) or a vendor-managed caching layer in the same cloud region family. All ephemeral copies are flagged as transient and are not persisted to long-term storage. We capture operational telemetry (start/stop timestamps, host IP range, trigger reason) which we can surface as auditable logs for up to 90 days under a paid evidence package.

Operational note: There are two paths customers typically choose — strict pinning with agreed failover windows (preferred for regulated workloads) or affinity-with-failover which allows faster recovery with transient hops. If you want, Karthik can give a short ops breakdown of triggers and logging, and Kimberly can list what we'd include in a DPA addendum (contract language and evidence scope).

Hey Samir —

Following Priya's overview, a few operational specifics so your infra team can evaluate risk:

- Triggers:
  * Autoscale cold-starts for model shards (typical)
  * Rolling kernel/OS patch on pinned-hosts requiring live cache pull
  * Emergency failover (rare; when >1 host in pinned AZ becomes unusable)

- Typical duration: 10–30 minutes for cache population; we observe median 12 minutes in normal conditions. We surface the full duration per event in logs.

- Where ephemeral copies may appear:
  * Within same cloud provider family: US-East (primary) -> US-East-2 as transient hop only
  * Vendor-managed caching nodes hosted under contract (we can share subprocessor names in the DPA schedule)

- Auditing:
  * Events include trigger reason, source shard id, involved host IP ranges, and start/stop timestamps.
  * We can provide CSV extracts for a 90-day window on request; longer retention is available as a billed add-on.

- Encryption: All in-flight and at-rest crypto keys remain customer-controlled for Dedicated/Private customers; for hosted we use envelope encryption with KMS and can provide key access logs on request for attestation purposes.
