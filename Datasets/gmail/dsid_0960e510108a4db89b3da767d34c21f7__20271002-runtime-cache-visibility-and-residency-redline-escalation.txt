> Hi Olga / Patricia / Priya,
>
> Technical summary from runtime/product perspective:
>
> - Current behavior (hosted API): KV cache (per-model key-value cache used for attention/context pre-warm) is normally kept in-process memory. For operational reasons (cold-start reduction and instance warmup), we have an optional persistent snapshot feature that writes encrypted snapshots to object storage (S3-equivalent) in the deployment's region. This feature is off by default for new customers but was enabled for a subset of pilots to reduce token latency on short-lived instances.
>
> - Access model: snapshots are encrypted at rest using our platform encryption keys. Access is limited to the service account that performs deployments; Redwood engineers do not routinely read snapshot contents. However, support may request temporary access under an approvals flow (audit logged). Subprocessors that run our object store (cloud provider) may have host-level access but not decryption keys.
>
> - Residency: for Dedicated and Private deployments we can guarantee region. For hosted customers we currently pin snapshots to the region backing their tenancy; Helix (if hosted) would by default be in us-west-2 for their account unless they request otherwise.
>
> Proposal to address Helix asks with minimal product change:
> 1) Make persistent KV snapshots opt-in only (default off) for hosted customers. For existing tenants with snapshots on, provide an opt-out toggle that deletes existing persisted snapshots.
> 2) When snapshots are persisted, require explicit configuration: region selection AND optional customer-managed KMS (CMK) support so plaintext is not accessible to Redwood.
> 3) Add a short-term telemetry mitigation: strip any raw prompt text from snapshot payloads and only store hashed keys/prefixes for matching; retain full KV in-memory only.
>
> Tradeoffs / timeline:
> - Opt-in toggle + delete path: ~2 weeks (low risk).
> - CMK integration + region enforcement (hosted): ~6 weeks engineering + security review.
> - Hashing/strip-payload work: ~3 weeks to implement safely and validate regression tests.
>
> Performance impact: if Helix elects to keep snapshots off, they should expect more cold-start token latency (est. +40% median for short-lived endpoints). If they enable snapshots with CMK in-region, performance is similar to today.
>
> I can draft exact contract language that maps to these commitments. Priya — please weigh in on whether Legal/Security can accept a timeboxed remediation (8 weeks for CMK + validations) in the DPA redline.
>
