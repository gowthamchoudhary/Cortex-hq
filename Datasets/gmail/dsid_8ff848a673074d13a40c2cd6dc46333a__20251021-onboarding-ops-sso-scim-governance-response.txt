Alex — thanks for the clear list. Summarizing Redwood's position and attaching a starter mapping. High-level answers below; I included where we typically ask customers to confirm tenant-specific choices.

1) SSO (SAML & OIDC)
- Protocols: We support SAML 2.0 (SP & IdP-initiated) and OIDC (authorization code + PKCE) for modern apps.
- Multiple IdPs: Customer tenants can configure up to 3 active IdPs; each IdP has its own certificate and config.
- Cert rotation: We support automated and manual X.509 cert rollover for SAML (overlap window configurable). We provide a webhook that notifies on approaching expiry and a test endpoint for validation.
- Attributes: Attribute mapping is configurable; default mapping includes: email (primary), given_name, family_name, groups. Custom attributes supported via attribute mapping UI and SCIM sync.

2) SCIM provisioning
- Implementation: SCIM v2 (RFC7644) with full and incremental (delta) sync.
- Service account & tokens: SCIM uses a scoped bearer token per tenant. Tokens can be rotated and we support short-lived tokens via an integration with your key manager if required.
- Rate limits: Default is 100 requests/min per tenant; can be increased for Dedicated customers. Bulk update guidance: batch up to 100 users per request is supported; for very large directories we recommend initial bulk CSV import + SCIM incremental for daily changes.
- Filtering & rules: Support for group filters to limit provisioning scope (e.g., only specific OU or groups).

3) RBAC & delegated administration
- Role model: Redwood has a first-class RBAC model: Organization Owner, Admin, Ops, Viewer, and custom roles. Roles map to capabilities (read, write, manage-models, manage-instances, billing-view).
- Group -> role mapping: SCIM groups can be mapped to Redwood roles during onboarding; the mapping is editable in the Console and via the SCIM schema.
- Delegation: You can create tenant-scoped delegated admins with scoped permissions (for example: on-call operator that can restart model instances but cannot change billing).

4) Audit, logs & evidence
- Audit events: user-auth, sso-login, scim-provision, role-change, api-key-create, token-rotate, admin-action.
- Retention: Standard retention is 90 days in the Console; longer retention (12/24/36 months) is available as an add-on with secure archival.
- Export & access: Audit exports available via CSV and streaming webhooks to your SIEM. We provide signed evidence packages for audits (SOC 2 artifacts) on request.

Procurement Team — short answers below; happy to include in a DR/contract appendix if needed.

1) SLA & audit archive access: Audit export availability is covered under our enterprise SLA for Dedicated and Private customers. For Hosted customers we guarantee access to 90-day live exports; archival retrieval (12+ months) is available as a billable add-on with a 5-business-day retrieval SLA. 2) Scoped IP allowlist for SCIM: Yes — we support tenant-level IP allowlisting for SCIM endpoints. Options: a) single static IP (for appliances), b) CIDR ranges, or c) mutual TLS for extra assurance. We recommend IP allowlisting + token rotation for the strongest posture.

Operational notes: for initial bulk imports we can temporarily increase SCIM rate limits to 500 req/min for a 72-hour window; this is a service operation we schedule with your SRE.
