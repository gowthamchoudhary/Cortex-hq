Hi Mark — following Aisha’s note with some technical clarifications that often come up during questionnaires. I’ve called out defaults and what’s configurable.

- Log types / retention:
  - Request / trace logs (request metadata, path, latency): default 90 days on Hosted. Can extend to 365 days for Dedicated with additional storage charge.
  - Audit logs (admin actions, config changes): stored separately; default retention is 90 days on Hosted, configurable to 365+ for Dedicated/Private. We can export audit logs into your SIEM (S3-compatible export) on a scheduled cadence.
- Backups / snapshots:
  - Nightly point-in-time backups: Hosted default retention 30 days. Backups are encrypted at rest with customer-tenant keys managed by Redwood.
  - Dedicated: customers can select 90/180/365 day backup retention; we can also set up cross-region replication for resiliency (adds cost).
  - Deletion semantics: backups are rotated; when a deletion request is processed, we mark live data for immediate removal; backups are removed according to retention policy (max 90 days baseline to final deletion), with cryptographic erasure options available for Dedicated/Private deployments where required by contract.
- Deletion SLA (suggested contract language):
  - "Active customer data will be removed from primary storage within 30 calendar days of contract termination or upon validated deletion request. Secondary copies and backups will be purged within 90 calendar days, unless otherwise specified in the SOW."
- Encryption / key management:
  - Data encrypted at rest and in transit. For Dedicated/Private we support customer-managed keys (KMS/HSM).
