Thanks Emily — quick reply and then I’ll loop in security for a deeper dive.

High-level answers: 
1) Persistence: By default our hosted inference API does not persist user payloads beyond the request lifecycle for customers on standard settings. However, customers can enable request/response logging for debugging and quality monitoring; when enabled those logs are stored in encrypted object storage for a configurable retention window. We can also support a proxy-only mode where payloads are streamed through the runtime and not written to long-term storage — this is commonly used in PHI workflows.

2) BAA: Redwood will sign a BAA for customers with PHI. For hosted customers, BAA execution is possible but we require a combination of settings:
- disable long-term request logging (or limit retention to 30 days and restrict access),
- enable encryption-at-rest with either Redwood-managed keys or customer-provided keys (KMS/HSM), and
- restrict webhook callbacks to VPC peering or static IP allowlists for the customer.

3) Logging separation: We support logical tenant separation for telemetry, and for Dedicated/Private customers we can provide stronger physical separation (isolated logging buckets and dedicated SIEM ingestion). For hosted customers we offer per-tenant indexing and RBAC controls; if Oakridge needs proof of physical separation you should consider Dedicated or Private.

> 1) Persistence: ... proxy-only mode?

Proxy-only mode: yes. Our runtime supports passthrough mode for streaming payloads (including binary attachments). In passthrough mode we avoid storing request or response bodies in object storage; ephemeral buffers exist only in memory and local NVMe caches until the request completes and are zeroed. This mode is recommended for webhooks carrying PDF lab reports or DICOM extracts.

> 2) BAA: hosted BAA requirements and KMS options

KMS & keys: hosted customers can choose Redwood-managed KMS (default) or bring-your-own-key via AWS KMS/CloudHSM or customer HSM. If you bring your own key we can configure envelope encryption so that persistent logs and any cached KV entries are encrypted under your key.

Retention: default request log retention is 90 days for standard customers. For BAA-covered workflows we require reducing that to <=30 days or enabling pii-scrubbing/pseudonymization prior to persistence. We can redact PHI programmatically (we have an ML-backed PII scrubber) before logs are persisted, or you can opt-out of persistence entirely.

Logging separation: for hosted we provide per-tenant encryption keys and isolated index namespaces; however the underlying logging cluster is shared. For true physical separation we recommend Dedicated or Private where we provision separate storage buckets and SIEM connectors under contract.

Evidence & questionnaires: SOC 2 Type II report (current) is available at: https://redwood.app/soc2-report/2027. We can provide a current pen-test summary on an NDA or limited-distribution basis; the SIG extract we provided is a subset of CAIQ responses (attached). If Oakridge needs a full SIG or CAIQ matrix we typically export the extract and then mark sections that require customer-side controls.

Suggested minimal controls for Procurement to accept hosted+BAA: 
- disable long-term request logging (or set 30d retention),
- enforce customer-managed keys or approved KMS rotations,
- enable proxy-only mode for attachments,
- limit webhook endpoints to VPC or allowlist IPs,
- add contractual SLA for incident notification and support level
