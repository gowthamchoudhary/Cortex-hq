Sam — great to hear, thanks for the thoughtful list. Answers inline below and next steps at the end.

- Prefix/KV caching: Hosted sandbox endpoints do support prefix caching and KV reuse for the common case (we expose the same caching behavior you’d see in production hosted endpoints). For highly-custom cache policies we recommend Dedicated but you’ll get realistic caching behavior during the trial.

- Rate windows for sandbox: default trial sandbox is configured at 10 requests/sec steady-state with a short burst allowance up to 25 rps for microbursts (30s window). We expose per-route token and rps metrics in Console; you’ll see 1m and 5m aggregates plus per-request latency breakdowns. If you need a higher steady-state for the trial we can provision a larger slice.

- Migration Hosted -> Dedicated: migration is designed to be low-friction — we preserve the same API surface and endpoint naming when you pin model versions. Work typically required: update traffic routing/credentials, and a brief cutover window to switch to your Dedicated pool. There’s some operational coordination (capacity reservation + contract), but no rework of prompts or SDK changes. We’ll share a short checklist.

- SSO/Okta: Okta SSO for the Console and API key management is available for Dedicated and Private by default. For Hosted trials we offer SSO on request for enterprise accounts; for initial sandbox access we provide scoped API keys. If Okta SSO is a blocker for procurement, we can arrange a temporary SSO binding for the trial with a short onboarding step.
