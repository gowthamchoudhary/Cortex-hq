  - 34.198.128.0/24
  - 52.23.64.0/24
  - 3.231.12.0/24
  - 13.54.101.0/24

- DNS: recommend allowing TCP/UDP 53 to your resolver; alternating approach below avoids needing UDP 53.
- Notes: these IPs are for control plane, runtime telemetry and license validation. We will provide a signed IP-list CSV (attached) and maintain a one-week rotation notice for changes.

Option B — Egress via customer-managed HTTPS proxy (recommended for environments that disallow any external NAT):
- Allow outbound to your internal proxy host(s) only (proxy does the TLS termination to Redwood).
- Required: proxy must preserve SNI and forward the upstream Host header. Support for CONNECT tunneling is required.
- Ports: 443 (TCP) to the proxy; proxy needs to support CONNECT for arbitrary hostnames.
- Advantage: no direct public IP allowlisting on your internal firewall; you can apply deep inspection & logging at the proxy.

Other requirements & clarifications:
- Certificate validation: Redwood requires standard TLS 1.2+ with full chain verification; no client cert required by default. We validate SNI on the control plane; if you terminate TLS at the proxy you must forward SNI.
- Keepalives/Idle timeouts: allow 15+ minute TCP keepalives for long‑running streams (chat/streaming RPCs).
- DNS: If you cannot allow UDP 53 outbound, configure split-horizon to resolve our internal runtime hostnames to private addresses or use the proxy pattern.
- Passive telemetry: we send aggregated usage/health pings; telemetry endpoints are within the IP ranges above. No payload contains customer prompts or PII by default — metadata only.

Michael —

Short answers to your asks and an audit checklist excerpt below. We'll turn this into a one-page artifact for your compliance team and sign-off.

1) CONNECT support: Yes — Redwood supports upstream HTTPS CONNECT tunnels. Requirements: the proxy must not perform TLS re-termination for the end-to-end channel (i.e., support true TCP CONNECT). SNI must be preserved by the proxy.

2) Telemetry & retention (summary):
- What we collect: service health metrics (CPU/memory usage), request metadata (timestamp, model id, token counts), and anonymized performance telemetry. We do NOT collect customer prompt text, audio, or model outputs by default.
- Purpose: platform health, capacity planning, regression detection.
- Retention: raw metrics retained for 90 days; aggregated summaries retained for 24 months.
- Access: telemetry access limited to Redwood SRE + Product; export requires managerial approval and is logged.

Audit checklist excerpt (for sign-off):
- Egress pattern: Option B confirmed (HTTPS CONNECT via customer proxy).
- Proxy requirements: supports CONNECT, preserves SNI, forwards Host header, provides request-level logging with timestamps and upstream IP.
- Firewall rules: allow outbound TCP/443 from proxy to Redwood control hostnames/IPs.
- TLS: TLS 1.2+ with chain verification; no client cert required unless requested in writing.
- Logging: proxy logs retained for 90 days; security export via S3/GDrive requires approval.
- Change control: Redwood will provide >= 7 days notice for planned outbound IP changes.
