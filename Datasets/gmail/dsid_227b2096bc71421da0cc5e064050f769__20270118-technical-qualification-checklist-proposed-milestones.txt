Anna — quick follow from our side with concrete bench params and an initial model shortlist so you can see tradeoffs. High-level notes first: if you run in Redwood-hosted shared cluster we can hit p95 350ms for 256-token outputs on an A100-equivalent with continuous batching; on-prem will likely add 50–150ms depending on GPU model and network egress.

Benchmark runner params (what we will measure)
- Input distribution: 100 prompts, 256-token max response, real sample sizes with average input length ~420 tokens.
- Throughput modes: single-request (latency SLO) and sustained (100 rps) with batching profiles 1/2/4/8.
- Metrics captured: p50/p95/p99 latency, tokens/sec, GPU utilization, memory foot-print, 95th percentile KV-cache miss rate, and cost-per-1k-output-tokens (model + infra).

Initial model shortlist (recommend we test these in order)
- open-llm/xl-7B-quant4 (fast, lower cost; quality baseline)
- open-llm/xl-13B-8bit (midpoint, better quality at modest cost)
- redwood/opt-30B-quant4 (higher quality; plan for higher infra cost)
- vendor-sku/gptx-accelerated (if MediServe allows vendor model access; Jason can run throughput-specific tests)

Proposed acceptance thresholds (draft)
- Latency: p95 <= 350ms Redwood-hosted; p95 <= 550ms on-prem (GPU dependent).
- Cost: <= $0.20 per 1k output tokens for shortlisted mid-tier models; allow up to $0.45 for top-tier model if quality delta > 8% (semantic eval).
- Quality: semantic similarity >= 0.78 and annotated acceptability >= 85% (human review on 30 samples).
