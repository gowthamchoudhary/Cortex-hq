Thanks for the clear asks. Quick technical answers and what I’m attaching: data-field-mapping.xlsx (workbook tabbed by surface), and a short note here to summarize.

1) SOC 2: Redwood is currently SOC 2 Type II certified; the full report can be shared under NDA. Redacted summary attached (redwood-soc2-summary.pdf).

2) Telemetry & product analytics (summary):
- Console (developer UI): we collect anonymized usage metrics by default (page, feature flags, API route usage). By default we do NOT send email addresses or customer UIDs in analytics. We surface customer GUIDs in traces only when explicitly enabled by the customer for debugging (opt-in).
- Docs site: we use a privacy-configured analytics provider; default cookie set is anonymous (session + performance). Customers can opt-in to deeper tracking for product analytics via an account-level flag.
- Server-side traces & logs: request metadata (request id, model id, latency, error codes). Payload content (prompt/text) is not retained by default in production for hosted customers. For Dedicated/Private deployments customers can choose retention policies.

3) Retention windows: default aggregated telemetry 30 days; debug logs 90 days; configurable for Dedicated/Private customers. We can support custom retention via contract (DPA addendum).

4) Identifiers: by default no PII or email addresses are included in telemetry. If a customer needs to include a user identifier for debugging, that is an opt-in and controlled via an account setting; we log the agreed identifier and retention per contract.

5) HIPAA: we have a HIPAA-readiness checklist. Redwood offers Private deployments and contract language to support HIPAA (including BAAs) for customers that require it — we’ll surface the legal template separately.
