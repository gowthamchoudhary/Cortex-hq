Subject: KV cache residency + safeguards notes (for Acme)

Team — attaching the diagram and a short ops note. Summary below for the DTIA: 

- KV cache residency: default behavior pins KV cache in-region (same cloud region as request) for latency reasons. We have an explicit cross-region fallback only when regional capacity is temporarily exhausted; that fallback path is logged and we can provide exportable audit trails.
- Persistence: caches are memory-backed and evicted according to LRU within seconds to minutes; no long-term token persistence is performed. Persistent storage only exists for model binaries and control-plane metadata (encrypted at rest).
- Encryption: all data in transit is TLS1.3; at-rest encryption uses customer-managed KMS for Private deployments and Redwood-managed KMS for hosted. We can provide key scoping notes for UK/EEA customers who require customer-managed keys.
- Subprocessor access: subprocessors with potential plaintext access limited to: redwood-serving (inference runtime), metrics-processor (aggregated telemetry, pseudonymized), and a limited logging transformation service (only in emergency modes; access is audited). See subprocessor table draft in Drive.
