Chris — thanks, this is exactly the right time to align. High-level answers up front, and I'm attaching a concise handoff pack. See the diagram and checklist attached.

Quick summary (TL;DR):
- Export model: sidecar push to customer-local collector (recommended) or push to a dedicated Redwood forwarder inside their VPC. Pull (polling) is supported only for metrics if you run a Prometheus scrape target in the VPC.
- Protocols: OTLP/gRPC for traces/metrics (preferred for reliability), HEC over TLS for Splunk events, and optional syslog/tcp-tls for legacy SIEM pipelines. All endpoints support mTLS.
- Tracing: sidecar-based automatic instrumentation (Envoy + OTEL sidecar) for inference service traffic; we also support an in-process OTEL SDK where customers prefer fewer containers. Sidecar approach isolates instrumentation and simplifies cert mgmt.
- Egress: we assume no public egress. Sidecar talks to a private collector endpoint (customer-provided) over internal VPC routes or via a peered Redwood forwarder in the same VPC.

Security/operational notes:
- mTLS for all telemetry -> automatic cert rotation via ACME-like controller or KMS-signed short-lived certs.
- Batch windows: sidecar batches small traces immediately, aggregates logs for up to 30s (configurable) to limit burst egress.
- Schema mapping: we can provide a sample transform that maps Redwood token-level events to Splunk's event model and includes a stable event_type and request_id for correlation.

Chris / team — adding network specifics for the two recommended patterns. I'm keeping this short; happy to expand to a one-pager with diagrams.

Pattern A — Sidecar -> customer collector (recommended):
- Flow: inference pod -> OTEL sidecar (localhost) -> TLS to 10.0.12.45:4317 (OTLP/gRPC) or 10.0.12.46:8088 (Splunk HEC).
- Firewall: allow outbound TCP to collector IPs on ports 4317 (OTLP), 8088 (HEC). No public NAT required.
- DNS: use an internal hostname with mTLS SAN matching the cert (collector.acme.internal).
- Authentication: mutual TLS enforced; clients present certs issued by customer's internal PKI or Redwood short-lived certs negotiated through a bootstrap API.
- Network policy: set egress limits on the pod to only the collector CIDRs; restrict healthcare/PII-exfil targets explicitly.

Pattern B — Redwood forwarder in customer VPC (when customers prefer not to run collectors):
- Flow: inference pod -> OTEL sidecar -> forwarder (hosted as a managed EC2/GCE/VM) -> local SIEM or routed to Redwood's private peering.
- Firewall: allow inbound from cluster subnets to forwarder instance on OTLP/HEC ports; forwarder requires additional IAM role and placement notes.

Latency/cost tradeoffs: sidecar->local collector gives best latency and avoids cross-account routing; forwarder simplifies onboarding but requires monitoring of forwarder scaling and queueing.

I also want to call out tracing hooks: set sampling at the ingress LB to ensure the root span is created with the customer's trace-id header. Sidecar should propagate B3/traceparent headers and emit request_id for downstream correlation with logs.

Happy to run a short tabletop with Acme's security team to walk the firewall rules.
