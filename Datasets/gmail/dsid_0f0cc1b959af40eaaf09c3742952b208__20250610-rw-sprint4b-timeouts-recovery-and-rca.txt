Jordan / team —

Preliminary ops triage: we’re seeing a reproducible backlog on a subset of worker pods serving rw-sprint4b when receiving requests with long prefix lengths + streaming enabled. Symptoms: KV cache contention + a kernel path regression in the quantized glue layer that causes a worker to block during KV lookups under memory pressure. That leads to request queuing and downstream timeouts (504).

Immediate corrective actions taken (already active):
- Emergency autoscale + temporary routing to v2 (Jordan did this).
- Batching cap to reduce memory contention.
- Rolling restart of the affected node group to clear stuck semaphores.

Data exposure: failed requests were only present in ephemeral worker logs and the in-memory KV cache; no persistent store was written for the failed requests. We’ve confirmed no customer payloads were saved to long-term storage.

Credit recommendation: apply a 15% usage credit for the affected 22m window to reflect degraded success rate and operational impact. I think that’s reasonable and defensible.

We’ll continue with a targeted patch to the quantized kernel path and schedule a canary rollout; ETA for code fix + canary: 48–72 hours depending on test outcomes.

Team —

Initial RCA summary (attached: rw-sprint4b-rca-summary.pdf). High-level: a recent optimizer change intended to reduce memory for quantized forward passes introduced a race in the scheduler when combined with long-context KV lookups and streaming mode. Under load this produced semaphore contention that stalled a subset of workers. Key points:

Timeline:
- 07:38 UTC: first error spike detected internally by model-health alerts.
- 07:43–08:05 UTC: customer-visible failures for Skyline Analytics (6% of requests for that period).
- 07:50 UTC: emergency scale and routing override applied.
- 08:10 UTC: rolling restart completed; error rate returned to baseline by 08:25 UTC.

Root cause: race condition in quantized kernel scheduling path when interacting with KV cache lookups for long prefix requests.

Immediate fixes implemented:
- Reverted the optimizer change in the quantized path for the affected runtime build.
- Added a batching guard for streaming routes to prevent oversized batches.
- Improved alerting to detect semaphore stalls earlier.

Preventive actions (next 30 days):
- Full regression suite covering long-context + streaming combos.
- Canary rollout of the patched quantized kernel with increased telemetry.
- Update runbook and add a quick mitigation script to switch routing to compatible variants.

I’ll publish the 48-hour initial post with more logs and timeline and a final postmortem in 5 business days.
