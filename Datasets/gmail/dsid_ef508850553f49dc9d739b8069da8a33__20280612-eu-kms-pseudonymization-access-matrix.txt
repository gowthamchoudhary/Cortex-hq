Hi Olivia — technical follow-up from the infra side (copying Kimberly + Laura). I'll keep this focused on the three items you called out.

1) KMS / key residency
- For the Private EU deployment we *integrate* with a customer CMK in their AWS account (eu-west-1). The CMK never leaves the customer's account. Redwood only holds a key reference and performs envelope encryption using the customer CMK.
- For Dedicated customers we can either use customer CMKs (recommended) or Redwood-managed CMKs provisioned in an EU-only KMS. Keys are never exported in plaintext.
- For Hosted (self-service) customers we use Redwood-managed CMKs provisioned in the EU region; these keys are audited and we rotate per policy.

2) Backups & replication
- Snapshots/backups are stored in the same region by default. Cross-region replication is disabled unless explicitly requested.
- If a customer requests cross-region replication for DR, we document the scope and require a signed change order.

3) Deletion / evidence
- Deletion API: /v1/customers/{id}/data/delete returns an event ID. Once accepted, internal deletion workflow purges active storage, triggers S3 lifecycle deletes for snapshots, and marks DB shards for shredding.
- Audit evidence: we emit an immutable log entry with event ID, actor, and timestamps. We can provide a signed audit bundle (log slice + certificate) for compliance reviews.
