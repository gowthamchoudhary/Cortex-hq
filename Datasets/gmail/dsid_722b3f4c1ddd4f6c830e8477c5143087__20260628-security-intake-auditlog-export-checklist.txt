Hi Sam — quick answers inline and a few notes on implementation options.

1) Full request/response bodies:
- Hosted offering: we do NOT retain model prompt/response bodies by default for customer privacy. We can enable capture of request/response bodies for hosted customers under a written agreement and with strict access controls, but this is atypical.
- Dedicated/Private: full payload capture is supported and commonly used for forensics; these deployments run in the customer VPC or dedicated cluster and you control retention and access policies.

2) Retention:
- Hosted default: API logs = 90 days; Admin events = 365 days.
- Dedicated/Private: configurable 30 days up to 7 years (policy + S3 lifecycle).

3) Immutability / chain-of-custody:
- Private: enable S3 Object Lock + legal hold and provide signed export manifests (SHA256 checksums, signed by Redwood KMS) to correlate export artifacts.
- Hosted: we offer signed snapshot exports (periodic) with timestamped manifests and checksums; for strict WORM requirements we recommend Dedicated/Private or an export-to-customer-s3 workflow where S3 Object Lock is applied on customer side.

4) SOC 2 / BAA:
- SOC 2 Type II: audit in progress; report expected Q3 2026 (target: Sept 2026).
