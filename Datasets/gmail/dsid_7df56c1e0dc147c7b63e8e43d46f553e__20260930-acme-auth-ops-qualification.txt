1) Rotation cadence: we recommend short-lived tokens for client-credentials with a default 1h lifetime for production tokens and refresh token flow for service-to-service. For environments with strict compliance we support 15–60 minute lifetimes and automated rotation via our KeyManager API. Rolling rotation is non-disruptive when you use the SDK’s transparent refresh — we’ll share code snippets.

2) Per-environment service accounts: yes. You can create separate service accounts per environment, each bound to a KMS key (KMS/HSM integrations supported). On Private deployments we can integrate with your HSM; on Hosted we can offer customer-managed encryption keys (CMEK) in supported cloud providers.

3) Scoped keys for embeddings: yes — we support scope-limited API keys and OAuth scopes. Example scopes: embed.write, embed.read, inference.generate. Scoped keys are enforced at the gateway layer and appear in the audit log with scope metadata.
