Hi Olivia — thanks for the clear list. Quick summary up front, then details below.

TL;DR:
- By default: transient inference artifacts (prompt text + immediate model responses) are NOT written to customer-visible long-term storage. We store minimal telemetry (request metadata and token counts) for 30 days to support routing/metrics.
- If a customer enables logging/analytics or uses features that persist (e.g., conversation history, evals, or debug logs), prompts and responses will be persisted per the chosen config and will reside in the region you select.
- Deletion: self-serve purge is available for persisted logs; for telemetry/diagnostics beyond self-serve retention windows, support can assist with account-scoped purge requests.

Details:
1) Default behavior (no logging features enabled):
   - Prompts and generated outputs are processed in-memory by the serving runtime and are not stored as persistent artifacts.
   - Short-lived operational traces (request id, model id, latency, token counts) are written to an internal telemetry store with a 30-day TTL and are stored in the region tied to your tenancy (US regions for Acme by default). These traces do not include full prompt text or full generated output.

2) When logs/analytics are enabled (explicit customer opt-in):
   - Conversation history, debug logs, and saved prompts/outputs will be written to the configured storage bucket and retained according to the configured retention policy (default 180 days unless customer changes it).
   - You can pin residency: storage buckets can be provisioned in US, EU, or APAC regions depending on your contract and Dedicated/Private deployment choices.

3) Separating prompts vs outputs:
   - We tag persisted artifacts so prompts and outputs are distinct objects. Access controls and audit logs are applied separately.

4) Deletion and purge paths:
   - Self-serve: customers can delete persisted logs via the Console (per-bucket/object delete) and set lifecycle rules for automatic deletion.
   - Support-assisted: for telemetry or for cases covered by contractual obligations, open a support ticket or use the data subject request flow; we will perform account-scoped deletions and provide confirmation.

Adding a technical note from platform/product:

- Telemetry we retain by default (30 days) is intentionally minimized to reduce risk: it includes timestamps, model/route identifiers, hashed request ids, and token counts. No plaintext prompts/outputs are kept in telemetry unless the customer has enabled debug logging.
- For Dedicated and Private customers we offer options to route telemetry and persisted logs to customer-managed storage (S3/GCS) in the desired region; we can also integrate with customer KMS for object encryption at rest.
- For PII-sensitive workloads we recommend one of three paths: (1) Private deployment with on-prem storage, (2) Dedicated tenancy with bucket residency configured to US-only and strict lifecycle rules, or (3) disable logging and use ephemeral session-only operations.
