Top-level success criteria (must all be met to pass trial):
1) Production-like throughput: 95% of requests at P95 latency <= 450ms (sample set, 512 tokens)
2) Accuracy baseline: end-to-end intent recognition F1 >= 0.88 on your labeled sample set (30k examples)
3) No data egress concerns: KV cache and telemetry settings documented and verified by security
4) Cost envelope: projected monthly token cost at scale <= $X (we estimate within spreadsheet)

Exit gates (immediate stop & review):
- Any P95 latency regression > 40% vs baseline after load test
- Data privacy discrepancy found in security review (unredacted PII leaving VPC)
- Repeatable quality drop where F1 falls >= 0.07 below baseline across two consecutive runs

- Smoke generation test (50 queries): compare latency, check no PII leakage via redaction check (Soojin owner)

I reviewed the draft MAP and added technical acceptance test details in the "Test Procedures" column (spreadsheet). A few engineering clarifications and recommended tolerances:

Technical test notes:
- Latency tests: use a synthetic mix (60% short 64-token prompts, 30% medium 256-token prompts, 10% 512-token stress queries). Report P50/P95/P99 and token-per-second while pinned to a single model revision.
- Cache validation: run warm-start vs cold-start sequences and report per-request time breakdown (KV restore vs generation).
- Safety/PII check: run a regex-based redaction validator on outputs and a small manual review (10 examples). If any unredacted PII is found, that's an immediate stop gate.
- Drift signal: add a rolling weekly concordance check; trigger deeper review if semantic-similarity to baseline < 0.85 on two consecutive runs.
