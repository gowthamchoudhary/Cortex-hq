Notes from packet-level triage (summary):

1) What I saw in the provided pcap and an additional live tcpdump on the customer-facing GRE:
- Multiple large TCP segments sent with DF=1 and sequence gaps when we see retransmits.
- A series of fragmented IP packets from Redwood host 10.240.12.18 -> customer on-prem IP (frag offsets present in pcap). Fragments are not being reassembled on the far side; one of the intermediate firewalls is dropping later fragments.

Snippet (from tcpdump -n -vv -r brightfield_truncated.pcap):
  10:21:13.453123 IP (frag 0) 10.240.12.18.52344 > 172.31.10.8.443: Flags [P.], seq 3245:8421, ack 1982, win 64240, length 5176
  10:21:13.453456 IP (frag 1856) 10.240.12.18 > 172.31.10.8: frag 1856:3711, proto TCP
  10:21:13.453789 IP (frag 3712) 10.240.12.18 > 172.31.10.8: frag 3712:5423, proto TCP
  10:21:13.756234 IP 172.31.10.8.443 > 10.240.12.18.52344: Flags [R], seq 0, ack 8421, win 0, length 0

2) On the customer NAT / edge (logs provided by Brightfield infra-ops):
- The stateful firewall is configured to drop out-of-order fragments that cannot be associated with an existing connection if the conntrack table is near capacity.
- We observed conntrack table near 95% utilization during peak; NAT ephemeral ports limited to a smaller pool due to older appliance limits.

3) Root cause hypothesis (short):
- Large model responses produce large TCP segments that get fragmented in-flight across a path with MTU mismatch. An intermediate stateful firewall or NAT device is dropping later fragments when conntrack cannot associate them, resulting in truncated connections and reset behavior. Ephemeral port exhaustion exacerbates the problem, causing abrupt RSTs.

4) Recommended immediate actions (playbook):
- Increase conntrack_max on the customer's NAT appliance and/or expand ephemeral port range temporarily.
- Apply MSS clamping on the customer's egress (or on the Redwood hybrid gateway) to avoid IP fragmentation for large TLS streams (set MSS to 1360-1400 depending on path).
- Add a temporary rule on transit firewall to allow fragmented packets or to reassemble at the firewall if supported.
- Plan a maintenance window to apply the NAT/conntrack changes and monitor for 2 business hours.

5) Mitigation steps Redwood can do without customer maintenance window:
- Route affected customers to an alternate region that avoids the constrained NAT path (we can do per-account routing for Brightfield test subset).
- Implement server-side chunking so no single TLS record exceeds safe MTU thresholds (short-term patch).
