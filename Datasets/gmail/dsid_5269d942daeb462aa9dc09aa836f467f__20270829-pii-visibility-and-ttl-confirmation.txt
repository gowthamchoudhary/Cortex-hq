Hi Anika — thanks for the questions. Below are concrete answers you can drop into your SOC2 evidence pack. Quoting your points inline.

On Sun, Aug 29, 2027 at 09:45 AM Anika Rao <anika@medlogic.com> wrote:
> 1) SOC2 team specifically wants: a) exact retention windows for any persisted prompt/output artifacts, b) whether full prompt payloads (including PHI/PII) could ever appear in logs or backups.

Answer:
- Retention windows (default/demo values):
  • Session debug logs (ephemeral, accessible through the Console): 7 days. Can be reduced to 0 days (disable) in enterprise config.
  • Persisted outputs (only when customer enables persistence): configurable per-route with a recommended minimum of 30 days; we can set 30 / 90 / 365 windows contractually.
  • Billing & aggregated telemetry (non-PII): 13 months (we can shorten for enterprise deals).
- Full prompt payloads in logs/backups:
  • Default behavior: prompt inputs are processed in-memory and not written to long-term S3. Short-lived traces used for debugging do include payloads if enabled; those traces are subject to the session TTL above.
  • Backups: we do not include prompt payloads in scheduled backup snapshots unless the customer has explicitly enabled persistence for those payloads.

> 2) Do you support customer-managed CMKs for S3 objects (we prefer to hold the key).

Answer: Yes. We support customer-managed KMS keys (AWS CMK or equivalent) for any persisted objects (logs, transcripts, embeddings). We will supply the bucket ARN and policy to bind the CMK during onboarding.

> 3) If we opt-out of persisting outputs, are there any fallbacks (e.g., temporary debug logs we could accidentally leave on)?

Answer:
- Safe default: Opt-out of persistence = outputs not written to durable storage. Temporary debug traces are a separate toggle — turned off by default for production tiers.
- We recommend adding an audit rule: for any environment that disables persistence, debug traces are automatically purged (TTL=0) and alerts are generated if debug mode is enabled. We can add that rule to the contract appendix.

Additional details we’ll include in a deliverable:
- Where data lives: primary storage region is us-east-1 (we can pin to other regions for Dedicated/Private). Bucket ARNs and VPC config will be provided in the appendix.
- Encryption: TLS in transit + AWS KMS (CMK) at rest; envelope encryption for additional isolation.
- KV cache and runtime caches: in-memory only and not included in backups.
- Embeddings & metadata: stored only when explicitly enabled; otherwise transient.
