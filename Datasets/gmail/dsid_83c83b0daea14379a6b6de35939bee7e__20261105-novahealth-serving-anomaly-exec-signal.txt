Final incident brief (summary):
- Timeline:
  - 07:30 PST: v3.2-quant with INT8 kernel enabled to novahealth-prod pool (canary -> full).
  - 07:50 PST: NovaHealth reports increased 5xx/429 and timeouts.
  - 08:00 PST: Investigation — kernel alignment + KV cache invalidation suspected.
  - 08:10 PST: Rollback initiated to v3.1-stable; temporary limiter relax and rate override applied.
  - 08:30 PST: Metrics returned to acceptable thresholds (p95 < 300ms).

- Root cause: interaction between INT8 kernel path and our KV cache layout for long repeated prefix contexts. Under concurrent access patterns it caused cache thrashing and device memory pressure leading to replica restarts and elevated error rates.

- Impact: NovaHealth production route experienced elevated 5xx/429s and increased tail latency for ~40 minutes; customer retries exacerbated limiter-triggered 429s.

- Mitigations (short term):
  - Reverted novahealth-prod to v3.1-stable.
  - Locked INT8 kernel rollouts and added a canary gating test that simulates long-prefix KV cache patterns.
  - Adjusted autoscaler sensitivity for high-retry scenarios.
  - Coordinated client-side retry guidance with NovaHealth.

- Long term actions:
  - Add a model-serving validation suite for quantized kernels (emulate long-prefix cache pressure).
  - Introduce kernel-level memory safety checks and backpressure signals to avoid silent OOM restarts.
  - Update rollout policy to require staged increases + extended observation for kernel-path changes.
