Team / Timothy,

Quick technical summary:
- Root cause signal: host GPU memory pressure + degraded network egress from AZ B in us-east-2. Instances are returning 503s when KV cache misses align with heavy batching.
- Impact: increased tail latency and 5xxs for long-context requests (seq > 1024).
- Mitigation options:
  1) Live cross-region routing to westus-1 with weighted routing (canary 10% -> 50% -> 100%) — fastest user relief but requires FocusRetail sign-off for transient cross-region processing.
  2) Force rollback to previous model variant on us-east-2 and scale up capacity — slower, risk of queuing.
  3) Apply tighter shedding (reject long-context >2048) — reduces impact but is a degraded user experience.

I recommend option 1 with a 10% canary for 10 minutes, monitor 5xx and latency, and then ramp if stable. We'll also enable prefix cache bypass mitigation to reduce memory churn. Expected customer-visible improvement within 6–12 minutes if routing shift is executed.

Attachments: perf-logs-20261104.tar.gz (contain aggregated host metrics and model PID traces)

Requesting: fast approval from FocusRetail to route to westus-1 for a temporary window and permission to escalate to full shift if canary meets SLOs. Also requesting exec-level awareness in case we need to expand to dedicated capacity.
