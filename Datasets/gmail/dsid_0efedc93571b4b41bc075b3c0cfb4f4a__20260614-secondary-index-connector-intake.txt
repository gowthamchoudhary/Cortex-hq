Thanks all — appreciated the fast turnaround. Quick replies inline to Ben/Vivek and attached the compat matrix you asked for (compat-matrix.csv).

> Auth modes supported
We support API keys, short-lived tokens (via an auth server/STS exchange), and AWS IAM for S3. For managed Pinecone we can accept ephemeral keys issued by your platform.

> Eviction semantics
Configurable: TTL-first policy with optional LRU within the hot window. You can set a hot window (e.g., most recent N days) and a separate cold threshold. We will expose metrics: cache_hits, cache_misses, promoted_to_s3, evicted_to_s3.

> Encryption
By default we rely on provider-managed encryption for S3 objects but offer client-side envelope encryption (CSEK) as an opt-in.

> Multi-tenancy
Per-tenant prefixing for metadata + optional shard isolation. We do not co-mingle tenant indexes unless the customer explicitly wants a pooled model (we document tradeoffs).
