Couple of technical notes after looking at env_inventory.csv and the sidecar constraints: 
- We can implement tracing via a sidecar middleware that captures span context at the ingress and injects into outbound requests. No model-router recompilation required.
- Sampling: recommend dynamic sampling: 10% for low-cost paths, sticky 100% for auth-proxy and model-router when latency > 200ms or error rate spike (>1%).
- I’ve attached trace_hooks.patch — a minimal wrapper and example config for our sidecar. We should also add a short guardrail in the runbook: if we see >20% span drop, revert sampling to 2% and notify SRE.

I’ll open a short PR for the sidecar with the patch and a test harness. Ben — for alerts, if we route model-router latency P1 to Platform SRE, we should also have a fallback to product-oncall if it persists >15m.
