David / Ellen —

Quick technical sanity check on the numbers and a few caveats from infra side: 

Sizing caveats
- The 12 GPU estimate lines up if we assume per-GPU token throughput of ~90k tokens/s for the chosen model and our batching heuristics; that number drops if sequence length variance spikes — recommend we run a synthetic on your real sample to measure tail behavior.
- I recommend allocating at least 2 dedicated NICs per GPU host for isolation (one for control plane, one for inference traffic). If Acme requires encryption-in-flight with per-request TLS termination inside the fleet, budget CPU headroom + ~5-7% network overhead.

Autoscale & warm-pool
- Warm-pool at 20% is sensible. For on-prem, we suggest a multi-stage warmup: keep a keeper-queue of prepared KV caches for top-3 model variants to avoid token-level cold starts. This reduces cold-start latency from hundreds of ms to tens.

Network egress math (sanity)
- Confirmed David's payload estimate. If you plan to stream partial responses, multiply the egress by ~1.6x. Also consider chunked-encoding overhead for long responses.

Operational runbook note
- During the staging test, capture token-level tracing and kernel-utilization samples. We should instrument per-GPU GPU_util, NIC_tx, and scheduler_queue_depth. Set thresholds so the autoscaler triggers before queue depth causes latency degradation.
