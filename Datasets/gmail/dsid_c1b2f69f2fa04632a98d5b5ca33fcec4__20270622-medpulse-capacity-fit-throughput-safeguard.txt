Adding technical detail that will affect the pilot sizing and the org-level reserved throughput recommendation. TL;DR: H100 wins for p95 streaming with minimal batching and aggressive KV-cache pinning; A100 wins for aggregated token throughput when batching is acceptable; L40S is a strong cost compromise for q8 workloads.

Key knobs and my recommendations:
- KV cache: For interactive sessions with repeated context (chat), pinning KV cache on H100 reduces per-token compute and reduces variance in tail latency. Recommend enabling prefix/KV caching for pilot.
- Batch sizing: For A100 throughput profile, use dynamic batching up to batch_size=8 for 13B; for 70B set max_batch=4 depending on mem pressure. Larger batches increase throughput but hurt p95 for streaming.
- Quantization: q8_0 gives ~2–3x speed-up on L40S with minor quality regressions; include eval prompts.

Sizing rough numbers (pilot -> production reserve guidance):
- H100 path (latency-first): single H100 can sustainably handle ~200–300 tokens/sec for 70B fp16 with KV cache; expect p95 headroom if we pin at 150–200 tokens/sec per GPU. For your peak 1,200 tps, that maps to ~6–8 H100s to hit <200ms p95 with margin.
- A100 path (throughput-first): single A100 ~600–800 tokens/sec for 70B with batching; to hit 1,200 tps we estimate 2 A100s (but this will rely on batching and increases p95). If you need strict <200ms p95 during bursts, plan for ~4 A100s.
- L40S q8 path (cost-optimized): single L40S ~1,000–1,500 tokens/sec for quantized 13B; for 70B q8 expect ~500–700. For a q8 fallback strategy, 3–4 L40S could handle aggregated throughput at lower cost with a slight p95 compromise.

Operational notes:
- Reserved throughput contract: recommend negotiating a baseline reserved tokens/sec (e.g., 1,500 tps) with burst credits for 72 hours to cover unexpected spikes.
- Autoscale/burst: Redwood Dedicated supports burst capacity; we'll include automatic fallback to a quantized 13B variant if the latency budget is threatened.
