Hi Audrey — appreciate the clear set of questions. High level answers below; I copied Neha (security) for details and Ben (AM) to coordinate timing for a sample export.

1) Retention windows
- Hosted (default): access logs (request/ingress level) are kept 90 days; higher-fidelity audit trails (admin actions, API key lifecycle, role changes) are retained 1 year by default for standard hosted plans.
- Dedicated: default retention is configurable per contract; customers commonly set 1–3 years.
- Private (VPC/on-prem): retention fully customer-controlled.

2) Exports
- Formats supported: NDJSON (line-delimited JSON), gzipped CSV, and Parquet for large analytics workloads. See attached PDF for field mappings.
- Identifiers: exports can include user IDs and tenant IDs. PII/sensitive identifiers can be hashed (SHA256) at export time on request.
- Delivery: scheduled S3 pushes (daily/hourly depending on plan) are supported for Dedicated and Hosted (enterprise tier). Private customers can configure exports into their storage.

3) Bulk export turnaround
- On-demand exports: for windows up to 3 months we typically deliver within 24 hours.
- Larger windows (6–24 months): delivery time depends on volume; expect 24–72 hours for moderate datasets. For very large exports we coordinate with SRE and provide a target ETA once we scope the request.

4) Deletion proof and tamper evidence
- For Hosted: Redwood provides an export manifest and SHA256 checksums for exported files, plus a signed deletion statement for auditable requests. For Dedicated/Private customers we can implement signed manifests or provide you with a signed purge confirmation tied to the export job ID.

5) Residency
- Hosted: tenant logs are stored in the region associated with the tenant; we offer US-only and EU-only tenancy for enterprise customers.
- Dedicated/Private: residency is customer-controlled.

Hi Audrey — adding a bit more technical detail from the security side and what we’ll need to run a full export / provide deletion proof.

Export formats & fields:
- NDJSON: each line is a single event with standardized top-level fields (timestamp, tenant_id, user_id, action, resource, ip, user_agent).
- Parquet: columnar export for analytics; we partition by date to speed retrieval.
- CSV (gz): available for SIEM ingestion; field order and headers match the attached PDF.

PII handling:
- We support three modes: raw (default for signed contracts), at-export hashing (SHA256) for identifiers, and tokenization (replace identifiers with reversible tokens scoped to your key management settings). For hashing/tokenization we need to agree on the scope and whether token keys are customer-managed (KMS) or Redwood-managed.

Bulk extract workflow and timings:
1) Scope & estimate: share the exact time window + S3 location -> we provide volume estimate within 8 business hours.
2) Preparation: we reserve capacity for the job (if >30 days of data) and provide an ETA; typical large jobs complete within 24–72 hours.
3) Delivery: files are written to your provided S3 prefix with a manifest.json that lists file names, sizes, and SHA256 checksums.

Deletion/proof options:
- Hosted: we maintain a soft-delete window of 30 days for exported log shards; after soft-delete expiration files are purged per our retention policy unless archived by customer. For auditable deletion requests, we provide: (a) the export manifest, (b) signed SHA256 digest of the exported files, and (c) a deletion confirmation referencing the export job ID and timestamp, signed by Redwood compliance.
- Dedicated: you can opt to have Redwood perform a custodial purge with the same signed artifacts, or we can provide tooling and runbooks for you to purge directly if you prefer customer-controlled deletion.
- Private: deletion is customer-managed; Redwood can provide the export tooling and suggested runbook.

Additional notes:
- Cross-region residency: we can enforce region-bound storage for logs at the tenant level in Hosted enterprise — this is a billing/contract term.
- Long-term archival: if you need >3 years retention, we recommend Dedicated or Private and can provide an archival pipeline to Glacier-equivalent storage.
- For M&A evidence: we can attach the relevant SOC2 AICPA pages and provide a signed statement for any requested export/purge.
