Alice — thanks for the matrix and heads-up. High-level guidance here (I'll put a one-page checklist below + attach a template you can drop into your firewall change request):

1) Two-tier allow model (recommended)
 - Tier A (Control plane): Domain-based allowlisting for control/control-plane endpoints (private.reg.redwood.ai / control.redwood-inference.com). Use HTTPS (443) only; we sign all control-plane traffic with mTLS for customer connections. Prefer FQDN+TLS/SNI checks instead of raw IPs where possible because control plane IPs may change across regions.
 - Tier B (Data/model artifacts & runtime egress): Static sanctioned IP ranges for model fetches and streaming telemetry. These are smaller and change infrequently; we'll provide a stable CIDR list you can pin in your NAT gateway.

2) DNS and resolver guidance
 - You can use your internal DNS resolver; however the Private deployment requires outbound DNS resolution for certain signed artifact domains and CRL/OCSP checks. If you prefer to intercept DNS, ensure forwarders allow resolution for the following FQDNs and that responses are not rewritten.

3) Ephemeral port ranges and conntrack
 - Allow outbound TCP ephemeral ports 1024-65535 by default for short-lived connections; recommend setting conntrack timeout to a conservative value to avoid exhaustion during heavy batching. If you must lock down ports tighter, route outbound control/data through a proxy (see below).

4) Outbound proxy / NAT pool options
 - Option A (recommended for strict egress): Configure a dedicated outbound proxy cluster (TLS egress proxy) and allow only that proxy's IPs. Redwood will accept connections from those proxies and you can centralize TLS inspection and logging.
 - Option B: Use multiple NAT pools with sticky SNAT to reduce connection churn and conntrack exhaustion.

5) Operational controls + testing
 - Provide a test plan: curl checks against control FQDNs (validate TLS cert chain + SNI), model artifact GETs (200 + signature header), and telemetry POSTs to telemetry.redwood-inference.com.
 - Test from a representative host behind your NAT gateway and from a host behind the outbound proxy.

6) Audit & compliance
 - Enable egress flow logs for the NAT gateway + host-level connection logs for the POC window. We'll provide a sample SOC2-friendly evidence pack (attached draft).

Attachments included: rdwd_private_endpoint_egress_template.pdf (playbook + checklist). I've also attached a short list of initial CIDRs for model artifact fetch (these are expected to be stable for the POC): 52.24.100.0/24, 52.24.101.0/24, 52.24.102.0/24.
