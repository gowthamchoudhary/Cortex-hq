Alex — thanks for the checklist and timeline. Following up with a proposed set of architecture adjustments based on your constraints. Attachment: mdc-qa-answers-20270427.docx (application/vnd.openxmlformats-officedocument.wordprocessingml.document).

Summary of proposed changes (control plane / data plane separation):
- Control plane placement: Keep control-plane components in your control cluster behind the customer-managed reverse proxy. We will authenticate to the control plane over mTLS; no data plane tokens will be present in the control channel.
- Data plane isolation: Tenant runtime nodes will be physically/virtually isolated per your tenancy requirements. We propose a sidecar-based egress filter that enforces an allowlist and performs per-request authz for outbound flows.
- KV cache demarcation: Sidecar will maintain a local KV cache; cache persistence will live on customer storage volumes. Redwood runtime will only hold ephemeral keys and will never persist tenant secret material.
- KMS routing: We will support an HSM-backed KMS via private peering (BGP or direct connect). Need confirmation of the KMS endpoint IPs and whether your HSM requires private circuit ACLs.
- Telemetry: Provide an option to disable collection entirely or push to a customer-owned observability endpoint inside the tenant boundary.

Action items for MediCore: please confirm the KMS endpoint and indicate if you require a hardware-backed attestation (e.g., PKCS#11 profile certs). Once we have that we will update the diagram and regenerate the interface matrix.
