Hi Dana — thanks for the note and the appendix. I've pulled in Monica (security) and Marcus (enterprise sales) to ensure we answer completely. Inline responses below; attaching our HIPAA summary and a short answers doc.

1) PHI persistence: For Hosted API, Redwood does not persist PHI to long-term analytics stores by default. We do maintain transient KV-cache entries on inference nodes for active sessions (TTL configurable, default 30 minutes). Persistent logging by default is limited to redacted request metadata (timestamp, request_id, tokens_generated) without user payload. Customers can opt-in to full request logging for debugging/analytics and in that case the data is stored in customer-scoped buckets under their account and retention is configurable. For Dedicated and Private deployments, no customer data crosses the customer boundary unless explicitly configured (e.g., optional telemetry export).

2) KMS/HSM: Private deployments support customer-supplied KMS/HSM integrations (AWS KMS, Azure Key Vault, on-prem HSM via PKCS#11). For Hosted, keys are managed by Redwood using KMS with automatic key rotation every 90 days by default; customers may request a dedicated key per account and we support Bring-Your-Own-Key (BYOK) on enterprise plans.

3) Audit logs: Redwood can provide per-request audit logs with request_id, model_version, user_id (if provided), and redaction status. Standard retention is 1 year, but we support extended retention (including 7 years) for enterprise contracts; logs can be exported to S3/Event Hubs/SIEM via secure transfer. Export tooling and schema are documented in the attached audit-log-schema.pdf (snippet).

4) Incident notifications / BAA: Our standard BAA includes 72-hour initial notification for confirmed breaches and 30-day full incident reports. We are open to modifying those timelines for enterprise BAAs; legal can review the redline you shared. If necessary, Marcus will escalate for an exception.

Hi Dana — Monica from Security here. A few technical clarifications and the extracts we'll include in the appendix: 

- Redaction: our redaction pipeline supports automatic PII/PHI detection using regex + model-assisted classifiers. Redaction is applied to logs when enabled; redaction status is written into the audit log as a boolean and a redaction_summary field (samples only).
- Caching details: the KV cache is encrypted at rest with AES-256 and is stored on local ephemeral NVMe for Hosted inference nodes. Cache TTL is configurable down to 0 seconds for customers that cannot tolerate any in-memory persistence.
- Tokenization/embedding: embeddings and token IDs are ephemeral and never written to long-term telemetry unless customer opts in.
- Data residency: for Hosted we support region pins (us-west, us-east, eu-central). For regulated customers we recommend Dedicated or Private deployment to meet strict residency controls.

On logs export: we can push structured JSON records to an S3 bucket you provide (preferred) or deliver to a Splunk/Datadog endpoint via TLS. Which would you prefer for Clearmont?
