1) Probabilistic model: we run a bootstrap of your hourly samples to generate p50/p90/p99 demand curves and translate into sustained tokens/sec and concurrent requests. For each quantile we model three config axes: dense GPU (A100/80GB equiv), int8-quantized variant, and a mixed multiplexed instance profile.

2) Headroom rules: recommend +30% warm-headroom on p90 sustained to allow for prefix cache misses and short ramp spikes; +60% for p99 if you require hard latency gates. We'll provide a matrix that maps pX -> required GPUs for each model fidelity.

3) Networking/egress: initial pass assumes 25 Gbps per host baseline with 2:1 NIC oversubscription at peak. If your on‑prem racks have lower NICs (10G), effective throughput and batching economics change materially — we'll flag that in the spreadsheet.

4) Operational controls: canary rollout topology, warm pool of preloaded KV caches, cross‑region fallback if applicable. We'll include autoscale thresholds (queue depth + KV hit rate triggers).
