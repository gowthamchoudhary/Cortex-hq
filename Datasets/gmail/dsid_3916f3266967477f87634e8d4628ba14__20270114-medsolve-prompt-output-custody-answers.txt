Marissa / team / Dana — thanks for the clear list. Answers below by number (Hosted vs Dedicated/Private differences noted):

1) Prompt inputs (what customers send in API requests)
- Hosted API (default): inputs are NOT persisted to long-term storage by default. We retain transient request buffers and KV caches in-memory for the duration of the request and to support streaming; these are rotated and not written to durable object stores. Short-term request traces (request_id, timestamp, model variant, token counts) are kept in telemetry logs for 7 days by default for debugging and performance SLO analysis. These telemetry logs do NOT contain full prompt text unless customer enables 'persist_inputs' (opt-in).
- Dedicated: by default inputs follow same ephemeral behavior. For Dedicated customers who enable enhanced observability, there is a config flag enable_input_logging=true that writes prompts to customer-isolated object storage; this is off by default. When enabled, storage location is the customer’s reserved S3 bucket (or object store) in the region specified in the Dedicated config.
- Private (on-prem/VPC): All data is kept within customer-controlled infrastructure; persistence semantics are controlled by the customer's deployment configuration.

2) Outputs (generated text)
- Hosted: short snippets used for safety/quality monitoring may be persisted if safety_review=true (opt-in) and are stored in our encrypted customer tenancy for up to 30 days by default, configurable down to 0 days (no storage). We do not use stored hosted-customer outputs to retrain public models; any research use is explicitly gated under customer consent.
- Dedicated: Generated outputs are not stored centrally by Redwood unless the customer enables output_persistence in their Dedicated configuration. If enabled, data writes go to the customer's allocated object store and retention is configurable by policy (defaults can be set per project).
- Private: Controlled entirely by the customer.

3) Runtime logs / traces
- Captured fields (default Hosted telemetry): request_id, model_id, timestamp, latency metrics, token counts, and anonymized error traces. PII-containing payloads are NOT captured by default. IPs and header metadata are captured only for billing/abuse detection and purged within 7 days. No full payloads are sent to third-party SaaS logging providers unless the customer configures log forwarding. For Dedicated, log forwarding endpoints can be customer-managed (e.g., Splunk/Datadog into the customer's account).

4) PII detection & redaction
- Redwood offers pre-storage PII detection that can be enabled as a managed service (pii_detection=true). When enabled, the system applies regex + ML-based detectors and can either mask (replace tokens with [REDACTED]) or hash sensitive fields before storage. This is a configurable pipeline step for Hosted (opt-in), default-off for Dedicated (customer chooses to enable), and under admin control for Private. We also provide client-side SDK helpers to perform masking before sending if customers prefer end-to-end control.

5) Dedicated data residency & customer-controlled storage
- Yes. Dedicated supports writing persisted artifacts (when enabled) directly into a customer-managed S3/GCS/Azure container via cross-account/bucket policies. For Private we run inside the customer's VPC/cluster and data never leaves the customer environment unless explicitly configured.

Additional operational notes:
- Encryption: all persisted data (Hosted tenancy or Dedicated customer buckets) is encrypted at rest with AES-256; keys are managed by Redwood KMS in Hosted but Dedicated customers can opt to use their own KMS keys via customer-managed KMS integration.
- Retention controls: retention windows are configurable (0 / 7 / 30 / 90 / 365 days) for stored prompts/outputs in Hosted telemetry workflows; Dedicated/Private can set arbitrary retention via lifecycle policy on the customer storage endpoint.
- Access & audit: all persisted artifacts are subject to access controls and audited. We can export audit logs for any reads/writes to customer artifact buckets during the retention window.
