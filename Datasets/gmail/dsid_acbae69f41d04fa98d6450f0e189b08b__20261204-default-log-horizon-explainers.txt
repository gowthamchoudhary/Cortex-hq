At a high level (operational defaults for Hosted Redwood API):
- Raw prompts (user input): retained for 7 days by default. Used primarily for debugging/abuse detection; not used for model training.
- Model outputs (final responses): retained for 30 days for debugging, billing reconciliation, and quality incident investigation.
- Streaming token traces / wire-level streaming logs: retained for up to 48 hours; used only for reconstructing streaming issues.
- Derived artifacts (prefix/KV cache snapshots and telemetry extracts): not persisted beyond 90 days unless customer has opted-in to longer storage or Dedicated/Private deployment.
- Attachments referenced in sessions: we store filename and metadata by default for 90 days; we do not persist attachment content unless explicitly uploaded to Redwood storage.

Alice / Marissa — adding a bit more color from Security so Procurement can see exact operational controls and deletion mechanics. This is intended for technical review and to be included as an exhibit in any procurement packet.

Operational defaults (Hosted API):
1) Prompts / Request payloads   - Retention window: 7 days (rolling TTL).   - Usage: retained for debugging, abuse detection, and rate-limit dispute resolution.   - Deletion: records aged past TTL are purged by a background job; tombstones are retained for an additional 24 hours to avoid race conditions.

2) Model outputs (final responses)   - Retention window: 30 days.   - Usage: incident investigation, billing reconciliations, and eval regressions tied to customer prompt sets.   - Redaction: customers can request near-real-time redaction of stored responses via the Console API (erase request endpoint).

3) Streaming token traces / wire logs   - Retention window: 48 hours.   - Usage: transient troubleshooting for streaming latencies or partial-response errors. Not used for analytics ingestion.

4) Derived caches / KV snapshots   - Default: not stored persistently across sessions.   - If a workload opts into cache-persistence for performance, retention is controlled per-customer; default is 90 days unless contracted otherwise.

5) Attachments and file references   - We store file metadata (filename, mime-type, reference hash) for 90 days by default.   - Binary content is stored only when uploaded into Redwood-managed storage and then follows object store lifecycle policies (can be deleted on request).

Compliance notes:
- We do not use stored request/response content to train public models.
- For EU residency requests we can scope retention to a regional bucket and adjust TTLs — that requires EU region flag during onboarding.
