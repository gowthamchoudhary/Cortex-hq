Tom / team — quick technical notes ahead of today’s deep-dive. I’ll keep this short and focused on the Private/VPC and air-gap options we discussed.

Option A — Dedicated VPC (recommended first step):
- VPC with private subnets for inference workers, no public IPs on worker instances.
- Egress via managed NAT/egress gateway that we control; allowlist specific service endpoints.
- Dedicated GPU pool (reserved) mapped to the private subnets (Redwood Dedicated).
- KV cache + model artifacts stored in customer-managed S3 with role-based access and SSE-KMS. We support HSM-backed KMS if you require.
- Logging/audit: JSON structured logs streamed to your SIEM (support for S3/CloudWatch/Direct syslog).

Option B — Air-gapped appliance (for enclave-like needs):
- Physical or VM appliance deployed in an isolated network segment with no internet egress.
- Model/artifact sync performed via signed offline bundles; we provide tooling for bundle creation and integrity checks.
- Offline audit logs exported on schedule to customer storage.

Security controls checklist (what we’d need from MedClear to qualify):
- Up-to-date network diagram (edge, proxies, egress, NATs) — attachment noted.
- Expected throughput/peak RPS and max sequence length (for model sizing).
- KMS/HSM preferences and key rotation policies.
- Retention requirements for logs and prompts (GDPR/HIPAA constraints).

- Short architecture options brief (we’ll attach a one-pager after the call).
