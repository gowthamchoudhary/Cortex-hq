Summary of first-pass triage (10:10am):
- Root cause hypothesis: intermittent JWT validation exceptions caused by clock skew and a corner-case in our token parser when encountering `nbf` fields. The validator throws an internal exception which bubbles up and gets treated by the gateway as a 5xx rather than an auth failure.
- Consequence: client libraries interpret 5xx/503 as transient and retry, creating a retry storm that elevates traffic and pushes other pools to 429.

Immediate mitigations in order of priority:
1) Hotfix gateway mapping (deploy within 30–90m): explicitly map known token-validation exceptions to 401/403 and include a structured body that signals non-retryable auth failure.
2) Deploy an auth-failure rate limiter and short circuit for token validation errors to cap amplification while we roll the mapping fix.
3) Add logging to capture token `iat/exp/nbf` and the upstream clock offset to confirm clock skew incidence.
4) Longer-term: harden token parser for unexpected/malformed `nbf` and add a small grace window for clock skew.

I’ve prepared a config patch (prod-gateway-config-diff.patch) with the mapping change and a simple limiter. If Ops approves, I can push this immediately. We should also prepare a customer-facing incident note and exec summary.
