Preliminary topology notes (things we'll validate during the deep dive):
- For p50 <= 120ms on generation with ~150 tokens, we'll need a latency-focused cluster. Recommended starting point: 4xH100 (dedicated) with continuous KV-cache support and small batching window (10-30ms).
- If Nova prefers a cost-first topology, 8xA10G or A100-based setup with 4-bit quantization on the 70B variant tends to hit cost targets while still meeting p95 <= 400ms for many workloads.
- Rerank flow: prefer running the 70B quantized model pinned on a dedicated pool with a warm persistent KV-cache + synchronous batched scoring for top-K candidates. That avoids repeated cold starts.
- Autoscaling: use concurrency-based autoscale with a burst buffer (burst capacity ~2x baseline) and route-level circuit-breaker to degrade to a smaller model when load or inference error rates exceed thresholds.

Measurements & test matrix we want from Nova prior to perf tests:
- Representative request corpus (JSON) for generation and rerank.
- Peak concurrent sessions and typical session duration.
- Any network constraints (NAT, private endpoints, egress limits, VPC endpoints for KMS).
- Allowed maintenance windows for private/Dedicated changes.

Operational controls / security considerations:
- KMS/HSM endpoints, which cipher suites you require, and whether you need Bring-Your-Own-Key (BYOK).
- Audit log retention: confirm retention window (we can support customizable retention buckets, but need baseline).
- Data residency: confirm if all inference must remain in us-east-1 or if multi-region fallback is allowed for DR.
