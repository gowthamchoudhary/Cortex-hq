Raj / Marissa — detailed answers below, plus next steps and the artifacts we can attach to the SIG.

1) Stream vs Export (supported topologies)- Hosted (shared control plane): periodic exports (S3) + pre-signed URL delivery; no direct tenant-level push to customer-managed brokers by default.
- Dedicated / Private: supported options include
  * Secure Log Forwarder (mutual-TLS) that pushes events to customer Kafka/CloudPubSub with TLS + token auth (at-least-once delivery; ordering guarantees per-request-id)
  * Server-sent events / Webhook stream for small-scale integrations (best-effort ordering, latency 1–3s)
  * S3 export (parquet/JSONL) on scheduled intervals (hourly/daily) or ad-hoc bulk export.

2) Retention, immutable storage, and archiving- Default detailed-event retention: 395 days (configurable per-customer).
- Cold-tier archival: available beyond 395 days; we can enable S3 Object Lock/Gov-Guard (WORM) for contractual evidence preservation.
- Exported archives include file-level metadata and manifest; we keep a signed index entry for each export to prove export time and contents.

3) Tamper-evidence and signing- Every export bundle includes:
  * SHA-256 checksums for each file (manifest.json)
  * A manifest_signature.txt that contains an RSA-PSS signature of the manifest (RSA 2048 / SHA-256 by default) signed by Redwood's export-signing key.
  * A per-customer HMAC (HKDF-derived) to validate origin if requested.
- We store manifest hashes and signing metadata in an append-only audit index (internally time-series-backed with immutability enforced by Object Lock for archived buckets).

4) Customer access model and redaction- Dedicated/Private: customer can be granted a read-only IAM role with temporary STS tokens; access is limited to their tenant paths.
- Hosted: we provide time-limited pre-signed URLs or deliver exports to a customer-owned S3 bucket via cross-account copy (requires mutual account config).
- Redaction: pipeline supports pattern-based redaction (PII regex), field-level white/blacklists, and tokenization. Redaction is applied during export and recorded in the manifest (redaction_policy_id).

5) Forensics / eDiscovery process and timelines- Standard bulk export delivery: 3–5 business days.
- Expedited forensic package (signed manifest, sample raw events, chain-of-custody PDF): 24–48 hours for customers on enterprise SLA.
- We maintain an export audit trail that records requestor, change history, and delivery proofs.

6) Operational notes and performance- Streaming latency: typical end-to-end 1–3s for the forwarding service; ordering guaranteed for events keyed by request_id.
- Export sizes: incremental hourly bundles ~10–200 MB depending on tenant activity; large bulk exports handled via multipart transfer and manifesting.
