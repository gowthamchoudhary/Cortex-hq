Hi all — attaching the evaluation-rubric.xlsx and a slightly expanded POC scope (apex_poc_scope.pdf) per Monica's plan. Key technical details / methodology notes below.

Offline evaluation (recommended):
- Data: de-identified set from Apex (target 5,000 labeled rows; mix of triage Qs, short notes, and multi-turn interactions).
- Metrics:
  - Extraction F1 (for structured fields) — target >= 0.92
  - Intent classification accuracy — target >= 0.92
  - Semantic similarity (embedding-based) for summarization tasks — mean cosine >= 0.82
  - Hallucination rate: measured by sampled manual review and automated assertion checks (we calculate % of outputs with at least one medically incorrect assertion). Current pass threshold: <= 1.0% (we can iterate).
  - Latency (local sim): p50/p95 for typical request size; target p50 <= 250ms, p95 <= 600ms on our dedicated-high-throughput config.
- Evaluation harness: we'll run reproducible offline runs in an isolated, SOC2-compliant environment. Raw predictions are stored encrypted and will be purged 30 days after report generation unless Apex requests archival.

Online shadowing (recommended next step):
- Duration: 2 weeks at production traffic levels, logging-only (no user-facing outputs).
- Goals: validate latency under load, monitor distributional drift, collect failure cases, and compute live hallucination/accuracy proxies.
- Controls: full request/response hashing and token redaction; KMS-managed keys for any stored artifacts; audit logs available via the Console.

Grading rubric (summary, full file attached):
- Green: Extraction F1 >= 0.92 AND hallucination <= 1.0% AND latency p50 <= 250ms -> move to limited live trial
- Amber: metrics within 5% of thresholds -> remediation + second shadow run
- Red: any metric misses by >10% or any high-severity safety finding -> stop and remediation discussion
