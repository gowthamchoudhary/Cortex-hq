Samantha —

Following up with the technical detail Kim promised. Below is a concise description of how we implement customer key custody and the operational boundaries for Redwood staff in a Private (VPC/on-prem) deployment.

Key custody and runtime crypto model:
- Option A (Customer KMS endpoint): Redwood runtime calls your KMS endpoint (KMIP/Cloud KMS) via mutually authenticated mTLS. Redwood never stores plaintext keys or key material. The runtime holds only an in-memory reference and a short-lived session token to perform crypto ops.
- Option B (HSM connector inside your network): We run a connector agent in your VPC or datacenter that talks to your HSM. All signing/decryption happens inside your network. Redwood operators do not have network access to that agent unless break-glass is invoked.

Operator privileges and break-glass flow (operational controls):
- Normal ops: operator roles are limited to orchestration, health checks, and logs redaction. No operator action can retrieve key material or raw inference payloads.
- Emergency ops:
  * Trigger: customer reports incident and submits an emergency access request using the pre-agreed DocuSign envelope or a signed ticket.
  * Approval: two-person Redwood ops authorization (senior SRE + on-call security engineer) AND an explicit customer authorizer (named person/email in the DPA exhibit).
  * Session: access is timeboxed (maximum 4 hours by default), audited (session recordings and syscall-level logs where available), and limited to the minimum set of endpoints needed for the fix.
  * Post-incident: a remediation and audit package (logs, session recordings, actions taken, and a plan to rotate keys if key exposure is suspected).

Logging and auditability:
- We retain all operator session logs for 180 days by default for Private customers (can be extended contractually).
- All operator API calls are signed and included in an immutable append-only ledger (signed by our ops key) that is delivered to customers upon request.

Notes on data egress and regional controls:
- By default, we scope model weights, inference traffic, and telemetry to the deployment region you choose; cross-region replication is off unless explicitly enabled.
- Any telemetry that must leave the VPC for Redwood's control plane is hashed/minimal and marked in the DPA exhibit.
