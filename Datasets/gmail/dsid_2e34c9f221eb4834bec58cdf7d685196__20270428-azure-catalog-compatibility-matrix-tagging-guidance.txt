Hi Sarah —

Attached are the three artifacts you requested: compatibility_matrix_v1.xlsx, sku_tagging_guidelines.md, and arm_template_example.json. Quick highlights below and a recommended validation checklist at the bottom. Please review and tell me if you want any column additions in the matrix.

Compatibility highlights (short):
- We support x86_64 containers for all published images; arm64-ready images are available for our inference runtime but require explicit image tags (see matrix).
- Recommended VM families: NCasT4_v3 / ND A100 v4 for high-throughput Dedicated pools; Standard_D4s_v4 / Standard_D8s_v5 acceptable for small dev/test workloads.
- Drivers: NVIDIA 525+ for CUDA workloads; we include a fallback path with CPU-only quantized variants.

SKU tagging guidance (summary):
- Offer: redwood-inference-platform
- Plans (examples): redwood-basic, redwood-pro, redwood-enterprise
- SKU naming: plan_SKU-{region}-{gpu-type} (e.g., plan_SKU-us-ncast4). Keep tags short; full examples in sku_tagging_guidelines.md.

ARM template notes:
- We include a sample that wires a user-assigned managed identity and sets an MSI role assignment for the storage account used by model artifacts.
- The example shows minimum required permissions and a parameterized location/sku block.

Validation checklist (suggested):
1) Provision test subscription + publisher account linkage.
2) Deploy ARM template in test subscription; confirm MSI can read blob manifests.
3) Launch a small Dedicated pool with NCasT4_v3; run the smoke-start script in the repo.
4) Confirm telemetry and logging ingestion to the Azure Monitor workspace (we’ll share sample queries).
