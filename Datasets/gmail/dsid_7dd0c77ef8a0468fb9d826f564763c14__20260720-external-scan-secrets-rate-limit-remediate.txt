Aaron / Kimberly —

Quick technical update and planned ETAs below. Marking INF-7894 (service keys) and INF-7901 (auth rate-limit bypass) in our tracker.

1) Exposed service account keys (INF-7894)- Findings: Public S3 object contained JSON with long-lived service key.- Remediation actions taken: rotated the exposed key, revoked related IAM credentials, added S3 bucket policy to block public ACLs, and added a pre-commit lint (terraform-policy) to block accidental public exposures.- Evidence: rotation logs (attached kvcache_rotation_logs_20260719.txt), IAM revocation audit (Jira INF-7894 has the revocation PR links), and updated pentest summary.- ETA: Closed on 2026-07-19 (re-check performed). We will schedule a targeted external re-scan by 2026-07-22.

2) Auth rate-limiting bypass (INF-7901)- Findings: Token refresh endpoint accepted repeated refresh attempts without incremental delay when calls came from the same IP with varied User-Agent headers.- Remediation actions planned: enforce server-side progressive backoff + nonce validation on token refresh; add rate-limit counters per IP and per client ID in front of the auth mesh; instrument additional audit logging for refresh attempts.- Current status: mitigation (temporary) applied 2026-07-16 to limit concurrent refreshes per client to 5 attempts/minute; permanent fix PR is open and under review (PR #4721).- ETA: Permanent fix to be merged and deployed to prod by 2026-07-21; post-deploy smoke tests and logs collection complete by 2026-07-22.

Notes on evidence: we will provide links to the PRs, a short runbook describing the mitigation, and a subset of anonymized refresh logs demonstrating the rate-limit behavior before/after. For compliance reasons we will not include any user-identifying data in logs.
