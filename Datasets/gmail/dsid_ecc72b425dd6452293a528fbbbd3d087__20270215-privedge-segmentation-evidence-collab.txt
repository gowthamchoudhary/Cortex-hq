Markus / Ellen — attached is the first-pass diagram set and accompanying notes. Files: privedge-segmap-20270214.pdf (annotated topology), segmentation-canvas-v2.pdf (matrix: shared vs tenant-owned), network-dataflow-privedge.svg (dataflow with egress paths). Highlights below: 

- Control plane: logically multi-tenant control plane hosted in a separate management VPC in the same region; control-plane API endpoints authenticated with mTLS and role-restricted service accounts. Not exposed directly to tenant workloads.
- Data plane (inference runtime): per-tenant runtime pods backed by dedicated GPU pools in Dedicated capacity mode. Network namespaces per tenant with strict iptables-based default-deny and KVM-level hypervisor isolation where applicable.
- Shared services: central observability ingestion (ingest pipeline is write-only from tenants), model artifact registry (read-only mount to runtimes), and shared NAT gateway for controlled egress. These are clearly enumerated in the segmentation matrix with rationale.
- Egress & outbound controls: tenant egress flows through a managed egress proxy with per-tenant allowlists; egress IP ranges are rotatable per customer request. By default we apply outbound TLS inspection to destination IPs for known telemetry sinks; sensitive outbound destinations can be denied.
- KMS / keys: customer data-at-rest keys are managed in a customer-scoped key ring (Cloud KMS/HSM) for Private deployments; audit logs are retained 90 days by default with options to extend. Key material never leaves the customer's key ring and access is recorded in logs with tenant identifiers.
- Logging / PIIs: inference request payloads are not persisted outside short KV cache TTLs unless customer enables retention; we provided an example retention policy in the Q&A doc.

A few SIG/CAIQ notes included in the Q&A doc: mapping for 3.1–3.6 where applicable (network segmentation, egress control, key management, logging retention). Kimberley: please see inline where we reference CC6.1 for access control and CC7.2 for encryption-in-transit.
