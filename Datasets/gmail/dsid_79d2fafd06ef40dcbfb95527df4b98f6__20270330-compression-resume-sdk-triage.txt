Thanks Mina — flagged to runtime. Quick notes after a first pass through the logs: the traces show a few interesting markers around chunk flushing and an unexpected FIN after a partial chunk. Two hypotheses:

1) The server-side streaming assembler expects uncompressed chunk boundaries and some heuristics for chunk-size/flush; compressed payloads change the timing/size characteristics and could expose a race in the streaming buffer finalization path.
2) There's an off-by-one in our chunk-reassembly path when clients send compressed bodies which results in a truncated SSE/stream being emitted before final bytes are flushed.

Action items:
- I'll open an internal Jira (INF-9821) and assign a triage owner.
- Jonas, can you try to reproduce on a dedicated node with a synthetic client that mirrors Devon's config? If reproduced, capture minimal server-side logs and a tcpdump of the handshake/stream.

Short-term mitigation for the customer: as you suggested, disabling request compression is the fastest route. We may also ship a small SDK patch to add a "X-Resume-Sequence" header the server can echo in the response to help resume, but that will be behind a toggle and needs product signoff.

Update after a repro attempt in our staging Dedicated cluster: we were able to reproduce with the customer's exact SDK config (gzip + streaming, long prompts). Root cause appears to be a timing window in the streaming assembler where compressed input delays final flush, while the connection close is interpreted as an immediate stream termination. The assembler then emits the partial buffer.

What we're doing:
- INF-9821 created and assigned to runtime-streaming (https://redwood.atlassian.net/browse/INF-9821).
- Short-term patch (hotfix) to add an extra grace window on connection close to wait for pending compressed flushes: target staging roll 2027-04-05, prod/Dedicated patch 2027-04-10. This should eliminate the current truncation in most cases.
- SDK feature ask: we'll add a proposal to the product backlog for a resume-token header + server echo and a small client-side resume flow. If product is onboard, this becomes a Q3 roadmap candidate.

Mina — please relay the temporary workaround (disable request compression or switch to non-streaming) and give Devon the INF-9821 link. If they need an earlier workaround we can ship a small telemetry toggle to Dedicated nodes to extend the grace window immediately (requires CSA signoff).
