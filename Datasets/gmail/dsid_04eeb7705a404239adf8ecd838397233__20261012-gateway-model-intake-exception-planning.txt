Quick triage notes (high level):
1) Compatibility delta: Gateway-v2 introduces two non-backwards-compatible changes: a) rotary embedding parameterization (different positional encoding layout) and b) KV cache key ordering for multi-query attention. Both will cause cached prefixes generated on v1 to be incompatible if switched mid-session.
2) Impact: Hosted routing + cache reuse between requests could lead to garbled continuations for live sessions during a mixed-variant rollout. Offline batch/embeddings unaffected.
3) Options to unblock:
   - Short-term: allow account-level variant pinning for the Sunrise account on the gateway-v2 variant in staging, with traffic split controlled by Redwood. This is strictly a routing change and does not require kernel work.
   - Mid-term: implement a compat shim that can detect v1-v2 prefixes and gracefully invalidate cache on variant switch (ETA ~3-4 weeks, depends on kernel QA).
   - Fallback: force per-request explicit model-version header (customer-managed) — low overhead but requires Sunrise to change client.

Estimate for a staging pin + canary: we can enable account-level pinning and an isolated canary cluster within 48 hours once infra approves capacity. No runtime kernel changes required for that path.
