Hi Julian / Maria — Neha here (solutions engineer). I ran the initial microbench against your preview prompt set and a small gold set (n=150) overnight. High level results and recommended starting point below. Full raw CSV attached.

Executive recommendations:
- Start: Mistral-13B (FP16) as the functional baseline for quality checks. If accuracy and entity F1 are within your acceptance thresholds, run AWQ-6 for latency-sensitive endpoints and GPTQ-4 for batch-heavy pipelines where throughput matters more than the last % of quality.
- Safety: for any route that writes back PHI to patient records, serve FP16 or have FP16 fallback. Quantized variants should only be used on de-identified or review queues until we pass an expanded hallucination validation.

Tradeoffs we observed (summary):
- FP16 baseline (Mistral-13B): entity F1 0.88, hallucination rate 3.2% (on our small gold set), median token latency 95ms on A100-80GB.
- AWQ-6 (13B): entity F1 0.86 (-0.02 delta), hallucination 3.8% (+0.6pp), median latency 45ms (~2.1x throughput uplift vs FP16).
- GPTQ-4 (13B): entity F1 0.87 (-0.01 delta), hallucination 3.5% (+0.3pp), median latency 60ms (~1.6x uplift).
- FP8 experimental (13B): entity F1 0.84 (-0.04 delta), hallucination 4.8% (+1.6pp), median latency 32ms (~2.8x uplift). FP8 has larger variance on rare-entity tasks (we saw 4 cases of swapped entity labels in the 150 sample set).

Notes on operational behavior: 
- AWQ provides the best balance for latency-sensitive interactive routes (lower quantizer noise on prefix tokens, better KV cache compatibility).
- GPTQ tends to preserve tail-quality better for rare tokens but is costlier to compile and has slightly higher memory footprint at runtime compared to AWQ-coded kernels.
- FP8 gives the biggest throughput win but increases risk on hallucination and entity fidelity; requires a stricter QA gate before production.

Suggested configuration by route:
- Clinical triage (interactive): Mistral-13B AWQ-6 with FP16 fallback, prefix/KV cache enabled, 95th latency SLO monitor.
- Nightly batch (bulk summarization): Mistral-13B GPTQ-4 (or AWQ-4 if you want simpler ops), run in Dedicated reserved capacity to hit throughput targets.
- Safety-critical writes: FP16 only.
