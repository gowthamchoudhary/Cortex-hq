Emily / Lauren — quick technical note from infra side so the runbook can be specific:

1) Signed URLs (HTTPS)
- We issue time-limited PUT URLs (recommended TTL 15–60 minutes) scoped to a single manifest file path.
- URLs are generated from a service account; we can require SAML-authenticated exchange to obtain a short-lived token that requests a URL.

2) SFTP option
- We can provision a per-partner SFTP account locked down by IP allowlist. Transfer must enforce SFTP using strong ciphers (no old CBC).

3) Audit / Chain-of-custody
- Every upload logs: uploader identity (SAML Subject or API client id), file checksum (SHA256), source IP, and time. Log entries are retained for 1 year by default and can be exported as a CSV for auditors.

4) Encryption & redaction
- At-rest AES-256. For pen test reports, we recommend redaction of PII before upload; if redaction is not possible, we can accept encrypted artifacts and hold keys in a customer-managed KMS (bring-your-own-key).

5) Manifest schema
- Minimal: filename, sha256, control_id, uploaded_by, timestamp, evidence_type (screenshot/log/report). I'll attach a sample manifest schema to the runbook.

- Create a short-lived account for alex@pentestco.io and require 2FA OR
- Provide a pre-signed URL for one-off PUT and revoke after successful upload.
