Elena —

Thanks for the clear summary and the redlines. We can accommodate a narrow emergency-only operator access carveout with the conditions you listed, with a few clarifying bullets from our side:

- Authorization: Redwood requires an on-call escalation path (Customer-designated approver + Redwood SOC manager). We'll record request, approval token, and issuance time.
- Session limits: access will be time-boxed to a maximum of 2 hours by default and requires re-authorization after expiry.
- Key handling: Redwood will never hold or persist the customer CMK; we use a DEK model where DEKs are ephemeral and wrapped with the customer CMK on-demand.
- Evidence: we can produce access logs, syscall-level command summaries, and a higher-level remediation report within 48 hours. Full session recordings are possible but may require an Ops exception due to retention policies; we'll note that in the DPA appendix.

From an operations perspective, a few technical guardrails we'd require on the Annex:

- Breakglass workflow: authenticated request (customer SSO ticket with escalation flag) -> Redwood SOC triage -> temporary session token minted by customer KMS proxy -> session binds to ephemeral DEK and logs forwarded to customer audit endpoint in real time.
- No persistence of unwrapped keys: DEKs must be zeroized post-session. We'll include a short section describing the key lifecycle.
- Out-of-band notifications: webhook to Mediva's SIEM on session start/stop with session id and operator principal.
