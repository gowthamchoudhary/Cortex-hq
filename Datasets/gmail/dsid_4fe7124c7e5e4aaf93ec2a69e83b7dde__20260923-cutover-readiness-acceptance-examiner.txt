Alex / Priya — thanks, this is exactly the right set of inputs. I've attached a first-pass MAP and an acceptance-tests YAML that maps checks to evidence items. High level approach below; the attachments contain the fields you'll need for procurement and approvals.

1) Success criteria (what constitutes PASS) — measurable, tied to clinical QA and infra: 
   - Latency: 99th percentile inference time <= 450ms for typical request mix (50–350 tokens).
   - Accuracy proxy: top-5 intent match >= 94% on our shared test subset (Synthea v1.4).
   - Consistency: regression rate <= 2% vs baseline model on 500-sample smoke set.
   - Uptime: >= 99.5% during scheduled window (excluding pre-agreed maintenance).

2) Exit gates (fail-fast triggers) — if any of these occur during the evaluation window we pause and triage: 
   - Any single-day regression > 7% on accuracy proxy.
   - Repeated KV-cache evictions causing >10% latency spike across 3 consecutive hours.
   - Data drift: production input distribution shift > 3 standard deviations for two key tokens (predefined list).

3) Acceptance tests (evidence & ownership):
   - Smoke test runbook (Owner: Marissa) — 30-step checklist, pass/fail per scenario, artifacts: logs + sample outputs. See acceptance-tests.yaml.
