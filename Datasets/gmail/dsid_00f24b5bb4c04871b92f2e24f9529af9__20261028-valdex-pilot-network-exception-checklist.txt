Thanks for the context. Quick technical assessment below (high level):

- Runtime: We can run a reduced-capability runtime on T4-class cards using int8 quantization (per-model validation required). Expect ~55–70% throughput of our standard runtime for comparable token sizes. Memory-constrained KV cache will force more frequent recompute and increase latency.
- Networking: We can support an air-gapped model if the control plane is deployed in the customer VPC and we rely on pull-based artifact sync (customer-initiated SFTP pulls) for model updates. Telemetry can be batched and pushed via SFTP gateway during maintenance windows.
- Crypto exception: The HSM limitations mean we cannot use the default TLS cipher profile for mutual TLS termination. Security exception required. Possible mitigations: endpoint-level VPN to isolate control traffic, HSM-backed key wrapping for local disk encryption, and HSM rotation scripts.
- Pilot footprint: Recommend 3–5 worker nodes (16GB GPUs), 1 control-plane appliance in customer VPC, and a staging jump host for maintenance. Staffing: 0.5 FTE infra eng (4–6 weeks), 0.2 FTE release engineer for packaging, and on-call rotation for pilot (1:6) for 8 weeks.
