Adding technical sizing notes and a slightly different shortlist based on latency and caching behaviour. Quoted below are clarifying assumptions and a per-feature token cadence estimate.

Assumptions:
- We’ll plan for 99th percentile peak bursts of 60 QPS for production; pilot we can cap bursts to ~12 QPS with throttling.
- Prefix caching will help for templated prompts (extraction); triage and summarization less cache-friendly because of freeform notes.

Model shortlist (recommendation with tradeoffs):
- open-chat-13b-8k: default for triage in pilot — 8k context, modest memory, good cost/latency.
- open-chat-70b-16k (quantized): reserve for long-form summarization where you need 16k context to avoid multi-pass chunking. Higher cost but simplifies correctness.
- open-embed-2.5b (embedding service) + retrieval: avoid sending full long-text to the LM when only extraction/lookup required — reduces token counts significantly.

Token cadence per interaction (example):
- Summarization (one note): input 700 tokens + output 300 tokens = 1k tokens
- Triage (history of 3 notes + form): input 1,200 tokens + output 200 tokens = 1.4k tokens
- Extraction call (structured): input 250 + output 50 = 300 tokens

Traffic scenarios:
- Pilot peak day (12 QPS sustained for 2 hours):
  - If 50% of QPS are triage, 30% summarization, 20% extraction -> estimated pilot peak-hour token throughput: ~ (12 * 3600) * avg_token_per_call (assume 1.2k) = ~51.8M tokens for that 2-hour window (this is a stress estimate; real daily will be lower).
- Capacity recommendation: pilot on Hosted fine if you accept throttling; for production at 1,200 users with 60 QPS target, recommend dedicated pool sized for ~120 concurrent generation streams with autoscale headroom. That maps to monthly reserved commit in the ballpark of 300–400M tokens/month to keep unit economics predictable.

Operational notes:
- Enable KV/prefix caching for repeated extraction prompts; configure batching window to 10–20ms for triage path to preserve latency while improving throughput.
- If AlphaHealth requires <100ms p50 and <400ms p95, plan for Dedicated with GPU-class that favors latency (smaller batch windows, more replicas).
