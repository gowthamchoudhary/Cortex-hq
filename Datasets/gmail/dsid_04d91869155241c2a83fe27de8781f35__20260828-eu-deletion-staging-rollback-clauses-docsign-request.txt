Adding technical clarification on the retention and rollback mechanics so the annex maps to reality: we keep immutable snapshots (WORM-like) in eu-west for 90 days by default. Those are created daily; we keep a 7-day staging buffer on snapshot deletion so Legal/Customer Support can request evidence or a restore. Operational notes: 

- Staging window: snapshot marked for purge -> 7-day staging flag where the object is read-only and flagged for legal review. During staging the object is not returned to normal workloads.
- Rollback / restore flow: (1) Open a restore ticket (priority set by contract), (2) Provision a temporary restore environment (2–8 hrs depending on data size), (3) Run validation scripts (0.5–24 hrs), (4) If validated, promote to customer workspace or provide data export.
- Evidence SLA: raw log exports and metadata packets are available within 48 hours; full forensic exports depend on size but we aim for a 5-business-day completion for large requests.

Two implementation caveats: cross-border replication snapshots (for DR) may live outside the EU for up to 72 hours for replication purposes; we can restrict replication with a contractual clause but that may affect RTO.
