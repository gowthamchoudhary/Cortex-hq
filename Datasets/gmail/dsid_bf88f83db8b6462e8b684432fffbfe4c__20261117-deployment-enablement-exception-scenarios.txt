Got it — filling in the product constraints tab now. Quick notes while I update the sheet:

- Model availability: for pilot we can offer a limited set of open models (v1.2 quantized) and Redwood-verified throughput profiles; any custom model onboarding will add 4–6w.
- Feature gating: function calling + streaming should be available, but we need to disable cross-tenant KV cache to satisfy isolation guarantees. That reduces effective throughput ~12–18% in some workloads.
- Data residency: Clearview insists logs remain in their VPC; we should confirm whether they expect audit logs to be write-only to their S3 or an exported syslog.

Exception scenarios (draft):
- "Managed VPC with customer-owned logs": Redwood runs controlplane in our tenancy but configures encrypted log forwarding to customer's bucket + customer-managed VPC peering. Pro: faster to stand up. Con: inability to fully attest to network isolation.
- "Containment Appliance (sync-lite)": Ship a minimal runtime appliance that hosts tokenization and caching locally, with model weights in a sealed store; nightly encrypted sync for metrics. Pro: more isolation; Con: heavy ops and lower feature parity.

I'll attach my sheet entries. Tentative blocker: if Clearview requires FIPS-certified endpoints and HSM for key operations we need legal + security signoff and a procurement line for cert work.

Thanks — added the architecture pre-reqs to the sheet and sketched out estimated engineer-weeks. Highlights:

- Network: Customer must provide 2 subnets (controlplane, runtime) and a defined peering model. We can support TLS-over-mTLS, but mutual-auth requires a cert exchange protocol (we can automate via step function but will add ~2w).
- KV cache: to avoid cross-tenant leaks we will run per-customer cache instances; memory overhead suggests +30% RAM per runtime node; this has cost implications for Dedicated pools.
- Quantization: we can support int8 quantized weights; if customer requires non-quantized FP16/32 we need to size for a ~2.5–3x memory footprint.

Exception engineering notes:
- Managed VPC: acceptable if customer accepts that controlplane logs are stored in our tenancy until TTL export occurs (we will write an encryption-and-export runbook).
- Appliance: requires on-prem packaging and a minimal ops agent; provisioning the HSM-backed key store is customer responsibility unless they buy our managed HSM add-on.

Blockers for pilot: HSM requirement (unknown cost + legal), and whether Clearview will handle WAN provisioning for nightly syncs.
