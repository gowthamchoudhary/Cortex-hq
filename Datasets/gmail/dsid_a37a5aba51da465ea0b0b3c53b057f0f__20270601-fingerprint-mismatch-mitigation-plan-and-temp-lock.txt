Agree with Marcus. A few notes from infra perspective:
- The mapping mismatch looks like a changed tokenization boundary for hyphenated IDs (we see +1 token in ~0.7% of the Acme sample). That will increase cache misses for prefix caching but only for specific routes.
- Proposed canary: 6 hours in us-east-1 at 5% of Acme traffic, then 24h at 25%, then full for Acme only (not global) if gates hold.
- Telemetry gates (suggested): token inflation <= 1.5%, error rate delta <= +0.2pp, P95 latency delta <= +15ms. If any gate trips, fallback to lotus-11b for that route and throttle canary to 0%.
- We can implement an adaptive fallback that routes only failing sessions to lotus-11b based on a short-lived session fingerprint. This reduces overall cost compared to global fallback.

We estimate additional cost if we route entire Acme traffic to lotus-11b would be ~18% more token compute for that account. Adaptive routing should keep it under 6%.
