Alex / Maya — tagging in technical detail and the sample files. Quick answers up front, then specifics below.

Short answers:
- CSV schema we need: id, prompt, reference_answer, intent, channel, timestamp, metadata_json
- Masking: remove PHI before upload; a UID can map back internally for audit but do not include raw PHI in the file.
- Hallucination heuristic: rule-based filters + model-against-knowledge-base cross-check + human spot-check sampling. We provide a small heuristic pipeline as part of the eval run.

Detailed format notes:
- sample_dataset_template.csv (attached) — one row per prompt. Columns:
  * id (string)
  * prompt (string) — the input you send to the model in eval (we recommend including system + user context where relevant)
  * reference_answer (string) — canonical expected answer (short)
  * intent (string) — triage label if available
  * channel (string) — web/email/mobile to help analyze distribution
  * timestamp (ISO8601)
  * metadata_json (string) — JSON-encoded metadata for the case (do not include PHI fields)

Scoring rubric (configurable, defaults we propose):
- Short-answer tasks (<20 tokens): Exact-match (case-insensitive, whitespace-normalized). Acceptance threshold: >= 85%.
- Long-answer / summarization: Tokenized F1 (normalize punctuation, stopwords). Target F1 >= 0.78.
- Hallucination: run our heuristic that flags answers with >2 unsupported facts; acceptable hallucination rate: <2% on a 1k sample, with manual spot-check pass-rate >= 95%.
- Latency: median <150ms per token and 99th <1.5s on the Hosted dedicated slot we propose.

Prompt set notes: prompt_set_v1.json (attached) includes system templates, few-shot examples for triage/summarization, and output formatting constraints. Please review and mark any output-schema constraints (e.g., JSON fields you need).

Operational notes for the run:
- We'll run the three recommended models on a dedicated Redwood slot so numbers are reproducible.
- For cost benchmarking, we'll test int8/quantized configs and a fp16 baseline.
- We'll deliver a per-model CSV of outputs + a scoring report and a short write-up of edge-case failures.
