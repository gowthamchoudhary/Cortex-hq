Ben / Marissa — did a quick microbenchmark with Aurora-like models (long-context retrieval + multi-turn). Short summary:
- H100 80GB: median token latency ~28ms, 95th ~110ms for their 8k-ish context runs when using 1:1 KV caching and continuous batching (target SLO 120ms looks safe).
- A100 40GB: median ~44ms, 95th ~160ms for same workload — fails 120ms SLO on heavier requests.
- L40S 48GB: median ~52ms, 95th ~210ms without aggressive KV caching; with prefix/KV cache warmed for repeat prompts you can recover to ~140ms 95th for certain traffic patterns.

Implication: For Aurora’s critical low-latency slices we should recommend H100 80GB for the committed tranche that maps to their 95th-percentile SLO. L40S can be offered as a cost-effective overflow with explicit latency caveats; it should be configured with a warmed KV cache and smaller batch sizing. Recommend we include a clear routing policy in the proposal: H100 for tagged low-latency routes, L40S for background/async jobs and best-effort bursts.

I’ll attach the microbench CSV (summary attached). If they want to push L40S for more workloads we’ll need larger cache sizes (roughly +30% memory footprint) which we should price.
