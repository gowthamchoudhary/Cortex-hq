Preliminary notes:
- The SDK v2.1 defaults apparently introduced a "fast_retries=true" flag for some languages; we see the FluentPay agent set no custom backoff policy, so it inherits the aggressive default.
- Our serving runtime handled the load but latency spiked for other tenants in the same pool because of CPU/IO contention.

Immediate mitigations we can do from our side:
1) Apply a short-term throttle rule for FluentPay's API key to smooth bursts (non-blocking, reduce concurrency).
2) Push a config override in the control plane disabling aggressive fast_retries for their tenant (will take ~20 minutes to propagate).
3) Offer a patch for the SDK today to revert to exponential backoff defaults; engineering estimates a 6–8 hour turnaround for a stable release.
