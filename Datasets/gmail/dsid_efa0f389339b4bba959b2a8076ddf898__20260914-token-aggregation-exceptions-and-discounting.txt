Neha — thanks for the ping and for attaching the logs. Short answer, and then a recommended concession for Atlas: 

Summary of standard billing rules (current product ops):
- Token accounting: we bill per-request for input tokens (context + prompt) and output tokens (generated). Both are billed at the same per-token unit price.
- Aggregation / session window: for streaming or multi-turn sessions we support a 30-minute session aggregation window by default. That means if multiple requests for the same session arrive within 30 minutes of each other and reuse the KV cache, we will aggregate token accounting into a single rolling session bucket for billing smoothing purposes.
- Rounding quantum: we normally round up billing to 10-token increments for each aggregated session bucket when computing line items to reduce metering noise. 
- Minimums: product policy applies a conservative 50-token per-session floor for very short sessions to prevent microcharges. This floor *only* applies when a session ends and total aggregated tokens for that session are <50 — we bill at 50 instead of the actual smaller usage.

How that maps to Atlas' logs: your sample shows long sessions with many small replies spaced under the 30-minute threshold and heavy context retention. Under default rules they will be aggregated into one session bucket and billed accordingly. Because they reuse the KV cache, the incremental cost per reply is primarily the generated tokens + occasional context refreshes.

Recommended concession for pilot / commercial play:
- Waive the 50-token per-session floor for the first 3 full months of the pilot (so sessions are billed at actual aggregated token counts).
- Offer a 15% usage discount (applied to billed token units) for the pilot term (3 months) conditional on a minimum committed monthly spend (MRC) of $6,000. If they want the floor waived without commitment, we could do the waiver for 1 month only.
- For clarity in contract language, add a clause: "For the Pilot Term, Redwood will waive the standard per-session minimum billing floor and apply a 15% usage discount, subject to the Customer meeting the Minimum Monthly Commitment stated in the Order Form. Billing will continue to aggregate session usage using Redwood's standard session aggregation window and rounding quantum (30-minute window; 10-token rounding)."

Operational notes (for onboarding/CS):
- Engineering should enable session-affinity for their Dedicated pool so KV reuse is stable (reduces unnecessary context re-sends).
- Add a metering tag for Atlas sessions so we can easily show usage broken down by session and by context vs generated tokens in the Console.
