Adding technical clarifications for the evidence bundle:

- BYOK import flow (short):
  1) Customer generates a wrapping key (recommended RSA-OAEP-2048 or an EC Diffie-Hellman ephemeral keypair) in their environment.
  2) Customer encrypts (wraps) the plaintext key material locally and uploads the wrapped blob via the Redwood provisioning API over mTLS.
  3) Redwood KMS imports the wrapped blob directly into an HSM-backed key slot; the HSM unwraps using a vendor-protected key and stores the key material in HSM key objects.
  4) No plaintext key material is ever logged or stored in application-level memory dumps; we enforce zero-dump controls and limit key material residency to HSM-protected contexts.

- Plaintext export: not supported for HSM-protected key objects. For non-HSM (software) keys in certain Dedicated/Private variants, we surface explicit warnings and require an elevated approval flow. We will include a short attestation statement confirming "no-plaintext-export for HSM objects".

- Remote attestation: for Redwood-hosted HSMs we can provide the vendor-signed attestation document and a sample challenge/response transcript. For Dedicated/Private deployments we provide instructions for customers to perform on-site verification or for us to run a supervised attestation run.

- Rotation & revocation: default rotation cadence is 90 days; customers can request on-demand rotation via the API. We support key versioning and immediate revocation; we will include the documented API call examples in the runbook.

- Audit logs: KMS admin and crypto operation logs include UTC timestamps, caller identity, operation type (import, sign, decrypt, rotate), and opaque key-id references. Exports are provided as gzipped JSON to a customer-owned S3 bucket or to a shared Drive link for procurement review. Default retention 365 days; enterprise retention tiers available.
