Sara — short answers inline:
1) Retry/backoff: we recommend a bounded exponential backoff with jitter for non-idempotent function triggers; for idempotent calls (e.g., writing to an audit log with a request-id) it's safe to do up to 3 retries with exponential backoff (initial 200ms, 500ms, 1s) and an overall 3s deadline. I'll paste a code snippet in the call.
2) confidence_score fallback: treat as nullable in the schema. If your model doesn't emit it, the validator will accept null and we recommend adding a downstream inference-derived surrogate (e.g., softmax max token probability) as optional enrichment.
