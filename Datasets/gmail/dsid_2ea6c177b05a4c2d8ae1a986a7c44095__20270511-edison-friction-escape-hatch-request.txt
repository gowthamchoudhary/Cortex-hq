Thanks Naomi, Samantha — I dug through the repro. Short summary: repro-script.py uses our Node SDK with prefetch=auto and opens short-lived sessions per request pattern that triggers background KV priming. The runtime currently keeps a per-session lease on a multiplexed connection while the KV priming job is in-flight; under certain timing distributions the lease reference counter isn't decremented if the client shuts down mid-priming. This leaks an in-memory session object that holds a reference to the stream.

Short-term mitigation (non-invasive):
- We can expose an SDK runtime toggle: REDWOOD_PREVENT_PREFETCH=true (env var) or sdk option preventPrefetch:true. That will make the client skip scheduled prefetch jobs; it avoids holding the lease and should stop connection growth. Non-breaking for generation, but will raise token latency for first-hit prefixes.
- Suggested throttle window: preventPrefetch=true for the overnight canary (8–12hr), with a 5s request-level connect timeout and backoff to avoid client retries amplifying open connections.

Timeline for a proper runtime fix (no leak):
- Patch (runtime): 3–5 business days including unit tests and perf run.
- Canary: 24–48 hours on dedicated test pool.
- Rollout: 1–2 weeks depending on SLA tiers and canary observations.

I can push the temporary SDK flag today (small client patch + docs). Logan — can you review the safety playbook and define the X threshold for active connections? Marissa — heads up for customer comms and to align on the canary window.
