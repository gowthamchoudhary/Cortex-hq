Summary from infra analysis:
- Root cause hypothesis: rapid fanout from a single high-QPS checkout route at Checkoutly caused disproportionate per-shard KV cache churn. When the cache misses increased, worker execution path dropped into slower fallback kernels and per-request latency increased, producing backpressure on ThinQueue.
- Evidence: attached microtraces show >60% cache miss rate on the two hot workers, and runtime counters show increased fallback kernel usage at the same timestamps. (attachment: checkoutly-kv-sample-20290514.txt)

Short-term mitigations we can enact within 15–30m:
A) Soft-handoff: mark the two hot workers as 'draining' and route new Checkoutly traffic to reserve pool. This reduces cold-start penalty because reserve pool has warmed KV for common prefixes.
B) Aggressive KV prefetch: temporarily raise prefetch window for Checkoutly prefixes (requires a small config flip, low risk).
C) Rate-smoothing: apply a 10% client-side smoothing at the router to reduce instantaneous fanout spikes.

I recommend we do A + B immediately; C as a fallback if we still see >20% p95 delta after the first wave.

I attached a debug tar with the microtraces and a short difflog.
