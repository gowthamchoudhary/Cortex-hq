Adding the technical artifacts and clarifying the CI/CD posture during emergency changes. Key points:

- GitOps flow retained: emergency changes are still pushed through a PR and require at least one on-call approver (ops lead) using GitHub protected branch rules. We do allow bypass of certain automated gates where the pipeline is blocked for non-critical reasons (e.g., flaky E2E) but we log the bypass.
- Feature flags: all customer-impacting toggles are behind a feature-flag gate and we prefer fast rollback via flags when possible.
- Approvals: Emergency approvers are listed in the runbook (roles, not personal emails) and approvals are captured in the approval_log_20261024.csv we attach. The CSV contains timestamp (UTC), approver email, change id, brief reason.
- Rollback: rollback_playbook_v2.md includes automated rollback commands, canary validation steps, and suggested smoke tests (endpoint check, trace sampling). Post-rollback we run a smoke-and-metrics checklist for 30 minutes and capture pass/fail.

Attachments: rollback_playbook_v2.md (markdown, 18KB), approval_log_20261024.csv (csv, 6KB).
