Ashley — thank you and team. Appreciate the quick turnaround from Logan and Dev. High-level customer update and next steps below (short, customer-ready):

What we found:
- The symptoms map to an interaction between SDK prefetch + our rolling worker restarts. When prefetch is active and a worker is restarted mid-prefetch, the in-flight generator state can be lost and the SDK will re-open a session (new session id) without surfacing an explicit error.

Short-term mitigations we propose (pick one, we can apply immediately):
1) Set prefetch: false in your SDK config (fast, client-side).
2) We can enable session-affinity for your namespace so connections stay pinned during rolling restarts (platform-side config change).

Medium/Long-term plan:
- Dev raised SUP-3210 to persist generator state across worker handoffs; ETA ~2-3 sprints.
- We'll also add a telemetry flag to measure how often prefetch was in-flight on reconnect (so we can quantify impact).
