Priya / Dylan — quick sizing notes after a pass on Elaine's numbers and the workbook:

Baseline assumptions I used:
- Model footprint: 7B-quant (approx 12–14GB device memory usable after kernels), 13B fallback (approx 26–30GB)
- Average latency target p95 150–200ms on A100-class GPUs for 7B with batching and KV caching
- Token throughput per GPU (steady, mixed seq): ~18–22K tokens/sec for 7B-quant; 9–11K tokens/sec for 13B

Sizing (pilot steady-state ~120 QPS, avg 450 tokens):
- APAC (55% = ~66 QPS): recommend a steady pool equivalent to 3 dedicated A100-equivalent nodes for 7B-quant, with 1 hot-standby node that can be traded into a burst lane (turns pool from 3->4 nodes)
- EU (25% = ~30 QPS): 1.5 node equivalent -> round up to 2 steady nodes, 1 standby for bursts (2->3)
- US (20% = ~24 QPS): 1 node steady, 1 standby for burst (1->2)

If we assume marketing spikes to 300 QPS global, the burst lanes above (standby nodes per region) cover most cases; for larger spikes we can add cross-region overflow routing to US/EU pools.

Cost tradeoffs: using 7B quant keeps node counts low; using 13B fallback increases steady-node counts by ~1.8x per region and adds reentrant latency risk during fallback.
