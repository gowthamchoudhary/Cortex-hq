On 05/01 08:14 Jamie reported token emission stalls and 502s. Quick findings from initial traces:
- Token emit latency skyrockets at ~3–4s per token for affected shards; normal is <50ms.
- Proxy (edge) shows repeated chunked-transfer timeouts: client kept the connection open, but our edge stopped flushing chunks for long pauses.
- There is a correlated surge in in-flight requests ~x2.1 at 07:48 that aligns with the promo spike they mentioned.

Hypothesis: a routing rule change we pushed yesterday adjusted the batching window aggressively for medium-length sessions. Under sudden throughput increase, the batch coalescer is holding chunks longer which exposes upstream keepalive/chunked timeouts and increases memory pressure. Kernel selection logs show fallback to a slower attention kernel for some model variants under those sequence lengths.

Immediate mitigations I recommend (ordered):
1) Reduce the batch coalescing window to the previous setting (rollback last night’s routing policy) — safe, quick.
2) Temporarily lower max-inflight per connection for Slate to throttle burst at edge.
3) Enable immediate emit flush on heartbeat miss (duck-tape but reduces user-visible silence).
4) If needed, rollback the kernel selection tweak for the affected model variant (higher risk, needs canary).

I’m collecting full traces and will upload to Datadog shortly. Sharing link when ready.
