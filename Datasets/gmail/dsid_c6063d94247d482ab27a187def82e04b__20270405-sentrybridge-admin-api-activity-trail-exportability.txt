Alex — thanks for the clear ask. Short recap and next steps below from our call + internal owners looped for technical details and the questionnaire.

Recap (high level):
- Exportability: Both admin activity (user/console changes, role/permission changes) and API invocation logs (per-request metadata, timestamps, latency, status codes) are exportable to customer-owned S3 or pushed to HTTPS endpoints via a secure connector. Exports can be run ad-hoc or scheduled (daily/hourly).
- Verifiability: Exports include an export manifest (CSV) and a SHA256 digest per file. We can also provide a signed manifest (HMAC with customer-managed key) for higher assurance.
- Immutability: We support two approaches — a write-once S3 export (WORM/retention lock) and an append-only export manifest stored for the retention window. For on-prem/private deployments we can enable local immutability hooks; for Hosted we use S3 Object Lock + KMS-backed encryption and retention policies as part of Dedicated/Private plans.
- SOC 2: Redwood's SOC 2 Type II report covers logging, monitoring, and change control relevant to audit trails. Sensitive-data access to logs is controlled via RBAC and KMS access; Marissa will attach the SOC 2 summary and scope.

Technical summary (deliverables):
- API log schema: timestamp, request_id, client_ip (if applicable), user_id (redacted if PII), route, method, status_code, latency_ms, response_size_bytes, agent_string (trimmed), request_headers_hash. We'll provide a JSON schema and a CSV sample.

A detached signed manifest (HMAC-SHA256) can be produced using a customer-provided KMS key for verification.

- SOC 2 scope: Redwood's Type II report covers logging and monitoring controls. We will provide the SOC 2 cover letter and a redacted report excerpt demonstrating log retention and access controls.
