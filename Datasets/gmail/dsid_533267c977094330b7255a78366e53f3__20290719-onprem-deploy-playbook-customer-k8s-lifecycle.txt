See notes below — rough-first-pass recommendations to discuss on Tue.

Cluster topology (recommended)
- Control plane: 3x control-plane VMs on dedicated hosts, anti-affinity across racks. K8s version: 1 minor behind upstream stable (we'll pin).
- Etcd: co-located with control plane but on separate disks (RAID1 or mirrored NVMe). Snapshots to object gateway nightly.

Node pools
- infra-pool (3-5 nodes): 32 vCPU / 128GB each, run kube-system addons, logging/metrics (Prometheus remote write to local object store), ingress, and CSI controllers. Tolerations for critical DaemonSets.
- model-cpu-pool (4-12 nodes): 48 vCPU / 256GB, local NVMe (2TB) for model cache; mount as ephemeral local PVs + CSI-local for fast workloads. Use liveness/readiness probes with appropriate timeouts (models may cold-start).
- model-gpu-pool (2-6 nodes): 8x A40/T4 equivalency per node (or customer-provided GPUs), 256GB RAM, nodes labeled gpu=true. Use device-plugin and nodeFeatureDiscovery.
- storage-pool (2-4 nodes): attach to on-site SAN (iSCSI) for block volumes, run Rook/Ceph as an option if customer prefers software-defined storage. Provide CSI + StorageClass with reclaimPolicy=Retain for archive volumes.

Storage strategy
- Model cache: local NVMe (CSI local PVs) — very low latency, not replicated; acceptable for cache; rehydrate from SAN/object-store on eviction.
- Persistent model artifacts & metadata: Ceph/RBD or SAN-backed PVCs with encryption at rest (we will rely on host-level dm-crypt + KMS keys).
- Backups: nightly incremental snapshots to on-site object gateway (S3-compatible) with 90-day hot retention; archives to the SAN with lifecycle policy.

Encryption & KMS
- Support for KMIP/KMS client to fetch CEK from the customer's HSM (KMIP gateway). If HSM not available, use customer-managed KMS in a locked subnet. We will document key rotation and access controls in the SOW.

Network & gating
- VLANs: control-plane, infra, models, storage, mgmt. Tagging on ToR required.
- MTU: prefer jumbo frames (9000) on the rack interconnect for NVMe traffic; fall back to 1500 if network cannot support.
- Egress: all outbound traffic must go through vetted gateway; we will provide a small set of CIDR/IPs and FQDNs for update mirrors (only required for initial OS/package distribution).
- Firewall rules: allow kube API (TCP 6443) to and from infra nodes; etcd port range; node-to-node high ports for container traffic; NFS/iSCSI ports only on storage VLAN.

Operations & lifecycle
- Maintenance window: weekly 2-hour windows (Saturday 02:00-04:00 local) for node upgrades; canary strategy: drain 1 node at time in model pools, observe QPS/cold-start impact.
- PodDisruptionBudgets: set for critical services and set maxUnavailable=1 for model-serving deployments to limit simultaneous evictions.
- Observability: Prometheus + node-exporter, central logging to on-site ELK; audit logs sent to immutable object store for SOC.

POC/Canary plan
- Phase 1: infra + control plane + one model-cpu-nodepool (2 nodes) + basic CSI local. Run sample traffic, validate cold-start < 2s for cached models.
- Phase 2: add GPU pool, integrate SAN/backup, KMS, and finalize SLOs.

Michael — quick answers below, and attaching our playbook PDF and a draft SOW link for signatures.

1) KMIP/HSM: yes — we support KMIP v2 and have a client implementation that integrates with both host dm-crypt and Ceph auto-unlock. We'll include an HSM integration appendix in the SOW.

2) IOPS guidance (very rough):
- Cache hit (local NVMe): ~5k-15k IOPS per NVMe depending on drive model; plan for 10k IOPS baseline per model-cpu node to cover bursty inference and small random reads.
- Rehydrate from SAN/object-store: depends on SAN characteristics; plan for 200-600 MB/s per node during rehydrate if NVMe saturates. We will run a workload profile during Phase 1 to refine these numbers.

3) Immutable logs (WORM): yes — configure object gateway lifecycle and bucket-level WORM with an immutable retention policy. We'll document retention windows and access controls; Redwood will write audit logs to that bucket via dedicated service account and rotation key.
