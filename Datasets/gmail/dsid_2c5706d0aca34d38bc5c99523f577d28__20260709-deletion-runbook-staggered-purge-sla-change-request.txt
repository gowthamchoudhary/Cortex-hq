Hi Amy — following up with operational detail and the Glacier snapshot policy attached.

Operational summary:
- We run incremental purge jobs per-account, grouped by data-class, on a staggered cadence by default for enterprise tenants. For accounts without an enterprise hold, standard cadence is a 48-hour sweep after the retention expiry. Enterprise accounts (contracted) can have canary windows (30/60/90) configured — this prevents full-batch deletion at a single time.
- Emergency preservation: send the preservation ticket (see Tessa’s attachments) to cloudops@glacierstorage.com and mark it HIGH. Glacier will suspend delete jobs for the affected namespace; we also set an immutable hold flag in our control plane which prevents retries.
- Rollback/restore: if deletion begins and you need a rollback, Glacier provides a 7–14 day retrieval window for deep-archive objects; we coordinate expedited restores and prioritize retrieval for compliance requests.

We can start a scoped canary purge for non-sensitive buckets while preserving the audit-scope objects you identify. If Acme decides a permanent change to retention cadence is needed, we will route a DocuSign amendment (link provided below).
