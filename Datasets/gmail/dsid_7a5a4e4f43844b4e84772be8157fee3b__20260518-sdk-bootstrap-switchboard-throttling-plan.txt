Alex / team — adding the technical migration checklist and a concise code pattern for retries. Key points first:

1) Migration checklist (high level):
   - Dual-write phase: run traffic to both endpoints and compare responses at 1% -> 5% -> 20% -> 100%.
   - Canary: route 5% of sessions through Redwood for 24h with detailed telemetry.
   - DNS / gateway cutover window: choose UTC 02:00–05:00 for minimal impact.
   - Rollback plan: immediate DNS revert and traffic kill-switch (Redwood SRE to execute within 5 mins).

2) Client-side rate & retry guidance:
   - Detect 429 and 503: backoff with exponential + full jitter.
   - Initial delay: 200ms; multiplier: 2.0; max delay: 10s; max attempts: 6.
   - If 429 returns Retry-After header, respect it and treat as a hard pause.
   - For idempotency: include an Idempotency-Key header for any stateful writes.

3) Concurrency and batching:
   - Target per-connection concurrency 4–8 for short gen requests (<256 tokens).
   - Batch small requests server-side where possible; Redwood can accept batch-up to 16 inputs on large models.

4) Telemetry and tracing:
   - Add x-redwood-request-id and forward X-Cloud-TraceContext so we can stitch traces.

Sample Node retry snippet (put in SDK bundle):

// pseudo-code
async function callWithRetry(request) {
  let attempt = 0;
  let delay = 200;
  while (attempt < 6) {
    try {
      const resp = await fetch(request);
      if (resp.status === 429 || resp.status >= 500) {
        const retryAfter = resp.headers.get('Retry-After');
        if (retryAfter) {
          await sleep(parseInt(retryAfter) * 1000);
        } else {
          const jitter = Math.random() * delay;
          await sleep(jitter);
          delay = Math.min(10000, delay * 2);
        }
        attempt++;
        continue;
      }
      return resp;
    } catch (err) {
      attempt++;
      await sleep(Math.random() * delay);
      delay = Math.min(10000, delay * 2);
    }
  }
  throw new Error('Max retries reached');
}
