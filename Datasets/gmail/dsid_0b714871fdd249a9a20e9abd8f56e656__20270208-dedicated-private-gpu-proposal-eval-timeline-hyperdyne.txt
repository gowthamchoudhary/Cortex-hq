Hi all — quick technical read on the proposed config and the targets Susan shared. Short answer: yes, the mix will work with a few tuning knobs. Longer details below.

Recommendation (adjusted):
- Pilot pool (us-east-1): 2 x A100-80GB (primary inference), 1 x H100 (for heavy-batch and model variants), 1 x A10G for lower-cost embedding runs.
- Autoscale policy: target 70% utilization on A100s for p50 latency headroom, allow burst to H100 when 95th percentile queue depth exceeds threshold.
- Throughput estimates (approx):
  - Chat (avg 1k token request): A100-80GB ~= 140–180 req/sec each (with our optimized kernel path and quantized weights) -> 2x A100 ~ 280–360 req/sec steady. H100 (burst) adds ~220 req/sec.
  - Embeddings (batching): A10G can handle ~600–800 embeddings/sec when batched (depends on batch size).

Notes: these are conservative numbers assuming single-model replicas and some model-specific memory overhead. If HyperDyne brings a heavier model (2k+ context), we should add one more A100 or increase H100 fraction. For private VPC, we also need to confirm outbound IP allowances for telemetry (or opt-in to pushing logs via customer-managed forwarder).
