Option A — Hosted Standard (recommended pilot)
- Config: streaming for interactive endpoints (low per-request overhead), no forced batching, small prefix caching.
- Latency expectation: p95 ~180–350 ms depending on prompt size and concurrency.
- Unit cost estimate: $1,300–$1,700 / 1M tokens (stated as a range to reflect model choice and streaming vs non-streaming).
- Pros: fastest to spin up, minimal infra commitments.
- Cons: slightly higher per-token cost at steady-state.

Option B — Hosted + aggressive batching for async jobs
- Config: keep interactive on streaming; route embeddings and nightly enrichment to batched endpoints (burst batch size 64–128).
- Latency expectation for batch jobs: 2–5s (acceptable for background flows).
- Unit cost effect: can reduce effective per-token cost for batchy workloads by ~20–40% depending on hit rates.

Option C — Dedicated Reserved (for post-pilot scale)
- Config: Dedicated GPU pool with autoscale and quantization profile optimized for your models; use batching for non-interactive workloads and streaming for low-latency.
- Latency expectation: p95 comparable or slightly better than Hosted for low concurrency; under high sustained throughput batching drops unit cost substantially.
- Unit cost estimate: $900–$1,400 / 1M tokens at scale (after commit), depending on commitment level and quantization choices.

Recommendation for pilot: run Hosted Standard for the interactive paths (meets your 200–300 ms p95 target in most tests) + route nightly enrichment to a batched Hosted endpoint. That lets us validate the feature before committing to Dedicated sizing.
