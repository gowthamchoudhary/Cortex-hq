Appreciate the clear list. I've scheduled a 60-minute preflight for Wed Jul 18 at 10:00 PT and invited your DPO and ops leads. Attached is a short checklist and a CSV with node-class examples tailored to similar healthcare customers. Quick answers inline to help your team triage: 

- Operator access model: we typically recommend a split model for regulated customers: Redwood runs a dedicated control-plane operator (read-only by default) and we provision customer-managed admin service accounts for day-to-day operations. For air-gapped sites we provide an operator bundle that can be installed from your internal registry; operator credentials should be stored in your KMS/HSM and rotated on the same cadence as cluster admin keys.

- Node classes: three logical classes is a good starting point. Suggested sizing (per 8-node rack): control/infra: 2 x m5-large-equivalent (control, probes, monitoring), GPU/serving: 3 x GPU (A10/NVIDIA T4 depending on model) with 192-384 GB RAM, general-purpose: remaining nodes with local NVMe for ephemeral caches. We'll bring a recommended eviction/QoS policy for mixed workloads to the call.

- PV retention: separate policies per data type. Model KV cache: ephemeral by default (rebuild on restart), telemetry/logs: 30-90 days on blockstore with daily snapshots; long-term audit store: immutable export to S3-compatible object storage (encrypted, multipart sync). We'll propose snapshot cadences and retention matrix during the session.

- Network / audit: minimal outbound endpoints for license check and health pings (we provide a short allowlist), and a push model for audit logs to your SIEM. Firewall rules should allow outbound HTTPS to our control-plane endpoints and ICMP/SSH for initial handoff if desired.

Ben / team —

A couple of tactical notes I want on record before the call: 

- Control plane placement: prefer control/infra nodes to be dedicated and spread across failure domains. Use anti-affinity for kube-system critical pods. Control-plane nodes should be tagged for restricted SSH access and run only monitoring/control agents.
- Operator privileges: if Arklight wants full control, provide them a cluster-admin service account and we run our operator with a CRD-only permission set and image admission controls. This reduces blast radius for incident response.
- Node-local storage: for model KV caching, recommend node-local NVMe with a local eviction policy and periodic compressed snapshots to blockstore. Keep the ephemeral cache TTL short (<= 6 hours) to avoid stale state in model serving.
- Backups: enforce immutable snapshots for audit logs for 365 days (industry expectation for certain healthcare audits) but keep user-activity telemetry to 90 days by default. If DPO requests, we can provide a variance table for regulatory requirements.
