Hi Liam — thanks for the clear ask. Putting a short plan below and attaching a 30-day anonymized sample (audit_log_sample.csv) plus our export playbook (log_export_playbook.pdf). High-level summary: 

1) Exports & formats
- We can produce exports in NDJSON, CSV, or Parquet; sample attached is CSV for easiest inspection.
- Standard fields: event_ts, tenant_id, request_id, principal, route, model_id, input_len, output_len, status, additional_meta (JSON blob).

2) Delivery options
- Presigned S3 URL: we can upload an export to a per-tenant S3 bucket and share a time-limited presigned URL (configurable expiry 15m–7d).
- SIEM push: we can stream events to customer-managed Kinesis/CloudPub/Sub or deliver daily batches to your SIEM via secure push.
- Temporary playback console: for scoped playback sessions we can grant read-only viewer sessions for a defined window (auditor IP restricted).

3) Entitlement matrix (proposed)
- Tenant Admin: can request exports, define retention, review events.
- Security/Audit role (customer): read-only export creation and download.
- Redwood Support (on-ticket): temporary, auditable access (timeboxed) scoped to ticket; must be accepted by tenant admin.
- External auditors: temporary token-based access; access granted by tenant admin or by e-signing an NDA; sessions are flagged in audit logs.

4) Redaction & PII
- Exports support configurable redaction profiles (strip raw inputs, mask tokens, or remove prompt fields). Note: redaction is applied at export time and documented in the manifest.

5) SLA & timeline
- We can deliver the 30-day anonymized CSV sample by EOD 2027-09-15 (attached).
- For auditor-scoped temporary access we propose a 3-workday onboarding window (identity check + ticket + audit NDA).

Quick clarifications from the playbook side — copying Liam so he sees these constraints: 

- Export manifest always includes a redaction_profile field that lists what was masked; auditors should receive the manifest alongside the payload.
- For time-limited presigned URLs we do server-side encryption using tenant KMS keys (if customer configured) or Redwood-managed KMS otherwise.
- When auditors request ad-hoc exploratory access (search/playback) we prefer to create a transient auditor role tied to a single session; logs capture every query, and transcripts are retained for 90 days.

If FinBank needs unlimited raw access for remote auditors, that triggers our formal SOC escalation and a data handling addendum — it can be done but requires legal + security signoff.

Technical notes to include in the SIG matrix: 

- Export cadence: ad-hoc, daily, or hourly. Exports are produced as gzipped NDJSON by default for efficient streaming; Parquet available for analytics pipelines.
- Presigned URL behavior: we limit concurrent downloads and issue URLs per-export artifact; expiry default is 24h, max 7d, min 15m. We rotate the object key per export run to prevent replay.
- Access controls: pre-signed URLs only grant GET; to allow auditor search/playback we create a temporary IAM role (timebound) with no write permissions.
- Integrity: every export includes a SHA256 checksum and a signed manifest; manifests are stored in immutable object store (WORM) for 1 year by default.
- Redaction: masking is deterministic and versioned; we include a redaction_version field in the manifest so auditors can verify what algorithm was applied.
