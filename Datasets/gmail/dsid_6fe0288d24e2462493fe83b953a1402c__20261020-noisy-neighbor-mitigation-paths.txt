What Redwood can provide for security review:

- Network diagram variants: Hosted with strict VPC peering, Dedicated in our cloud with tenant-level logical separation, Private VPC appliance diagram.
- Sample audit log extracts and schema for per-tenant request/response logs.

Noisy-neighbor mitigation (Dedicated pool specifics):
- Capacity isolation: Dedicated is implemented as reserved GPU nodes for a tenant. That prevents compute contention at the node level.
- Scheduler controls: We pin long-running batch jobs to separate nodes; short-lived interactive sessions go to separate, autoscaling buckets.
- Continuous batching & fair queuing: runtime uses request-weighted batching and a token bucket shaping per-tenant to protect tail latency.
- Fallbacks: automatic route to a lower-cost model variant or to a neighbouring standby pool only if the tenant explicitly opts in; otherwise traffic is throttled rather than impacting others.
- SLA: For Dedicated we offer an SLO-backed p95 latency target and an enterprise SLA for uptime. We can discuss a p99 SLO as part of an Enterprise add-on.

Trade-offs summary (quick):
- Hosted (logical isolation): fastest to onboard, lower ops overhead, slightly higher risk to tail latency under extreme global burst unless we pin capacity for you.
- Dedicated (reserved pool): best isolation vs noisy neighbors, predictable tail latency, higher base cost but easier to guarantee p99 in practice.
- Private (VPC/on-prem): maximum control, highest ops burden and cost; recommended when regulatory controls absolutely require customer-run infrastructure.
