Sara / Priyom / Marissa —

Below is a concise technical summary you can use in the RFP response (I will paste into the RFP draft):

1) Retention windows (defaults and configurable)
- Hosted API:
  - Generation artifacts (request inputs/outputs) — default: 30 days; can be extended to 90/365 days with an add-on.
  - Audit ledger (API-level audit entries, admin actions, model versioning events) — default: 365 days.
  - System telemetry for reconstruction (traces, sampling logs) — default: 90 days.
- Dedicated (reserved capacity):
  - Customer-configurable retention per-tenant. Standard plans support 365/730/1095 days (1/2/3 years). Longer-term archival available via snapshot exports to customer bucket.
- Private (VPC / on-prem):
  - Fully customer-controlled retention; no default enforced by Redwood.

Notes: Hosted retention above is for the canonical ledger entries required for compliance. For high-volume generation payloads (raw prompt + full token stream) we recommend customers use Dedicated or Private if long-term retention is required due to cost considerations.

2) Export formats & delivery mechanisms
- Full-account snapshot exports: JSON Lines (newline-delimited JSON) and Parquet (columnar) are supported; schema in attached redwood-audit-export-schema-v1.json.
- Incremental exports: incremental cursor-based pulls via the Audit Export API (/v1/audit/exports?cursor=...) producing ndjson deltas.
- Direct-to-customer-bucket: supported for Dedicated and Private (Hosted only for enterprise customers under contract). We sign temporary STS credentials to write to customer S3/GCS, or customers can provide a write-only bucket policy.
- For very large exports we provide multipart upload tooling and a resume-capable redwoodctl client.

3) Chain of custody & tamper-evidence
- Every export includes a manifest.txt that contains export metadata, start/end timestamps, object list, and per-object SHA256 hashes.
- Manifests are signed by Redwood's export signing key (RSA 4096) and we provide public-key fingerprint so customers can verify signatures. Sample manifest in attached chain-of-custody-sample-manifest.txt.
- For Hosted exports we additionally provide a signed S3 object lock option (governance mode) when exporting to a customer-controlled bucket — requires contractual setup.

4) Delivery SLA & timing
- Standard full-account export for medium-sized accounts (<5TB raw ledger) — typical delivery time: 24–48 hours after request acceptance.
- Large exports (>5TB) — time depends on size; we provide a delivery estimate within 48 hours and expected completion within 72–168 hours.
- SLA credits: available for enterprise contracts (tiered by plan). Out-of-scope for self-serve hosted customers unless included in enterprise addendum.

5) Verification & audit support
- We provide MD5/SHA256 checksums and signed manifests; we can also compute deterministic Merkle roots on request for additional tamper-evidence (paid engagement).
- For regulatory audits we can provide a redacted export that omits customer-sensitive PII if required; export tooling supports field-level redaction rules configured by the customer.

6) Deletion & DSR handling
- Data subject request (erase) flows: For Hosted, we remove generation artifacts within the configured retention policy and mark ledger entries with a deletion flag; full removal from backups/archives is subject to retention windows and will follow contractual timelines (we provide timelines in the RFP response).
- For Dedicated/Private customers, DSR handling can be delegated to customer admin with Redwood providing API hooks (DELETE /v1/admin/audit-objects/:id).

Constraints / Items that require exceptions or paid work
- Immediate export to customer bucket for Hosted customers: enterprise contract and configuration of outbound STS permissions required.
- Merkle root tamper-evidence and on-demand notarization: professional services engagement.
- On-site forensic assistance and chain-of-custody witness: professional services and travel/coordination fees.
