Thanks — quick technical notes from infra: 

1) BYOK/KMS
- Hosted API: we don't currently let customers upload their own master key for the multi-tenant hosted control plane. We can offer envelope encryption where a Redwood-managed key wraps customer data keys, but that doesn't meet "non-exportable HSM" requirements.
- Dedicated: feasible to integrate with customer KMS via envelope encryption and key policies; require an admin workflow to install customer key metadata and rotation policies.
- Private: full support for customer HSM / KMS (bring-your-own-key) including HSM-backed key origin and rotation; requires additional runtime and key-handling code paths.

2) Audit logs
- We have an "AuditStream" pipeline (internal proto) that can: stream raw events to S3, BigQuery, or push to a SIEM via partner connectors. Event schema includes request id, model id, route, timestamp, token counts; it currently does NOT capture full response text by default (privacy); can be extended if needed but that has cost and privacy tradeoffs.

3) Retention/deletion
- We can configure retention per-account (default 90d) and offer export before deletion. Deleting KV/prefix caches requires a background sweep and can't be instantaneous for large caches; estimate 24–72 hours for thorough purge depending on size.

Rough implementation estimate attached; this is a cross-team effort (serving runtime, infra, security review).

Questions for Acme: do you need full response bodies in the audit stream? Do you require HSM-backed non-exportable keys or is a customer-managed cloud KMS sufficient?
