Elena — thanks for the clear notes and the logs. Sorry you're hitting this. We are seeing an anomalous regression in token pacing for a subset of streaming endpoints that started ~05:45 UTC and engineering is investigating.

Immediate mitigation options you can apply client-side (low risk, fast):
1) Disable streaming temporarily: call the same endpoint with streaming=false. This will return full responses and avoid waiting on incremental tokens.
2) If you must stream: reduce chunk size to 32–64 tokens and set a client-side grace timeout of 2s to show a spinner until the first token arrives. That reduces the perceived stall.
3) Implement a short client-side fallback: if streaming hasn't started within 3s, switch to a non-streaming call for that request.
4) Pin to the lower-latency model variant (rwd-small-v1) — we can enable routing for SkyApps if you want us to flip that on.
