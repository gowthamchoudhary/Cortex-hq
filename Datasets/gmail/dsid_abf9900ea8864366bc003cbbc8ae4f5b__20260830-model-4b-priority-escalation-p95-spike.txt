Quick update from runtime triage: 
- Reproduced elevated tail on a copied request mix against v2026-08-29 in us-west. Median unchanged, tail increased.
- Recent changes in the release: toggled fused-attention kernel for weights with mixed-quant (int8 path) and a new memory allocation fallback for KV cache that can trigger on heavy concurrency.
- Preliminary hypothesis: the fused kernel falls back to a slower path for certain sequence-length distributions the customer triggers; it increases per-token compute in the tail which manifests at P95.

Mitigation options:
A) Canary rollback of NovusRetail's traffic to v2026-08-27 (no model code changes) — low risk, restores prior behavior; ETA ~ 60-90m to canary + validation
B) Hotfix compile with forced non-fused attention on affected nodes — ETA 3-4h plus validation; risk: new binary rollout complexity

Recommend option A to meet SLA quickly. I will prepare the canary plan and target 10% traffic for 30m validation window, then scale to 100% if metrics hold. I will also capture perf traces to validate hypothesis.
