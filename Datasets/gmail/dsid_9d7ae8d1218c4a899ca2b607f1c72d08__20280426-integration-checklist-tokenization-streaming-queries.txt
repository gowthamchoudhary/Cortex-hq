Hi Samir — good questions. Long answer short: both patterns are supported; pick based on your scoring needs. Details below (copy/paste friendly).

1) Reranker invocation pattern
- Completions-style reranker (recommended when you want a single scalar score or short label): send a prompt that includes candidate text and ask for a score. Simple, slightly cheaper.
- Chat-style reranker (recommended when you want role-based context, multi-turn context, or function/tool-calling for structured annotations): uses messages array (system/user/assistant) and supports function calls. Slightly higher token overhead for message wrappers but gives structured output options.

Suggested: for top-50 rerank -> use completions for initial quick score pass (lower latency/cost), then run chat-based second-pass on top-10 if you need structured justification.

2) Tokenization & max_tokens
- max_tokens only limits generated output tokens. Input tokens still count toward request size and affect truncation. You must trim inputs to fit model context window.
- Best practice: build a sliding/truncation policy that keeps the most relevant context (query + candidate snippet) and enforce a token budget for inputs.
- Stop sequences: when streaming, stops are applied at the generation layer; partial streams are emitted until the model hits a stop token or EOF. If you rely on receiving fully-formed JSON, do not process partial streams until you see the full stop token; alternatively, use non-streaming for structured tool outputs.

3) Streaming + tool-calling
- If you enable streaming with function/tool-calling, Redwood will emit token chunks as generated. Function calls are signaled as a final structured call in the assistant role, but the JSON payload can be split across chunks. We recommend one of two patterns:  
  a) Non-streaming for tool calls (safer — you get one complete JSON in the response).  
  b) Streaming + reassembly on client — we provide chunk metadata (sequence id, is_final flag) to make reassembly deterministic. See attached request_response_schema_draft.json for chunk fields.

4) Embedding metadata
- We attach model_id and quantization_profile fields to embedding responses. We recommend persisting these alongside vectors so you can filter by embedding generation version during recall/rerank.

Implementation snippet (pseudo cURL)
- Completions score call: 
  curl -X POST https://api.redwood.ai/v1/completions \n    -H 'Authorization: Bearer <SK>' \n    -d '{"model":"rwd-encoder-1","input":"SCORE:\nCandidate: <text>\nQuery: <q>","max_tokens":5}'

- Chat tool (non-streaming final JSON): 
  POST /v1/chat with messages=[{role:system,content:...}, {role:user,content:...}] & "stream":false
