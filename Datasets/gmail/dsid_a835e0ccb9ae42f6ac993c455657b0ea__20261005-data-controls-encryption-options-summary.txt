Hi Alice — answering your questions inline and attaching a couple of artifacts for review.

1) BYOK/HSM support
- Hosted: supports BYOK via customer KMS integrations (AWS KMS, GCP CMEK, Azure Key Vault) using envelope encryption; keys remain controlled in your cloud account. Hosted does not currently host single-tenant HSM appliances.
- Dedicated: supports HSM-backed CMKs via cloud HSM (e.g., AWS CloudHSM clusters) that we can provision into a Dedicated environment; this meets FIPS 140-2/3 requirements.
- Private (on-prem / VPC): supports customer-provided HSMs (on-prem HSM or HSM in customer-managed cloud) and full isolation.

Notes: HSM-backed CMKs for cryptographic operations generally require Dedicated or Private. Envelope encryption with a customer KMS in your account is available in Hosted for most use cases.

2) Audit logging and retention
- We can stream structured, immutable audit logs to your AWS S3 bucket with per-tenant prefixes and lifecycle rules you control. Logs are written in JSONL with one event per line.
- Standard fields available: timestamp, request_id, account_id, model_name, route, input_token_count, output_token_count, response_latency_ms, truncated_prompt_flag (boolean), redaction_level. Full prompt text is redacted by default; we can support storing full prompts only with explicit controls and contractual alignment.
- Retention: we can retain logs for 365+ days via your S3 lifecycle/Glacier tier; Redwood can also mirror a copy for support but can be configured not to retain full prompts.

3) Residency and migration
- Migration plan: migrating from Hosted -> Dedicated/Private requires rekeying (if you switch to a new HSM) and a one-time export of logs. KV cache is ephemeral and would be rebuilt; we provide tools to warm caches and migrate model versions. We’ll include a proposed MOP (mutual action plan) that lists downtime windows, data export steps, and smoke tests.

4) Artifacts and sample schema
- Attached: redwood-kms-hsm-matrix.xlsx (matrix of options and tradeoffs) and audit-logging-sample.jsonl (sample events).
- Regarding token-level traces: default behavior redacts sensitive tokens; we can enable full-token replay with customer authorization, but that typically requires Dedicated/Private and contract-level constraints.
