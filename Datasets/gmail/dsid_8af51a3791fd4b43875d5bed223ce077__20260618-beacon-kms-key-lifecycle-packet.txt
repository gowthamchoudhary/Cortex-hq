Hi Lena,

Below is a concise technical summary and the artifacts we're attaching. I'll keep it high level with pointers to the attached redacted logs/snippets.

1) Key storage and HSM backing
- Hosted (Redwood API): Data-encryption keys are encrypted with a Root CMK stored in AWS KMS. For the hosted control plane the CMK is managed by Redwood but is AWS KMS-managed (not exportable).
- Dedicated/Private: We offer CloudHSM-backed CMKs (customer or Redwood-owned clusters depending on contract). CloudHSM clusters we use are FIPS 140-2 validated appliances and are configured with role-based access controls; HSM configuration snippet attached.

2) Envelope encryption architecture
- We use envelope encryption: service-level data keys (DEKs) are generated per-tenant/session and encrypted with a Customer Master Key (CMK). DEKs are AES-256-GCM. The CMK performs Encrypt/Decrypt and GenerateDataKey API calls only in KMS.

3) Rotation policy
- Default: CMKs rotate on a 365-day cadence by policy unless customer selects a more frequent cadence.
- DEKs: short-lived (default TTL 30 days for cached keys; rotated on re-issue) depending on workload.
- Rotation workflow: automated rotation is handled by the KMS policy + orchestration service; rotation events are logged and we keep a rotation provenance record (see rotation_log_2026Q2.csv).

4) Key destruction/decommissioning
- CMK retirement: We mark keys retired in KMS and retain encrypted snapshots for safe rollback for a configurable quarantine period (default 30 days) before scheduled scheduled deletion; permanent deletion requires a documented approved request and is logged. For Private deployments, customers retain control of root HSM key material.

5) In-transit protections
- All RPCs and client-server communication use TLS 1.2+ with strong cipher suites; internal service-to-service traffic defaults to mTLS with mutual authentication using short-lived mTLS certs. For hosted traffic we terminate TLS at load balancers which are hardened and audited regularly.

6) Auditability and non-exportability
- KMS API calls (Encrypt, Decrypt, GenerateDataKey, ReEncrypt, CreateKey, ScheduleKeyDeletion) are logged to CloudTrail with request IDs and timestamps. We can provide redacted CloudTrail entries (attached) showing a sample Encrypt/GenerateDataKey/Rotate sequence.
- For hosted keys we do not export plaintext CMKs. For Dedicated/Private, customers with BYOK can bring keys and maintain export controls.
