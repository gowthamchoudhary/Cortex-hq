Thanks — quick technical note from the runtime side:

- KMS envelope support: when the customer supplies their own key namespace (HSM-backed), each model artifact signature and KV cache snapshot is encrypted under the customer key. That adds ~1–2s to cold-starts for large KV snapshots if we rehydrate from cold storage, but steady-state inference is unaffected. We account for that in the SLA for cache warming windows.

- Audit streaming: we provide a separate durable stream to a customer-owned project (or our managed bucket) that records per-request headers, token counts, and a hashed output for verification. Retention cost scales primarily with token volume and index granularity (we include a row-level cost in the spreadsheet).

- Throughput guarantees: the 250 concurrent tokens/s guarantee assumes a 512-token average context distribution. If your tails are heavier (2–4x longer), we'll need to provision more kernels and GPUs; that changes the pool sizing. Lab recommendation: run a 48-hour production-like trace to validate tail behavior.

I'll flag the operational knobs in the spreadsheet and add a small section about recommended guardrails (circuit-breaker thresholds, fallback model variants for graceful degradation).
