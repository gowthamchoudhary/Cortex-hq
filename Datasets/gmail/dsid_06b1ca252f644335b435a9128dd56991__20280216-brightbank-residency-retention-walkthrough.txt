Samir — thanks for the concise list. Answering at a high level here; I can produce an official statement and a one-page matrix for your procurement/legal team and attach it to the SOW. See the short summary below and attached CSV for a table view.

1) Default capture windows (hosted Redwood API):
   - Raw request text (prompts): retained for up to 30 days by default for operational troubleshooting and abuse detection; customers may opt out at account level for new keys.
   - Model responses (final outputs): retained for up to 90 days when used for product telemetry and quality monitoring; transient streaming tokens are not persisted beyond the session unless explicitly stored by the customer.
   - Derivative artifacts (e.g., eval logs, embeddings computed by Redwood for internal routing/benchmarking): retained up to 180 days by default; we isolate and minimize storage for embeddings unless the customer requests indexing services.

2) EU residency:
   - By default, data is routed to the region closest to the request origin. For EU customers with residency requirements we provide an EU-hosted tenancy option (EU residency) that pins both control plane metadata and retained artifacts to EU data stores — this is an opt-in configuration during onboarding or via an account migration.
   - For Hosted EU tenancy we offer a contractual residency guarantee (data remains within EU regions) and can include that as a contractual term for BrightBank.

3) Deletion / Erasure workflow and SLAs:
   - Self-service: Console and admin API allow erasure requests by resource id (documents, sessions, API key scope). Typical automated erasure completes within 48–72 hours for hosted accounts.
   - Manual/supported: For account-wide historical erasure or cross-region migrations we operate via a support runbook and provide a confirmation report; SLA for supported erasure is 7 business days for standard contracts, expedited options available under enterprise agreements.
   - Evidence: after completion we provide an audit log excerpt (timestamped job id, affected object ids).

Notes/exceptions:
   - Dedicated and Private deployments: retention and erasure behavior can be set by customer configuration or contract; Private on-prem installs have deletion paths performed by the customer unless Redwood is contracted to run the control-plane operations.
   - Backups & tombstones: backups are retained for disaster recovery; deletion operations remove primary records and mark tombstones for eventual purge according to the backup retention schedule — we include backup purge timelines in the contract appendix when required.
