This works.

Proposed initial page criteria (conservative, rollout-week only):

A) Time-to-ready regression (customer-impact proxy)
- Page if Provision→Ready P95 > 120 min for 30m (us-east, A100 pools only) AND new nodes added in that window >= 5
- Ticket if P95 > 90 min for 60m (same filters)

B) Success rate / gating failures (system health)
- Page if “node ready success rate” < 90% over 30m AND attempts >= 20
- Ticket if < 95% over 60m

C) Quarantine spike (capacity risk)
- Page if quarantined / provision attempts > 10% over 30m OR quarantined nodes count increases by >= 10 in 30m

D) Stuck state (pipeline wedge)
- Page if nodes in “Provisioning” or “Validating” > 50 for > 20m (again, us-east/A100 only)

Noise guardrails:
- No paging on per-node GPU health failures (Xid/ECC) unless it crosses the success/quarantine thresholds above
- First 6 hours of rollout: paging enabled only for (C) and (D). We can turn on (A)/(B) once we see baseline.

Incident flow:
- SRE oncall is IC; first action is to confirm if this is image channel vs infra vs control plane
- Infra oncall engages immediately if (C)/(D) triggered
- If we think it’s new behavior: disable rollout flag for us-east/A100 and stop admitting nodes to serving pools (readiness gate should already prevent this, but the flag is the kill switch)

Irene — FYI, this is the rollout-week page policy; we can tighten after we have a clean week of data.

If you’re good with these numbers, I’ll ask Aisha/Sergio to tune alerts accordingly in the observability pack.
