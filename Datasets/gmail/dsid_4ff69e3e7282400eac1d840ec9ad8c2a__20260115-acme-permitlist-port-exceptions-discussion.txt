Sean / David — drafting the recommended permitlist below. I've attached a worksheet with per-port justification and expected failover behaviour. Key points:

1) Control plane / API traffic (required)
   - Destinations: api.redwood.prod (FQDN) and an associated short IP set we publish (currently 3 addresses per region).
   - Ports: 443/tcp only.
   - Auth: TLS with client certs (mTLS optional for your higher security lanes).

2) Model artifact pulls (required occasionally, larger egress)
   - Destinations: artifacts.redwood.prod (FQDN). We recommend allowing 443/tcp and rate-limiting at your edge.

3) Health/telemetry probes (optional, but improves reliability)
   - Destinations: telemetry.redwood-ops.prod (single FQDN).
   - Ports: prefer 443; legacy runtime probe uses 8050/tcp for in-cluster debug only.
   - Recommendation: do NOT open 8000–8100 wide. If you must, allow a single port 8050/tcp targeted at telemetry.redwood-ops.prod and require mTLS. We can also encapsulate probe traffic over 443 to avoid new ports.

4) DNS/TLS name resolution
   - Allow outbound DNS (UDP 53) from the connector to your resolver (or use a forwarder) — we do not require direct DNS to internet.

5) NAT/source IPs
   - Best practice: static egress IPs for the connector. We can publish an IP set that your firewall can reference. If static IPs are not possible, we support a short-lived public key verify flow (SNI + cert pinning) as an alternative.
