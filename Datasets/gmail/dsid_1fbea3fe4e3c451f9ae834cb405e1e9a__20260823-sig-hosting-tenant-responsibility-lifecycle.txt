Summary (high level):
- Hosted (Redwood API): Redwood manages runtime, key material is Redwood-managed by default; customers may request BYOK for dedicated customers under an enterprise agreement. Network is multi-tenant control plane; customer data is logically isolated at the model-serving layer. Evidence: SOC 2 Type II report (attached link), runtime configuration screenshots, KMS integration guide.
- Dedicated (Reserved capacity): Reserved GPU pools for a single customer. Network peering (VPC) and customer-managed DNS are supported. Customers may provision keys into their KMS and we support KMS passthrough for model encryption. Evidence: VPC topology diagram (attached), contract excerpt describing reserved capacity, runbook excerpt for key rotation.
- Private (VPC / On-prem): Customer controls network and key stores; Redwood provides the control plane only when requested and we ship logs into customer-controlled storage. Evidence: deployment checklist, on-prem installation guide, sample audit log export.
