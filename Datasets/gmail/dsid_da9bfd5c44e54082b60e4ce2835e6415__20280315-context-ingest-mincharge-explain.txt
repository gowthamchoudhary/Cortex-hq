Grace / Vanessa / Marta — providing the worked examples below and confirming pilot discount approach. Attaching the spreadsheet with per-call scenarios.

Summary of rules that apply to this workload:
- Long-context concat: Metering treats the request as a single call with token count equal to the model input length (post-tokenization). We do not artificially split a single API request for billing; if you submit an 80k-character payload in one call, that is billed as the tokens produced/consumed for that single call.
- Service-side batching: Batching is an implementation optimization on our runtime. Billing is customer-visible at the logical request level (i.e., you are billed per original API call, not per GPU batch). If we return a single response to a single request, that's the billed unit.
- Minimum-charge & rounding: We apply a configurable per-call minimum of 1 token equivalent for chat/generation calls, and per-embedding minimum of 4 tokens when applicable. Rounding occurs at the per-call level to whole tokens (no fractional billing). Example: 1.2 tokens => billed as 2 tokens unless covered by a session minimum or a pilot credit.

Worked examples (see attached sheet 'context-billing-examples.xlsx'):
1) High-length single request
   - Raw tokenized input: 12,300 tokens
   - Generation output: 1,200 tokens
   - Billed = 13,500 tokens for that API call

2) Small-message high-volume (stateless calls)
   - Avg tokens/request (input + output): 1.2 tokens
   - Per-call minimum: 1 token floor (we will round up to 2 tokens if >1 and <2)
   - 2M calls/day * 2 billed tokens = 4M billed tokens/day

Note: For workloads that are a mix of multi-turn sessions and stateless hits, we recommend using session-based aggregation (conversation_id or session token) to enable KV reuse and reduced billed tokens across calls. Session aggregation can be enabled on the Dedicated plan or via a config flag on Hosted for pilot customers.

Pilot discount proposal:
- 12% pilot discount on per-token price for the first 90 days for RDW-ACME-2028-04, capped at 150M billed tokens.
- Waive per-call minimum for the first 30 days for validation traffic (to avoid one-off rounding distortions).

Marta — short answers and commitments so procurement/legal can proceed:
- KV/prefix reuse: If you break a long document across multiple API calls within the same session id (conversation_id header), our runtime will reuse cached KV state where applicable. For billing, we meter each call's tokenized input; however, because subsequent calls can send delta-only content or rely on cached prefixes, the billed input tokens will typically be much lower after the initial call. We included one example in the attached spreadsheet showing a 70% reduction in billed tokens after warm-up for long-document ingestion with prefix reuse.
- Waived minimum: The 30-day waiver will be applied automatically when the deal is closed and the HubSpot deal id RDW-ACME-2028-04 is supplied to our operations team. We'll include the waiver clause in the SOW addendum.
- Price lock for pilot: We can guarantee no per-token base price increases during the 90-day pilot period in the SOW addendum. Post-pilot pricing adjustments will follow the standard notice period (60 days) but won't affect the pilot period.
