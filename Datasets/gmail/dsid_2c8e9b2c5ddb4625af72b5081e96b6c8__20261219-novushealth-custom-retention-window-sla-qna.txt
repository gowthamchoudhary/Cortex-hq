Chloe / Amaya — quick technical note (quoting Chloe below):

> - Retention cadence: we can implement the 14-day active KV cache + 90-day cold retention and follow with a secure deletion workflow that targets completion within 7 calendar days after day 90.

Operational detail we should capture in the SLA appendix:
- Deletion method: we perform a two-stage wipe for encrypted blobs: (1) crypto-key destroy (KMS key revoke) timestamped, (2) metadata purge and object overwrite schedule for any replicated artifacts. Crypto-key destroy is immediate; object-level tombstone/overwrite may be scheduled within a maintenance window but will be completed within 7 calendar days. The deletion certificate will include KMS key ID, destroy timestamp, object ID list, and the job run id.
- Audit logs: we will expose a signed, time-stamped audit stream containing deletion job events (job_id, status, start_ts, end_ts, operator_id). We can provide this as a daily export for the 90->97 window and a single consolidated certificate after completion.
- For residency: if Novus requires strict AZ-local storage (no cross-AZ replication), we need explicit confirmation; by default our HA config uses cross-AZ replication inside us-east-1. Cross-AZ is more resilient but keeps the data in-region.
- Edge-case: if a dataset is exported for debugging (redaction/forensic copy), we need to capture that as an exception and track re-ingestion controls.
