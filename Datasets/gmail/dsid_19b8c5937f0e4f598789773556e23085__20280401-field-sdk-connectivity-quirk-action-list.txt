Thanks for the flag, Markus — I had a quick look at the log and pcap. Initial thoughts:

- The pcap shows a TCP FIN from the server side shortly after the last data chunk; it looks like the serving process closed the socket rather than the client timing out. That could be an application-level close triggered by a timeout or an internal health check.
- There was a small bump in CPU on the serving host in that window in our infra metrics; if the runtime preempts a worker to pick a new kernel/quant path there could be a short pause.

Immediate asks to reproduce:
1) Can FinMetric run a short script that streams a 3k token response in a tight loop against our hosted endpoint and paste full SDK debug logs (set REDWOOD_SDK_LOG=debug)?

Temporary mitigation we can recommend to the customer:
- Set REDWOOD_SDK_KEEPALIVE_MS=30000 (increase client keepalive)
