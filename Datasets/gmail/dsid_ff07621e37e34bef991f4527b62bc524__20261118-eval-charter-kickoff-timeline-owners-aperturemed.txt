Thanks again for taking the time today — it was helpful to see the triage workflow and the set of sample cases your team wants to accelerate. Per our discussion, I captured a compact evaluation charter and a proposed 4-week timeline that focuses on three measurable acceptance gates. The draft is attached (evaluation-charter-draft.pdf) and I also pasted the key points below for quick review.

High-level objective:
- Validate Redwood Inference can reduce end-to-end triage response time and maintain extraction accuracy on ApertureMed clinical notes while keeping cost below defined thresholds.

Proposed acceptance gates (pass/fail):
1) Accuracy slice: F1 >= 0.86 on the masked entity set (clinical_condition, dosage, patient_age) over 1k labeled examples.
2) Latency: 95th percentile < 280 ms per token with 8 concurrent users and peak simulation workload.
3) Cost: projected steady-state token cost <= $0.45 per 1k tokens for the observed token distribution.

Scope & deliverables:
- Test dataset: 2k de-identified clinical notes (we'll use the manifest in sample-dataset-manifest.csv).
- Models: start with redwood/gptx-2-8b (quantized) + fallback to redwood/gptx-2-16b for long-context cases.
- Instrumentation: per-route latency, token counts, and a small eval harness for the three slices.
- Owners: ApertureMed: Laura (clinical labeling), Samir (infra access). Redwood: Rachel (technical lead), Marissa (eval harness), Ben (SRE & environment).

Timeline (proposed):
- Week 0 (this week): NDA / minimal DPA confirmation, S3 access & sample manifest exchanged.
- Week 1: Redwood deploys sandbox, run initial ingest & smoke tests.
- Week 2: Run slice evaluation and iterate on prompt/template.
- Week 3: Final run and acceptance gate measurement; cost projection.
- Week 4: Readout + next steps (production plan / Dedicated allocation).
