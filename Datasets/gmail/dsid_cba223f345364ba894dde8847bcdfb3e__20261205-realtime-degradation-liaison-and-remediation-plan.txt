Team —

Thank you again for joining yesterday’s bridge. This is a consolidated follow-up with our preliminary findings and next steps.

Summary of mitigation and impact:
- Mitigation taken: temporary routing to tmp-opt-1.0 reduced observed 5xxs from ~8% to <1.5% within 20 minutes. Continuous batching and reduced batch-size stopped the cache pressure pattern we observed.
- Impact window: 08:40–09:10 PST on 2026-12-05. Streamline.ai saw ~9% of requests affected during the peak window; duration for any single user request was typically <2 minutes (retries included).

Preliminary root cause (draft):
- A combination of increased tail token lengths from a recent customer workload spike and a kernel memory fragmentation issue in one of the optimized attention kernels led to repeated cache invalidations on a model shard. The resulting memory pressure triggered intermittent failures on that shard and increased scheduling churn in the GPU pool.

Next steps / remediation plan:
1) Engineering action: apply a patch to the runtime kernel to address fragmentation (target: staged rollout in 48–72 hours).
2) Platform action: enhance model-variant fallback rules to proactively route heavy-tail-sequence traffic to our conservative execution path.
3) Customer options: we can apply temporary pins or provide the routing guidance in temporary-routing-steps.txt if you want direct control.
