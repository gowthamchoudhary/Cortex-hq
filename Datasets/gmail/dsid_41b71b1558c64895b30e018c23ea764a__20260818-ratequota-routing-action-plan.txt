Thanks Lydia — answers inline and a short plan for the deep-dive so Diego can prep.

1) KV cache isolation: Redwood supports tenant-aware KV namespaces. Operationally we either:
   - Create per-tenant KV namespaces that are isolated in memory/CUDA cache (preferred for enterprise customers), or
   - Use a priority-based eviction policy where platinum customers' keys are pinned and trial tenants are fair-share evicted.
We recommend per-tenant namespaces for the two enterprise tenants in the PoC to avoid any cross-tenant evictions. We'll walk through memory footprint and allocation in the tech call.

2) Routing rules example: Redwood routing policies are declarative — policies are stored as JSON/YAML and evaluated at request ingress. Example rule: \"if headers.x-customer-tier == \"platinum\" then route:model-zenith-v2; else if quota_state == \"exceeded\" then route:model-quantized-mini\". No code changes required; policies are pushed via the control plane and can be versioned and rolled back. Diego will show a live demo.
