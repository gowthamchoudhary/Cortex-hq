Ben / Sara — I pulled together a first-pass packet and attached the three artifacts: the diagram PNG, a segmentation matrix spreadsheet, and a control-plane narrative draft (PDF). Key points in the narrative (short):

- Deployment modes: Hosted / Dedicated / Private. This packet focuses on Dedicated (customer-dedicated GPU pools with VLAN tenancy) and Private (VPC/VPN or on-prem airgapped variant).
- Control plane: runs in Redwood’s control region; Private deployments can be configured with a customer-controlled control plane connector. Authentication and orchestration traffic is TLS 1.3 with mTLS for node registration.
- Data plane isolation: model workloads and KV cache are pinned to tenant GPU pools. Network-level isolation uses VLAN segmentation plus SG rules at the host level; egress is forced through NAT gateways or a customer-managed egress appliance for Private.
- KMS and secrets: customer keys can be provided via external KMS (via KMS proxy) or Redwood-managed KMS with strict tenant access controls. Keys are never persisted in plaintext on compute nodes.
- KV cache handling: ephemeral caches are scissored per-tenant; cache eviction and rotation are logged; we include a small appendix on cache lease semantics (Rishi, see inline TODOs).
