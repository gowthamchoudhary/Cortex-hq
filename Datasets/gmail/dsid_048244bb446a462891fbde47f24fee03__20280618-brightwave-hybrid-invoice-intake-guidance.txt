Hi Liam — great to hear from you. Short answers up front: portal preferred; email allowed as a fallback with stricter filename/subject rules. Details below and next steps at the bottom.

Portal (preferred):
- Upload via our vendor portal: https://redwood.company/vendor-portal — ensures timely ACK/PO matching and faster payment.
- Accepted formats: PDF preferred for invoices; CSV/XLX allowed for batch line-item uploads. Max file size: 15 MB.

Email fallback (allowed):
- Send to accounts@redwood.com and include the PO token in the subject line: PO{PO_NUMBER}:INV (e.g., PO123456:INV). This token helps our intake service route and stamp automatically.
- Attachments: single PDF preferred; if multiple files, zip them. Please avoid password-protected attachments.

Required fields (minimum):
- Redwood PO number (exact match)
- Invoice number
- Invoice date
- Supplier tax ID (VAT/GST/Tax ID)
- Line-level descriptions and net amounts; currency code

Automation / PO stamping:
- We support automated PO-stamping if the PO token is present in the subject or filename; our intake engine will use the token to route the invoice to the correct ledger.
- If you cannot add the PO token, your account manager can configure a custom subject token policy for your portal uploads during onboarding.

Technical options:
- SFTP: inbound drop available (sftp://sftp.redwood.com/inbound/brightwave) for daily batch files (CSV per mapping).
- EDI: supported but requires an EDI spec sign-off; attach your EDI/EDI-AS2 sample if you plan to use it.

Action items / next steps:
1) Please complete the vendor onboarding form: https://redwood.company/forms/vendor-onboarding?ver=2 (I attached the PDF copy for reference).
2) If you're planning batch uploads or EDI, reply with a sample and ETA; we’ll loop in our integration engineer (Markus) to review mapping.
3) If you prefer email fallback only, confirm and we'll provide the subject-token template to your AP mailbox.

Hi Liam — looping in with a few clarifications from the integration side:

- Line-item description length: portal UI truncates at 512 characters but the backend ledger supports up to 2000 chars for SFTP/CSV ingests. If you have longer free-text notes, put them in an attached CSV column; PDF invoices can carry arbitrary length in the visual description.
- Tax ID: header-level tax ID is sufficient for matching; we don't require per-line tax IDs unless your country requires line-level VAT treatments (let us know the jurisdiction).
- EDI mapping SLA: typical turnaround for a standard 810 payload is 5 business days for a validation pass and 10–12 business days for full mapping + QA if you provide samples and test files. We can accelerate for committed go-lives.

Implementation notes:
- Subject token format: PO{digits}:INV — recommended for email fallback. We also support filename tokens like invoice_PO{digits}.pdf.
- For automated stamping, include the PO in both the filename and the subject to avoid edge cases from forwarded emails.
