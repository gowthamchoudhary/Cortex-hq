Hi Julia / team,

Following up with the artifacts we discussed. Attached are two files: a one-page deletion playbook and a diagram that shows how we partition session data and where identifiable payloads are removed. Summary below for the SIG/CAT intake:

- Default behavior: identifiable session fragments are automatically tombstoned at T+30d. Tombstoning removes direct identifiers but keeps a minimal index (non-reversible shard id + timestamp) for debugging for up to 90 days. Full payloads are truncated on tombstone and cannot be reconstructed.

- Proof of delete: we can emit a signed deletion marker (SHA256 over shard-id + timestamp + tenant-id) and log the marker to an append-only audit stream. The signed marker and the audit-stream offset constitute verifiable evidence that a delete action executed. Markers are retained in the audit stream 1 year by default for compliance requests.

- For scoped extensions: we require an authorized change order, a short justification (forensic case id), and a retention addendum. Once approved, we schedule retention extension and provide a scoped evidence bundle (signed markers + storage bitsheet + timeline).

Attachments: partitioning-architecture-diagram.pdf, deletion-playbook-draft.docx
