Hi all — providing the technical summary for the SIG answers below. Attaching a runbook extract (runbook-draft-v2.pdf) with the procedural steps and playbook excerpts. Attachment stub included.

Summary (short answers for SIG):
- RTO / RPO by workload tier:
  - Hosted API (public): RTO = 15 minutes (regional degraded), 99.95% availability SLA; RPO = 1 minute for request metadata, 15 minutes for non-critical logs.
  - Dedicated (reserved capacity): RTO = 5 minutes (automated failover within same tier to warm pool), 99.99% SLA for committed capacity; RPO = <1 minute for customer-critical metadata when KV persistence enabled.
- Backups and replication:
  - Model artifacts and customer metadata: hourly snapshots for critical datasets, daily full snapshot for model artifacts.
  - Snapshots are encrypted at rest with customer-key or Redwood KMS; multi-region replication enabled (us-west-2 <-> us-east-1) for critical datasets using cross-region replication of object storage manifests.
  - Retention: 30 days for hourly snapshots, 365 days for daily full snapshots (configurable under Dedicated/Private contracts).
- Automated regional failover workflow (high level):
  1) Health signals detected via multi-probe monitoring (latency + error rate + control-plane heartbeats).
  2) Automated routing policy triggers failover to paired region after threshold (default 90s sustained error rate above baseline).
  3) KV-cache warmup and prefix caching replay to minimize cold-start impact; DNS and load balancer failover handled by managed route53 + internal proxy layer.
  4) Manual operator verification and rollback steps in runbook if data divergence is detected.
