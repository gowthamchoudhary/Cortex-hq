Node sizing (initial recommended profiles):
- control‑plane.medium: 3x m64‑large equivalent (8 vCPU, 32GB RAM, 1Gbps mgmt NIC) — no GPUs, high‑io for etcd (use local SSD for etcd if possible).
- inference.gpu.large: 3x nodes, each with 8 vCPU, 256GB RAM, 2x A100 (80GB) or single 4x A100 depending on your server SKUs. Use hugepages disabled for model serving; tune per‑model.
- cache.local.highio: 3x nodes, 16 vCPU, 64GB RAM, local NVMe 3.2TB, recommended for KV cache (LSM workloads).
- batch.cpu.small: 4x nodes, 12 vCPU, 48GB RAM, no GPU (for conversions, offline evals).

Kube flags / policies:
- kubelet eviction thresholds: memory.available < 8% and imagefs.available < 10% to trigger eviction on GPU nodes.
- pod disruption budgets: set for inference deployments (minAvailable: 2) to keep serving SLO.
- scheduler: use nodeAffinity + taints (taint: gpu=true:NoSchedule for inference). Use topologySpreadConstraints to distribute pods across racks.
- runtime: containerd (1.8+), cgroup v2 if your OS/kernel stack supports it; restrict swap to 0.

Networking specifics:
- Validate eBPF datapath compatibility across all ToR switches; if not available, configure Calico IPIP with BGP peering to your edge router.
- Recommend dedicating a 10G interface for GPU traffic; enable jumbo frames end‑to‑end.

Storage and data retention notes (NetApp + local NVMe):

1) Architecture pattern (three tiers):
   - Tier 0: Local NVMe on inference/caches — used for ephemeral KV caches and model runtime scratch. Use local PVs (PersistentVolume with local volume CSI) and enforce ReclaimPolicy=Delete. Short retention (< 24h).
   - Tier 1: NetApp NFS exports for model artifacts, logs, and shared RWX volumes — use NetApp Trident/CSI driver v21+ with Kerberos mount if your security policy requires. Ensure NFS mount options include noexec,nodev where appropriate and set fsync semantics per workload.
   - Tier 2: Backup object store (S3 compatible) for daily snapshots and long‑term retention (365d). If no external S3 allowed, run MinIO behind your bastion in the same VLAN and schedule replication to tape/backup appliances as per your policy.

2) CSI & performance:
   - Use NetApp CSI driver with async snapshot support; set storageClass parameters for dedupe/compression where ONTAP supports it.
   - For high‑IO workloads, avoid NFS for hot writes; prefer local NVMe or a dual‑write pattern (write to NVMe then async copy to NetApp).

3) Snapshots & retention:
   - Models/artifacts: hourly snapshot (rolling 24h), daily snapshot (30 days) and weekly archived snapshot (365 days).
   - Logs/metrics: retain node /audit logs 365 days; rotate compressed per week.

4) Security notes:
   - Kerberos + CIFS/NFS for privileged mounts; mount over dedicated management network.
   - Limit NFS exports to k8s master and infra nodes via ACLs.
