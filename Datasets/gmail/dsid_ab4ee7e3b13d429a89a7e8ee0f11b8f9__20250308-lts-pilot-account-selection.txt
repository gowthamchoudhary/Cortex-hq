Minimum pilot support intake checklist (for CSMs/TAMs) — suggest we enforce this before we page runtime/release:

1) Environment + packaging
- Hosted / Dedicated / Private
- Current runtime version + target LTS version
- Model(s) + typical prompt/response size range

2) Impact + severity
- Business impact (prod down / degraded / planned upgrade)
- Timeline/urgency + whether they’re blocked on change-control

3) Repro + diagnostics
- Request IDs / timestamps / region
- Logs (runtime + scheduler if available)
- Any recent config changes (batching/caching overrides)

4) Backport request specifics
- Link to upstream fix/PR if known
- Confirmation that they can test an RC within 48 hours if we provide one

Process proposal:
- One Jira SUP ticket per pilot account (keeps comms + timeline in one place)
- We add Connor + me as watchers; CS owns customer comms
