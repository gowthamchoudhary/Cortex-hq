Thanks for the sample, Maya — useful distribution. Short answers first, then a short baseline table.

1) Unit accounting model:
- For hosted API rerank/classifier endpoints we bill on a per-scored-candidate basis. That means if you run a classifier over 400 candidates, you incur 400 scoring units for that model. If you then run three separate reranker variants on 40 candidates, that's 40 * 3 additional scoring units.
- If you fuse models on the server-side (i.e., single request that returns multiple scores in one forward), billing is per model forward executed; a fused multi-head model counts per forward.

2) Batching & caching effects:
- Continuous batching reduces per-token computation but does not collapse per-candidate unit counts; you still pay per candidate, but batching reduces latency and can reduce cost indirectly by enabling smaller instance footprints.
- Prefix/KV caching helps when candidates share long prefixes (e.g., shared document context). In that case the incremental cost for additional candidates after cache hits is significantly lower; we reflect this in the performance profile and can build a custom quote if your data shows high prefix reuse.

3) Baseline rate card (hosted API, list pricing example):
- Classifier (per candidate, standard model): $0.00045 per scored candidate
- Reranker variant (per candidate, small-medium model): $0.00120 per scored candidate
- Ensemble discount: when multiple variants are run on the same candidate in a single request path, we can offer a stack discount; see tiers below.

Illustrative math from your sample (avg per-query):
- 400 classifier evals => 400 * $0.00045 = $0.18 per query
- 40 candidates * 3 reranker variants => 120 * $0.00120 = $0.144 per query
- Total per-query cost (list): $0.324

Volume tiers (committed monthly):
- Pilot: 100K scored-candidates/month => 12% discount on list rates
- Growth: 1M scored-candidates/month => 22% discount
- Enterprise: 5M+ scored-candidates/month => 33% discount + dedicated support

I attached a short PDF with the sample tiered rate card and assumptions (scoring_ratecard_v1.pdf). For Searchly specifically, if your prefix reuse is high the effective per-candidate cost could drop by ~10–25% compared to the table above.

Let us know your concurrency and p95 target and we’ll model expected monthly spend across the tiers.
