Thanks — great questions. High-level answers below; I’ll follow up with a downloadable matrix and a short playbook. If you need language for the listing we can provide bullet points.

Short answers (summary):
- Region-local storage: yes — marketplace artifacts are pinned to the region selected at listing time (we support AWS us-east-1, GCP us-central1, Azure eastus for your region). Models and generated artifacts created in the listing are stored in region-local buckets managed by Redwood Private nodes in that cloud region.
- Evacuation / deletion: customer-initiated evacuation is supported. Steps: request -> confirmation -> snapshot & verification -> deletion across primary + DR replicas -> signed deletion receipt. Target SLA for full deletion of customer artifacts is 14 business days; emergency deletions (legal/regulatory hold exceptions permitting) are expedited to 72 hours with additional attestations.
- Cross-cloud replication: we do not replicate marketplace customer artifacts across clouds by default. Backups/replication occur within region / availability zone unless customer has enabled multi-region backup. Any cross-region or cross-cloud replication must be declared during onboarding and will appear on the matrix (and may impact deletion timelines).

Ben — adding a few technical clarifications for the matrix before you send external: 

- For AWS: primary artifacts are in S3 with object lifecycle rules. We keep snapshots for 30 days by default (hot cache TTL), but long-term retention depends on customer profile. Deletion flow: delete S3 objects, invalidate caches (FrontDoor), clear KV caches on inference nodes, then remove metadata from our config DB. Deletion events generate an audit file per tenant (signed).
- For GCP: similar flow — GCS + regional snapshots. Note that GCP nearline/archival settings are separate and could keep copies outside normal retention windows if the partner requests archival. That would require an explicit opt-in and contractual note.
- For Azure: blob storage + soft delete policy — soft delete window defaults to 7 days; we recommend setting soft delete to 0 for marketplace-managed tenants that require fast evacuation, but that needs platform ops approval.

I’d also recommend we add a row in the matrix called 'Emergency legal expedite' that indicates the 72-hour escalation path and the required paperwork (signed DPA amendment + legal request).
