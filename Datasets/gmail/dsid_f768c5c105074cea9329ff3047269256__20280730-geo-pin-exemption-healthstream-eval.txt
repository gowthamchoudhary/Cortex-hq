Sean / team —

Short answer: doable, but with operational and capacity tradeoffs. Notes below: 

1) Geo pinning: we can implement a strict routing policy that requires requests for HealthStream to only be routed to the redwood-model-v2-us variant and to servers in a US region (we'd use us-west-2 by default). This is a routing config change + RBAC (customer account flag).

2) No-fallback requirement: marking this as "no automated fallback" is risky. Typical fallback behavior (to keep apps alive during capacity pressure) is the main tool we have for graceful degradation. Two options: 
   - Strict no-fallback (what the customer asked): we can enforce it, but we must reserve capacity for the pilot (dedicated pool / committed instances) and add a capacity-surge SLA. If demand exceeds reservation, requests will be throttled (HTTP 429) rather than routed to other variants. We should document outage behavior clearly.
   - Controlled fallback with cryptographic boundary: allow fallback only to a variant that meets attestations (same model weights, same KMS) and only within US regions; this reduces outage risk but may not satisfy their auditors.

3) Auditing / logs: we can emit model-selection headers and per-request region metadata to their logs. We'll need to maintain longer retention for this customer during the pilot (30 days as requested). We should capture perms for Audit: who can view those logs inside Redwood.

4) KMS/HSM: Key boundary is feasible if we use their customer-managed keys or a dedicated Redwood key umbrella. Need legal sign-off on key access windows.

5) Implementation effort & timeline:
   - Routing + model pin: ~3 engineer-days (config + e2e test).
   - Dedicated pool & reservation plan: ops + infra work, ~1-2 weeks to provision and smoke test.
   - Extra logging & retention tweaks: 2-3 engineer-days.

I attached a draft runbook for the no-fallback behavior (fallback_runbook_draft.md) with failure modes and recommended alerting.

Risks: throttles under peak will look like errors to the app; we need to make sure HealthStream is OK with 429s during spikes.

Happy to discuss at 3pm.
