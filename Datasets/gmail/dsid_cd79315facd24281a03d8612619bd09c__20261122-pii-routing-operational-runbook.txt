Hi Alyssa — thanks for the clear list. Attaching our operational runbook and the KMS custody matrix as requested. High-level summary below; detailed flows are in pii-routing-runbook-v1.pdf (attached).

Summary (TL;DR):
- Ingest boundary: traffic first reaches the inference gateway (HTTPS TLS). Raw payloads are accepted only via authenticated customer API keys; metadata is separated at the edge.
- Tokenization/pseudonymization: prefix KV caching and tokenization occurs in the preprocessing layer inside the customer tenant boundary. For Hosted customers we offer tokenization as a managed step; for Private customers tokenization runs in-customer VPC under customer keys.
- KMS custody: we support three models — Redwood-managed keys (default), Customer-managed keys (Redwood KMS proxy), and HSM-backed BYOK for Private deployments. Key rotation schedule: 90 days for symmetric keys; asymmetric signing keys rotated annually. See kms-custody-matrix.xlsx.
- Emergency egress: triggered by either (a) customer-initiated export request via the Console + signed SOW amendment, or (b) incident response where data must be moved for forensic analysis. Manual approvals required: Security Manager (Redwood) + named customer approver. Export is staged to a time-limited S3 presigned location with audit events and retention tags.
- Access controls & evidence: RBAC enforced via LDAP/SCIM for our console; privileged access is recorded in immutable audit logs retained per contract. For HealthCo, we recommend a least-privilege role (DataOps) with just-in-time elevation for exports.

Hi Alyssa / Vanessa — quick clarifications from CS/ops perspective (pasted here so Procurement sees before the DPA is locked down):

- Retention: By default inference telemetry (non-PII) is retained for 30 days; PII-containing artifacts follow contract-specific retention rules. We can add automated redaction hooks at ingestion to strip sensitive fields before longer-term logs are stored.
- Evidence & exports: The export package includes (a) the exported objects, (b) a signed audit bundle (log of who exported + approvals), and (c) a short export report template we provide for legal teams.
- On-call & revocation: We have a documented revoke playbook. For the pilot we recommend establishing two named approvers from HealthCo (primary + backup) that match SSO identities.
- Operational acceptance criteria: 1) ability to request export via Console with approval workflow; 2) exported object contains redaction metadata; 3) KMS key footprints documented.
