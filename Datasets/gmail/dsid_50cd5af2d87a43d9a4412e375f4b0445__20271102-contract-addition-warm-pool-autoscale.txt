Answers to Acme’s questions:

1) Warm pool billing
- Prewarmed replicas are charged as reserved capacity when assigned to the customer’s Dedicated pool. In practice the warm pool size is taken from the customer’s committed GPUs (so your 24 GPUs will include the 3 prewarmed replicas). This avoids separate metering surprises.

2) Scale‑up failure modes and rollback
- Typical failure modes: image pull failures, insufficient GPU headroom in the zone, or long model KV warm times for cold starts.
- Fallbacks: (a) automatic route to warm pool replicas for latency‑sensitive requests, (b) graceful downgrade to pre‑approved light model variant (configured in rollout policy), (c) auto‑failover to the secondary region if cross‑region routing is enabled.
- We include automatic alerting and a circuit breaker that pauses aggressive scale‑ups if 95th‑percentile scale time exceeds 60s for >3 consecutive minutes; engineering/ops are alerted and a manual review is triggered.

3) Monthly delta (single line item)
- +8 GPUs (committed) + warm pool sizing + SLA credits estimate = $18,600 / month on a 12‑month term.
- Notes: 24‑month commit reduces the uplift to ~$15,900 / month. Exact invoice line will be in the amendment PDF.

4) Throughput measurement
- Throughput reported and guaranteed at model output tokens/sec aggregated across the Dedicated pool (we map request ingress to model output in our telemetry for you). The 800 tps baseline is measured at the model token output.

Ops playbook (short)
- Prewarm window: warm pool replicas run a daily KV refresh 5 minutes before expected peak windows (configurable).
- Scale monitoring: we track scale latency at 50/95/99th; automated alerts at 95th > 45s.
- Emergency rollback: if sustained scale failures occur, traffic is routed to the fallback light variant and we hold a manual escalated incident call.
