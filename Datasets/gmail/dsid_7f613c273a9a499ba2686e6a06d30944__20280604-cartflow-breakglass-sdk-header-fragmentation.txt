Quick triage notes (pre-call):
- Reproduced similar failure locally using an nginx HTTP/2 proxy that deliberately splits header frames (test harness linked in INF-8421). The issue is in our streaming parser’s header coalescing logic: it assumes header frames arrive atomically and fails when continuation frames are delivered separately.
- Error surfaced as a parser panic that returns a 502 to the client and prevents the KV cache lookup path — which explains the latency spike as requests are retried.

Proposed immediate actions:
1) Patch the streaming parser to accept header continuation frames (two-line change to the coalescer) -> run CI -> can ship as server hotfix in ~90 minutes if we prioritize.
2) Publish a client SDK micro-patch (v1.7.1) that includes more robust header emission when behind HTTP/2 proxies; this reduces the probability of split frames on the client side (ETA ~2 hours for release/propagation).
3) Short-term mitigation: route CartFlow traffic to a dedicated read-only pool that does relaxed header parsing and bypasses the KV cache path to avoid the retry storm. This is ~10–15m ops work.

I’ll prep a PR and can be standby for the 10:30 sync.
