Daniel — great notes, thank you. Short answers inline and next steps below.

Inline: 
- AWS KMS + HSM-backed CMKs: supported. For Redwood Dedicated and Private deployments we can integrate with your AWS KMS CMK via external key policy. For hosted we offer envelope encryption where you can bring a root CMK in your account and we perform per-tenant data key wrapping; those keys can be HSM-backed (FIPS 140-2/3).
- Audit logging: We log key usage (per-request metadata: key-id, operation, requester-id, timestamp, request-id) to our internal audit sink. For Private deployments we can configure export of audit logs to your Splunk/CloudWatch S3 bucket (mutual TLS and IAM role-based export). For Hosted customers we support log export via secure delivery to a customer-owned S3 with KMS-encryption.
- Live rotation: Our runtime supports zero-downtime rotation for cached inference keys using a rolling rotate + KV cache invalidation. For streaming sessions there is a short (<2s) token rekey window where clients will retry; we instrument automatic fallback to a compatible key variant to avoid session termination. We'll demo this in the technical deep-dive.
