Cal / Tessa / Lauren — attaching a short mapping and two artifacts: redwood-byok-matrix.xlsx (matrix of key custody + operator entitlements) and key-flow-diagram.png (sequence diagram). Highlights:

1) Key custody model (BYOK):
- Master Key: always stored in customer KMS (supported: AWS KMS, Azure Key Vault, GCP KMS, and HSM export only).
- CEKs (content encryption keys) are generated per-model instance; by default, CEKs are encrypted with the customer master key and only the ciphertext is stored by Redwood.
- Operator access: operators cannot decrypt CEKs without an escrow flow. Escrow requires:
  * a signed legal request (DocuSign) from an authorized customer admin,
  * recorded justifications in audit log, and
  * multi-party approval inside Redwood (security + legal).

2) Telemetry and metadata collection (private control plane):
- Mandatory telemetry: agent-heartbeat, pool-health, error traces (no input payloads).
- Optional debug telemetry (only if customer toggles and shares a secure token): full request logs for a defined 72-hour window, stored in customer-controlled object store or encrypted Redwood bucket scoped to region.
- EU-residency: for eu-tagged routes, telemetry is routed to eu-central buckets; no cross-region replication unless explicitly allowed by the customer.

3) Subprocessors (private deployment profile):
- Patch/Update Vendor: SecureOps Ltd — access limited to signed, time-bound update tokens; no telemetry access.
- Monitoring Agent Provider: TeleProbe Inc — only aggregates (counts/errors), hosted in customer region.
- Hardware vendor telemetry (on-prem): OEM diagnostic package — can be disabled.

4) Breakglass-forensics path:
- Emergency access starts with customer request + DocuSign approval link. We can support a blinded attestation mode where Redwood runs a forensics job that returns only parity/diagnostic results without revealing plaintext. Full decryption only allowed per escrow flow above.

Cal — adding a few legal / DPA notes inline. Main items to consider for Global Bank:

- DPA Annex: we propose an Annex that codifies BYOK obligations and operator breakglass requirements (we will insert explicit steps for DocuSign authorization + retention of approval evidence).
- Subprocessor disclosure: we will include a short list and a promise of 30-day notice prior to onboarding any new subprocessor that can access telemetry/diagnostic aggregates. We will add a clause to restrict cross-border replication of telemetry unless signed off.
- Data subject requests & retention: recommend explicit section that telemetry retention defaults to 90 days for error traces, 30 days for heartbeat metrics, unless the customer sets otherwise in the control plane.
- Audit & evidence: Redwood can produce a PDF evidence package (signed) of any breakglass action within 14 days; for highly regulated customers we can add a certified notarization addendum (extra fee).
