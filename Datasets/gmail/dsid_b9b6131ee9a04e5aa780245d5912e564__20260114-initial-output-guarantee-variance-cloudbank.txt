Alex — thanks, great questions. High level first, then a proposed operational carveout.

High-level commitments (hosted offering, default model family):
- TTFT (streaming): 95th percentile <= 220 ms for outputs <= 256 tokens; 99th percentile <= 420 ms.
- Sustained token throughput: we provision per-model variants; for the model we demoed we expect sustained ~9k tokens/sec per GPU when batched.
- Burst handling: autoscaling and preemptible bursts apply; short spikes (<=90s) are absorbed by burst capacity, beyond that we recommend Dedicated capacity for hard SLAs.

Operational carveout proposal (pilot-stage exception):
- If streaming first-token target is at risk during rollout we will: 1) automatically fallback the request to the synchronous (non-streaming) endpoint with equivalent latency expectations for completion; 2) emit a trace tag and increment a pilot-exception counter.
- Measurement window: 30-day rolling window, compute 95p TTFT per route; credit tier: 10% service credit when monthly TTFT misses exceed 2% of requests, 25% credit when >10%.

Notes / constraints:
- Streaming is sensitive to prefix caching and client-side windowing; very short prompts with many concurrent warmups can increase observed TTFT for initial tokens.

Alex / Soojin — quick technical addendum to set expectations:

1) Batching and TTFT: the runtime uses continuous batching. For isolated low-qps requests we see near-single-request latency; however, when requests align for batching to be efficient, TTFT can be slightly higher (batching delay) but aggregate throughput improves. We tune the batching window aggressively for streaming routes to prioritize first-token emission.

2) KV cache warmup: cold-model or cold KV cache can add ~40–120 ms to the first-token emission until the KV cache populates. For CloudBank's pattern (bursts following idle periods) this is the primary cause of TTFT tail.

3) Quantized variants: some quantized model builds have different per-token emission rates; we should define per-variant baselines.

Proposed technical exception for the pilot:
- Accept an operational SLA that guarantees 95p TTFT <= 300 ms during a 14-day rollout window. After validated telemetry and a canary pass we will reduce the contracted 95p target to 220 ms.
- If streaming falls back to sync automatically more than 1.5% of requests in a measurement week, we trigger an incident review and temporary scaling of Dedicated-like burst capacity.
