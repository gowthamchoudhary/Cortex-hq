Marissa / Olga —

Quick internal note based on Elena's sample:
- Interactive bucket (short Q&A): mostly short prompts, median 120 tokens, p95 latency target should be strict. For that bucket we should target low-latency instances (e.g., A10G or A5000-class) with modest parallelism and KV cache enabled. Estimate: 4–6 nodes (oversub ratio 1.5x) to cover typical daytime traffic + short spikes.
- Throughput/batch bucket: for batched scoring (multi-turn summarization batched where possible) we can use larger GPU SKUs (A100-40GB or equivalent) with higher batch sizes. Estimate: 2–3 batch nodes (spot-burst enabled) for cost efficiency.
- Long-generation bucket: these are long-sequence, high memory; recommend 2–3 high-memory quantized nodes (L4x or A100 depending on model) with lower oversubscription and isolated queues to avoid head-of-line blocking.

Caveats: Our estimator needs exact p99 lengths, whether streaming is used (streaming reduces memory pressure but increases kernel-switch overhead), and the proportion of requests that can be served from prefix cache. If p99 response length > 2k tokens we likely need to bump memory SKU counts.

I'll draft a compact sizing slide (workload_bucket_hypothesis.pdf) after we get answers and Elena's signal for a call.
