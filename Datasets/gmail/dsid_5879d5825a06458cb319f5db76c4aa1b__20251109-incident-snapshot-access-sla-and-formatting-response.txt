High-level answers (short):
- Retention: hosted accounts default to 90 days for full per-event audit logs; configurable up to 7 years via Dedicated/Private plans or enterprise retention contracts.
- Snapshot exports: yes — we can produce scoped incident bundles (time range + identifiers). Bundles are produced as compressed archives that include event files plus a signed manifest.
- Formats: JSONL (primary), CSV export for structured events, Parquet on request. We include raw request/response payloads for customers that have opted into storage of request payloads; otherwise exports contain structured metadata and references.
- Delivery: S3 presigned PUT (preferred), SFTP, or encrypted HTTPS POST to your collector. We also support direct transfer to customer-owned S3 buckets via cross-account role (AWS).
- SLA: standard delivery target is 72 hours for up to 200GB. Expedited 48-hour turnaround is available for an upcharge. For very large datasets (>1TB) we provide chunked exports and an agreed timeline.
- Hashing/signing: bundles include SHA256 hashes per-file and a signed manifest. We sign manifests using customer-managed KMS where available; otherwise Redwood KMS-backed signing is used.
- Redaction: we offer on-export redaction and pseudonymization. The export includes a redaction map (rows removed or fields pseudonymized) and an assertion that redaction was applied.
- Costs: export pricing is volume-based (per-GB) plus a flat request fee; expedited processing has an additional fee. I'll have Ben follow up with a template cost table.

Emma — quick technical addendum from security/ops:

- Manifest signing: We generate a per-bundle manifest.json that lists all files and per-file SHA256 checksums. For Dedicated/Private customers we can configure manifest signing with your KMS (asymmetric ECDSA signing) or an HSM-backed customer key. For Hosted accounts we offer Redwood-managed KMS signing; the signature includes a timestamp (RFC3339) and the signing key id.
- Time provenance: manifest includes monotonic event timestamps (UTC) and the server ingestion timestamp. We can include an attestation file that contains a Redwood-signed statement of the export parameters (time range, filter set, user ids) suitable for legal review.
- Tamper evidence: apart from per-file checksums and signed manifest, we can provide a chained hash (Merkle-style summary) on request for high-assurance cases.
- Export filters: supported filters include time range, user_id list, session ids, route ids, and log level. Incremental exports supported (delta since last manifest) via continuation tokens.
- Redaction map: delivered as a CSV with original field path, redaction type (remove/pseudonymize), and redaction salt id (for pseudonymization reproducibility).
- Schema: attached audit_log_schema.csv — it documents event fields we include by default; additional application fields can be mapped during onboarding.
