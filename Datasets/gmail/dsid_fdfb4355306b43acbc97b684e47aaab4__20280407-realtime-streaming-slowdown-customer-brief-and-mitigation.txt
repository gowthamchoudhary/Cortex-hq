Marissa / Sergio — quick notes from initial triage (internal only). Please do not forward raw traces to the customer yet; we'll sanitize.

Observations:
- Spike start correlates with a scheduled kernel selection patch that rolled at 08:50 UTC to the realtime-serving fleet (commit 8f7a2c). We see queue depth grow for certain shard classes and an increase in tail latency for KV-cache lookups (~2.6x p99).
- A subset of sessions are suffering from intermittent slow memcpy on the new kernel path; appears to affect long-context sessions more.
- Correlation: 88% of affected requests hit a particular model variant (variant-v3-q8) that switched runtime kernel selection at deploy.

Proposed mitigations (immediate):
1) Roll back kernel selection change for variant-v3-q8 (rollback patch queued).
2) Temporarily pin Fintech Labs traffic to the older variant-v2-q4 which has consistent tail behavior.
3) Add a short-lived queue priority for streaming ACKs so small token frames are not coalesced into large bursts.

I'll coordinate rollback with infra and confirm once done. After that we should run a controlled canary of the fixed kernel against low-traffic shards.

Hi Alyssa — following up with a brief post-incident summary and recommended next steps. Thanks again for the signal and the traces; that was instrumental in narrowing the root cause.

Summary (what happened):
- Between ~08:50–09:25 UTC on 2028-04-07 we had an increase in p99 token latency on streaming endpoints for certain model runtime kernels. The root cause was a kernel selection regression for the variant-v3-q8 runtime that introduced occasional memcpy inefficiencies under specific long-context workloads.

Impact on Fintech Labs:
- Approximately 7% of your streaming requests experienced bursty token delivery (p99 token latency 4–7s) during the window. Non-streaming responses were less affected.

What we did (mitigation):
- Immediate routing of your traffic to a healthy replica pool (completed 09:00 UTC).
- Rolled back the kernel-selection change for the affected variant (09:18 UTC).
- Applied a short-term queue smoothing policy to reduce token coalescing while rollback validated.

Permanent fixes and timeline:
- Patch for kernel memcpy path validated in internal canary (deployed to canary 04-08, will ship to prod 04-10 after final perf regression tests).
- We will add a runtime guard that prevents automatic kernel switching for long-context streaming sessions until the memcpy path is validated under burst workloads.

Customer guidance (recommended workarounds while we rollout):
- If you observe regressions again, switch a small percentage of traffic to response-mode (non-streaming) as a fallback — this reduces UX regressions during the transient.
- Keep one or two sessions live for us to correlate if you file another incident; please include request IDs and timestamps.
