Quick update from infra: we saw a handful of 302 -> 200 flows where the relayState param was being dropped when the link was followed from Gmail on macOS (webview referrer behavior). The token itself is valid for 60 minutes but we also have a TTL handshake between the activation service and SSO proxy that expects the relayState to be present. If relayState is missing the proxy renders an empty page (no error) — a UX regression.

Details:
- Affected path: /activate?s=<<token>>&r=<<relayState>>
- Symptom: relayState missing -> proxy returns blank 200 with no JS payload
- Temporary mitigation: issue a "direct-activate" link that posts the token to /activate/confirm (one-time POST).

Monica, can you confirm whether HarborWave is going through our SSO flow (SAML) or using the hosted activation flow? If SAML, we should generate the POST link.
