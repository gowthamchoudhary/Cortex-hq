Jack — thanks for the clear asks. Looping in Laura (product/security), Marcus (serving runtime), and Mina (onprem ops) so we can align the pilot contract and runbook. High-level answers and next steps below.

Quick answers:
- SCIM shape: Redwood expects email (primary), externalId (opaque id), groups (array of group names), and a roles attribute that maps to our operator role names (operator.read, operator.write, admin). We can accept additional attributes (department, manager) but we don't canonicalize them for RBAC decisions.
- SCIM errors/deltas: we support incremental SCIM PATCH and full replace. Our connector retries transient failures with exponential backoff and surfaces persistent 4xx errors in the console. We'll provide a delta-report export (CSV) for the pilot.
- Delegation vs service account: we prefer delegated SAML assertions for operator sessions (short-lived) where feasible. We still support service accounts for automation. Delegated flow requires: SAML assertion with audience set to our private control plane SP, NameID/email, and a roles claim (mapped to Redwood operator roles).
- Audit logs & retention: we can export audit logs (JSON) to customer S3 or push to a syslog endpoint. Retention is configurable in Private CP; default export TTL for pilot can be set to 90 days.

Jack / team — quick product decision memo so we have a single source of truth for the pilot scope. This is a binding alignment for the PoC runbook and contract amendment.

Decisions:
1) Adopt delegated SAML assertions for operator sessions (preferred). Rationale: shorter lived credentials, clearer audit surface, aligns with our fallback model to hosted API.
2) SCIM mappings: support canonical attributes (email, externalId, roles, groups). For roles, we will expose three operator roles to Acme: operator.read, operator.write, operator.admin. Any additional entitlements will be handled via groups->role mapping documented in the runbook.
3) Audit export: Redwood will provide consumed-audit JSON with the following fields: timestamp, internalUserId, externalPrincipal (email/externalId), action, route, model_version, request_token_hash. We will enable 90-day retention and delivery to Acme S3.
4) Cert rotation: require customer-managed SAML certs rotated at least every 60 days for the pilot (we can relax to 90 days in GA). Set automated alerting if cert expires in <10 days.

Risks and mitigations:
- Partial SCIM failures: we will surface a per-user delta report and provide an endpoint for re-run of failed operations. Marcus to add an exponential backoff advisory for large directories.
- Operator privilege creep: RBAC review must be performed quarterly. We'll require Acme to sign off on mapping before any admin grants.
