Hi Anika — glad to be onboard. I reviewed the proposal and sketched a technical checklist (attached) that maps to a four-step pilot:

1) Sandbox provisioning: scoped API key + network rules; smoke test generation at 256/512 tokens.
2) SDK connector dev: LangBridge adapter that calls Redwood's /v1/generate endpoint with token-level streaming off for determinism.
3) Tracing integration: propagate X-Redwood-Trace, support TraceWise span export; add test harness for synthetic trace correlation.
4) Failover plan: configure routing policy to fall back to a smaller quantized model and surface a 429/503 policy to the SDK.

I've attached llm-sdk-trace-checklist.xlsx with tasks and owners. A few questions from an infra perspective: what baseline GPU flavor do you expect for the Dedicated window (g10x, a100g, etc.) and any IO/network constraints? Also, will the pilot use Hosted+Dedicated mix or Dedicated-only?

Security: we'll accept a scanned NDA and will push our DPA template after kickoff. If PromptWorks needs SOC2 artifacts upfront, we can provide a redacted report and an evidence pack (redwood-dedicated-sla.pdf).

Proposed kickoff: Tue Apr 5, 09:00 PT (30m). If that works, I'll create a calendar invite and include a short tech demo.

Marissa / Team — quick technical clarifications from TraceWise:

- Header format: we'll accept X-Redwood-Trace and also support w3c tracestate/w3c traceparent. Can you confirm Redwood will echo traceparent in responses so we can correlate latencies?
- Sampling: for the pilot we plan to sample 100% of Connector requests; please confirm rate limits for ingesting spans.
- Latency tagging: we need token-level timestamps surfaced in the span for accurate per-token latency heatmaps. Is that possible or can we get batch-level timing and per-chunk markers?

Thanks everyone — a few concrete commitments from Redwood infra/telemetry: 

- We will echo w3c traceparent in the response headers and emit X-Redwood-Trace for internal correlation.
- For the pilot we can enable token-chunk markers in the span (not full per-token timings) — will provide start/finish timestamps for each decode chunk. That should be sufficient for Request-level heatmaps.
- Sampling: we'll set tracing sampling to 100% for the sandbox window and provide a temporary elevated ingest quota to TraceWise.
- Dedicated flavor: we'll reserve one g10x-equivalent instance for the 2-week pilot; Marissa will confirm exact GPU model in the invite.

Logan — we should surface the fallback behavior in the SDK README and ensure the LangBridge adapter exposes a simple retry/backoff that prefers the smaller quantized model when the routing policy returns a 429. Also recommend adding a telemetry tag `pilot:promptworks` to all pilot spans.

I'll join the kickoff on Tue Apr 5. Marissa — thanks for owning the invite.
