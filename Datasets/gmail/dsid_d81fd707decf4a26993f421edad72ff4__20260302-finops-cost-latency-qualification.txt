Eva —
Thanks for the details. High-level guidance below, plus two example configurations with ballpark unit economics (numbers are illustrative; we’ll refine after you confirm model family preference and whether Private is required).

Key trade-offs (short):
- Streaming vs non-streaming: Streaming (token-by-token) reduces perceived latency for long responses but reduces batching efficiency for many short requests. For your UI use case (100–500 tokens), streaming helps UX but can raise tokens/sec utilization and per-token cost slightly when it prevents batching.
- Batching: Larger batches increase throughput (lower $/1M tokens) but raise tail latency. On our Standard tier, we target micro-batching ~8–16 requests; Performance tier uses optimized kernels + smaller micro-batches and lower P99s.
- Model size & quantization: Smaller quantized variants lower cost substantially (~2–3x) but may increase latency slightly depending on kernel availability.

Example A — Performance Tier (SLO-driven):
- Target: 90th pct latency <= 400ms for 100–500 token requests.
- Config: Performance GPU pool, streaming enabled for UI paths, per-customer warm KV cache, and aggressive autoscaling for spikes.
- Unit economics (rough): $45–$65 per 1M tokens (includes reserved capacity amortized, 24/7 SLA + observability).
- Pros: Meet 400ms 90th; predictable SLA; fewer errors under spikes.
- Cons: Higher $/1M tokens; commitment recommended.

Example B — Standard Tier (cost-first):
- Target: 90th pct latency ~700–1200ms (may be fine for background tasks and some UI paths).
- Config: Standard GPU pool, batch-first (no streaming for UI), larger batching windows, more aggressive batching cache.
- Unit economics (rough): $12–$28 per 1M tokens depending on batch efficiency and quantization.
- Pros: Much lower unit cost; easy to pilot on pay-as-you-go.
- Cons: Harder to hit 400ms 90th consistently; may require model trimming or caching to meet UX bar.

Recommendation for FinOps.ai:
- Pilot: Start Standard tier with a Performance-tier trial on UI-critical routes. Route UI calls to Performance only for a subset of users (canary) while everything else on Standard. This keeps blended $/1M tokens ~ $20–$35 assuming 10–20% of requests hit Performance.
- Streaming: Enable streaming for the Performance UI route only. For Standard, use small batching windows to reduce cost.
