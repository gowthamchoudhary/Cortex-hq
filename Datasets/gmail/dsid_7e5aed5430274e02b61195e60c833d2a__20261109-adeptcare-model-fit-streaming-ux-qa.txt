Hi Laura / Kevin —

Quick answers and an immediate mitigation plan based on Marissa's run: 

Why you see mid-sentence pauses
- Generation stalls can come from model tokenization boundaries or short-lived attention/compute backpressure on the runtime.
- On the client side, immediate-flush streaming surface renders whatever partial tokens arrive, so any micro-pause looks like a partial sentence stop.

Immediate mitigations (low lift)
1) Server-side "hold-final-token" policy (buffer last token for 150ms) — reduces flashes of half-sentences without noticeable end-to-end latency increase for clinicians.
2) Use a soft client heuristic: show an animated ellipsis if the latest token did not end with punctuation and <200ms has elapsed.
3) Prompt tweak: avoid prompts that end with open clauses (e.g., "The patient should be") — add an explicit completion anchor like "Summary:" or an end marker '###' to gate finalization.

Model recommendation
- For the POC we recommend redwood-13b-ptq as the primary variant: in Marissa's quick pass it reduced partial-hang count by ~60% vs redwood-7b-quant while p95 token latency remained within an acceptable multiple (approx +1.8x cost). We can attach the numeric report in the formal bench.
