Vectorstore / shard governance recommendation:
- Use your existing Weaviate cluster (weaviate-sales is on copy) to avoid new infra procurement.
- Shard key: customer_id + month (YYYYMM) — partitions will bound write fanout for backfill and allow time-based TTL later.
- Read routing: query router will fan-in across at most 3 recent partitions; older partitions are cold and only used for long-tail queries.
- Index schema: 512-d float32 embeddings, cosine distance; approximate search via HNSW with M=16 | ef=128 for staging; tune for prod after staging results.
- KV cache: warm top-100 queries per shard to avoid tail latency spikes during backfill.

Rerank eval proposal:

- Labels: 5 judgments per query (mix internal SME + vendor) — expected labeling run ~10k judgments.
- Metrics: primary = MRR@10, secondary = NDCG@10 and MAP. Use bootstrapped CIs; target a p<0.05 effect size detection for +5% relative MRR.
