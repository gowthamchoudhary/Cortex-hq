Alex / team — attaching the matrix and sample responses (attached to this thread). Below are the key technical decisions and a concise schema example you can paste into your validators.

1) Streaming config:
- Model: use redwood-llama-extended-13b (quantized) for pilot.
- Stream chunk window: 100–250ms recommended; fallback to 1 token boundary if you need strict JSON integrity.
- Prefix caching: enabled for repeat prompts (saves ~20–40% tokens on triage flows).

2) Function / tool mapping (high-level):
- intent_detect(input_text) -> returns intent_id, confidence, top_slots
- extract_entities(input_text, intent_id) -> returns list of entities with types and span offsets
- schedule_followup(patient_id, timeslot) -> returns appointment_id, provider_id, start_time

3) Sample response JSON schema (extract_entities) — drop into your validator:
{
  \"type\": \"object\",
  \"properties\": {
    \"entities\": {
      \"type\": \"array\",
      \"items\": {
        \"type\": \"object\",
        \"properties\": {
          \"type\": {\"type\": \"string\"},
          \"text\": {\"type\": \"string\"},
          \"start_offset\": {\"type\": \"integer\"},
          \"end_offset\": {\"type\": \"integer\"},
          \"confidence\": {\"type\": \"number\"}
        },
        \"required\": [\"type\",\"text\",\"start_offset\",\"end_offset\"]
      }
    },
    \"meta\": {\"type\":\"object\",\"properties\":{\"request_id\":{\"type\":\"string\"}}}
  },
  \"required\": [\"entities\"]
}

Notes on streaming + structured output: when streaming partials, the client should buffer until a top-level JSON delimiter is received. If you cannot tolerate partial JSON, we recommend streaming the narrative (user-facing text) and sending tool-call JSON as a separate non-streamed message (tool_call payload). We'll include both options in the matrix.

4) Testing & validation:
- sample_stream_responses.json contains 20 partials and 5 final payloads to run against your local validator.
- We recommend an automated test that asserts schema conformance on final payload and a lighter smoke check against partials.

5) Audit & retention summary:
- Hosted: call traces retained 90 days by default; optional extended retention can be purchased.
- Dedicated/Private: retention configurable via your S3/KMS bucket and audit logs forwarded to your SIEM.

Deliverables: redwood_schema_matrix_v1.csv and sample_stream_responses.json attached; full playbook and timeline on Drive (link below).
