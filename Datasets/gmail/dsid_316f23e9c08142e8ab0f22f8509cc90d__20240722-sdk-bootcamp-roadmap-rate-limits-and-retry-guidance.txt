Alex —

Great questions. I pulled together the short reference below so Lina can map to her client code before the bootcamp. I also attached a Markdown reference in case you want to drop it into an internal playbook.

Recommended defaults (client-side):
- Timeouts:
  - Connection timeout: 2s
  - Request timeout (overall): 30s for generation endpoints, 10s for embeddings by default (tunable by model/sequence length)
- Retries:
  - Retry on: 429 (rate limit), 503 (transient server), network errors (socket timeouts)
  - Max retries: 4
  - Backoff: exponential with full jitter (sleep = random(0, base * 2^attempt)), base=200ms
  - Retry-after honor: if server returns Retry-After header, respect it but cap at 20s
- Circuit breaker / throttling guidance:
  - If >10% of requests in a 1m window are 429/503, trip a short circuit for 30s and then probe at 10% traffic
  - For bulk/batch jobs: stagger job start times by random 0-30s to avoid synchronized bursts
- Rate smoothing: use small local client-side queues with windowed rate tokens (e.g., token bucket) to convert spikes into smoothed traffic

Server-side signals to watch for during cutover:
- 429 with X-RateLimit-Remaining and Retry-After headers
- 503 with X-Server-Load or Retry-After when present
- 200 + high latency (>95th percentile) as an early indicator of saturation

Sample Node snippet (in the attached zip) includes a retry wrapper that implements the above backoff + jitter. Below is a minimal example to paste into Lina’s tests: 

// pseudo-snippet
async function callWithRetries(fn) {
  const base = 200;
  for (let attempt=0; attempt<4; attempt++) {
    try {
      return await fn();
    } catch (err) {
      if (!shouldRetry(err) || attempt === 3) throw err;
      const wait = Math.random() * (base * Math.pow(2, attempt));
      await sleep(wait);
    }
  }
}
