Thanks Rachel — quick feasibility summary ahead of Thu 3/25.

Short answer: feasible. High level plan: 
1) BYOK options we can offer:
   a) CloudHSM-based CMK: customer requests key generation inside CloudHSM (AWS/Azure/GCP equivalent) and we integrate so that key operations (encrypt/decrypt/envelope) happen via HSM. Key material never exported; we support HSM-backed CMKs with standard KMS APIs.
   b) Customer on-prem HSM: for customers with strict key ceremony requirements we can integrate via an encrypted proxy connector that performs crypto ops on-prem and returns ciphertext to Redwood. This requires an installation window and network configuration (mutual TLS).
   c) Redwood-managed envelope with external wrapping: we can accept externally wrapped key material under strict attestations, but this is only for short-term pilots.

2) Audit & logging: we can export per-request audit events (request id, model, timestamp, token counts, response hash) to an HTTPS endpoint or syslog; we will redact or exclude raw response payloads for forwarded logs per your requirement. Retention is configurable per-customer; we can set immutable retention rules for 3/7 years depending on bucket/SIEM config.

3) Attestation & contract support:
   - We can provide deletion/rotation attestations (signed statement + timestamp) after we execute the rotation or deletion. For key ceremonies we can provide a certificate of generation from the HSM provider where applicable.
