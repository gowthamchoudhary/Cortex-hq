Dropping in some initial engineering notes: 

- Tenant-affinity: we have work-in-progress hooks for affinity (affinity-key + soft pin). Delivering strict hot residency across peaks is non-trivial and impacts bin packing + autoscaler. For a 2-week bridge we can do a best-effort pinned pool with manual capacity reservation for Hollis — effectively a reserved warm pool bound to their tenant id. This requires a small scheduler change (2–3 days) and a manual ops playbook for sizing.

- Audit hooks: we can expose an export endpoint that will stream per-request trace events to an internal buffer then to S3 (or a signed HTTPS endpoint). Format: ndjson with trace_id, request_id, model, tokens_generated, latency_ms, and a redaction flag. That is ~3–4 days to implement and 1 day to add retention config and docs.

- Risk areas: KV cache warming (first-hour tail latency spikes), extra capacity cost (we should quantify), and potential privacy redaction rules for token captures. We will need SOC/compliance review — Laura, can you coordinate?

If Product is comfortable with the limited-scope solution and we accept a manual capacity bind + canary, Eng can commit to the 2-week sprint starting 2026-10-05.
