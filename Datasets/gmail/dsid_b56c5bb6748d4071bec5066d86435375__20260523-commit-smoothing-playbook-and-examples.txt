Hi Morgan —

Appreciate the clear asks. I've attached two artifacts: a one-page commit-tier proposal (commit-tier-proposal.pdf) and a csv with three worked examples (smoothing-examples.csv). Below is a concise playbook and the short answers, then the examples follow.

Short answers:
- Minimums: billing is calculated per request with tokenization applied to the full call. We subtract any cached prefix tokens when the request matches a cached key (prefix re-use). If that doesn't apply, short requests still hit the per-call minimum which is defined as a minimum billable token quantum (e.g., 32 tokens).
- Commit smoothing: this is an invoiced credit mechanism applied at month close. We evaluate monthly commit usage vs committed units and compute a smoothing credit that reduces overage volatility for accounts enrolled in the smoothing pilot. The credit is contractual (line item) not an ad-hoc manual credit.

Playbook (high level):
- Enroll in smoothing: add rider to contract. Smoothing applies only to token-based metering (generation + context).
- Compute baseline: for each billing day, compute billable tokens (after cache subtraction). Sum month-to-date.
- Compare to commit: if month usage > commit, normal overage rules apply. If usage < commit but spikes earlier caused temporary overages, smoothing returns a credit equal to min(spike_overage, smoothing_band) up to an agreed cap.

Examples (see csv):
1) Steady low usage — no overage, no credit.
2) One major spike — spike causes two invoice-level overage events mid-month; smoothing returns a credit at month-end covering up to the smoothing band so net overage is reduced.
3) Frequent microbursts with long-context calls — demonstrates prefix reuse subtraction (we show how cached 1.5k prefix tokens reduce billable tokens per call).

Adding the precise accounting rules we use so the examples match billing: 

1) Tokenization & rounding: tokens are counted using our tokenizer; billable tokens per request = max(minimum_quantum, ceil(billable_tokens / quantum) * quantum). For accounts on pilot smoothing we set minimum_quantum = 16 tokens and quantum = 8 tokens; for standard hosted API minimum_quantum = 32 tokens.

2) Context/subtraction: when a request matches a cached prefix, we detect prefix length in tokens and subtract that prefix from billable input tokens for the request. We do not subtract KV/attention cache carried across sessions — only explicit prefix reuse detected by our cache key algorithm.

3) Rounding & proration: monthly invoices aggregate billable quanta. Smoothing credit is calculated at invoice close as: smoothing_credit = min( cap, sum_of_midmonth_overage_events - (monthly_commit - month_usage_excluding_spikes) ). That formula is verbose; see smoothing-examples.csv where rows show exact arithmetic.

I built the csv with three rows matching Camila's scenarios. Note: if Adept wants quantum changed to 4 tokens, that's contractable for Dedicated commitments > $X/mo.
