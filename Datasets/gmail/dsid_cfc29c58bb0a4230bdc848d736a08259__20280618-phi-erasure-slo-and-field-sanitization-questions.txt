Short answers up front:
- Erasure SLOs: we offer contractually-backed time-to-erasure windows for Private deployments. Typical commitments:
  * Metadata & audit logs: SLO = 30 days for deletion from live indexes, with an additional 30 days for dependent backups (60 days total for full media-level removal unless otherwise negotiated).
  * Model input residuals (active KV/prefix cache): eviction and zeroization within 24 hours for dedicated/private runtime; guaranteed zeroization within 7 days for standard private installs unless faster window is contracted.
  * Persistent backups / cold storage: standard 90-day retention window by default; can be shortened to 30 days or configured to immediate omission from backups for certain datasets at contract signing.

- Field-level redaction & pseudonymization: yes, we support multiple approaches:
  1) Pre-ingest redaction pipeline (recommended when you want PHI never stored): deterministic regex + ML entity scrubber that can replace tokens with reversible pseudonyms (KMS-wrapped) or irreversible masks. Trade-off: some loss in generation fidelity if critical context tokens are removed.
  2) On-the-fly token filtering before persistence: runtime hook that allows the model to see full input for inference but writes a redacted copy to long-term storage. This preserves model accuracy but leaves a brief window where raw input exists in memory; KV cache policies mitigate exposure.
  3) Post-hoc field redaction in stored traces: bulk redaction where we run scrubbers against stored transcripts; lower impact on model behavior but higher remediation complexity.

Lisa — a few operational clarifications based on Sean's summary and the proposed VPC install patterns:

1) KV cache and runtime artifacts
- For Private/VPC installs we patch the runtime to support configurable KV cache lifespans. Default: 24h TTL with immediate zeroization on erasure request where the impacted keys are known. If Acme requires guaranteed zeroization at request time for any key linked to a patient ID, we can scope that into the rollout with a 24-hour emergency zeroization job (SOC 2 observability hooks will show job completion).

2) Backups & snapshots
- The default appliance snapshot cadence is daily with 90-day retention. We offer an option at contract to exclude selected databases from snapshots (e.g., transient inference traces), or to configure snapshot lifecycle rules to purge those datasets within 30 days. Note: excluding from snapshots means you accept risk for reduced restore fidelity for those datasets.

3) Field redaction options (implementation detail)
- Detectors: a combined ruleset of regex + NER model (fine-tuned for clinical PII) to detect SSN, MRN, DOB, PHI phrases.
- Redaction outputs: irreversible replace (e.g., "[REDACTED_SSN]"), deterministic token mapping (pseudonymization) where original can be restored via KMS-wrapped key, or hashed tokens for irreversible pseudonymization.
- Tradeoffs: deterministic mapping preserves linkage across messages but increases re-identification risk if keys are compromised. Irreversible masks remove linkage but hurt any downstream dedup/analytics.

4) Auditability and proof of erasure
- We provide an audit package (job logs, zeroization confirmation events, snapshot lifecycle logs) that can be delivered under NDA. For compliance reviews, we can attach demonstrable runbooks and the job output CSV(s).
