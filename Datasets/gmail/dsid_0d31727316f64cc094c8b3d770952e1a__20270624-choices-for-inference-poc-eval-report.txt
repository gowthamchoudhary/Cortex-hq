Recommended shortlist (ranked by suggested starting order):

1) Redwood-Edge-13B (FP16 / 8-bit quantized) — Default POC pick
   - Why: Best tradeoff for your 95th %-tile latency < 250ms at single-token steady state with our GPU serving profile and prefix caching.

2) Open-Mistral-7B-Instruct (INT8) — Low-cost, high-quality for short forms
   - Why: Lowest cost and competitive quality for short prompts and intent extraction.
   - Cost estimate: ~ $0.00025/token.
   - Latency: Excellent single-token latency but may struggle on very long contexts; recommended for the bulk FAQ path where context < 1k tokens.

3) LlamaX-70B-slim (quantized 4-bit) — Fall-back for highest-quality/complex cases
   - Why: Use as a canary / fallback for hard extractions and long-context synthesis jobs where quality degrades on smaller models.
   - Cost estimate: ~ $0.002/token (use sparingly via routing rules).
   - Latency: Higher — use for batch jobs or when routed asynchronously.

Grace / Monica — a few quick technical points to call out that will affect the POC numbers so Emma has the right expectations:

- Continuous KV cache: For the FAQ route, ensure the probe/warmup phase runs ~200 representative queries per shard. That moves steady-state 95p down ~30–50ms in our runs.
- Batching policy: We recommend target batch window 8–12ms with adaptive burst up to 40ms for peak throughput. This keeps median latency low while preserving throughput.
- Quantization tradeoffs: The Edge-13B quantized path we're proposing uses a mixed 8-bit kernel while preserving FP16 attention; this gives the best latency/cost balance. Full 4-bit gains for 13B currently introduce a small accuracy hit on precise extraction tasks — flag in the regression checks.
- Long-context jobs (>4k tokens): Please plan to route as async jobs onto the 70B pool with slightly higher compute; for the POC we can run a small batch to validate cost/time.
