Update (09:05 PT):
- Batch size set to 1 for dsq-suggest-prod; immediate drop in queue latency for the batch lane.
- Hot-key lane enabled and we pinned top prefix (datasparq-suggest:hot) in RAM — cache hit rate for that prefix improved from 28% -> 93%.
- Error rate reduced from 12% -> 3.1%; P99 improved from 4.5s -> 1.2s. Throughput still ~15% below baseline because mid-percentile requests still encountering KV eviction churn for adjacent prefixes.

Root-cause hypothesis: a recent client-side change to the prefix tokenization introduced more ephemeral prefixes (higher cardinality), causing frequent evictions of hot entries. When the runtime batches requests, head-of-line (HOL) blocking made the impact visible at P99 and produced backpressure resulting in 500s for timed-out requests.

- Short-term: keep batch=1 for 2 hours and continue pinning top N prefixes. Toggle targeted prioritization (already in progress).
