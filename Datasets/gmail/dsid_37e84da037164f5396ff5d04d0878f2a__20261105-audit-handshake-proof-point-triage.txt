KMS rotation and access evidence: we maintain a rotation ledger (immutable entries) with rotation_id, operator_id (internal service principal), and rotation timestamp. For BYOK customers using Redwood Private, we record: key material import events, rotation API calls (with request IDs), and KMS access errors. We can include a signed ledger excerpt for Novamed.

Audit log granularity: request-level logs contain a token-id hash (not raw tokens), timestamp, route, and user-id when available. For SSO, we capture login/logout and token issuance events with timestamps and subject identifiers.

Exception path: we can support a temporary retention carveout for pilots but require:
- A signed exception request (customer + account exec)
- Defined TTL and start/end dates
- A mitigation plan (who can access, monitoring during exception)
