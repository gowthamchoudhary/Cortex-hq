Hi Lena,

Appreciate the clear questions — answering inline below so you can pull these into your questionnaire. Short version: we distinguish between metadata/telemetry, request/response payloads, and derived artifacts (embeddings, logs). Retention windows differ by category and by customer opt-ins (e.g., debug retention or enterprise data-residency contracts).

1) What we persist by default
- Request metadata: timestamps, model id, token counts, routing decisions — stored for 90 days for operational analytics and billing.
- Full request/response payloads (prompt text + assistant output): default behavior is conservative — we retain them for 30 days only for short-term debugging and to support self-serve troubleshooting. Prompts/outputs are not used to improve models unless the customer opts in.
- Token-level telemetry and aggregated usage metrics: retained up to 365 days in aggregated form (no raw text).
- Embeddings or derived artifacts: treated as customer artifacts and retained according to customer settings; default is 90 days but can be configured/contracted.

2) Deletion and accelerated purge options
- Self-service: customers can request on-demand purge of content via the Console or API (Data > Purge) which triggers our deletion workflow. Typical processing time is 24–72 hours depending on queue.
- Emergency/legal: we have an expedited runbook for contractual/legal purges (security@redwood.ai) — SLA is 48 hours for acknowledged requests.
- For Private/Dedicated customers: you can set retention TTLs at the account level (including immediate no-persist modes).

Notes and caveats
- EU customers: residency controls mean logs and payloads are stored only in the selected region; retention windows above apply per-region but can be tightened via contract.
- Cache and prefix KV: some short-term cache entries (used for latency) are ephemeral and purged automatically per-host; they are not considered persistent logs.

Lena — adding a few precision points from product/security so your legal team has the right language to put in the contract. Diego's summary is correct but I'll call out explicit default windows you can copy verbatim:

- Request metadata (non-text): 90 days (by default); includes timestamps, model id, token counts. Retained for billing/usage analytics.
- Full request/response payloads (prompt + assistant output): 30 days by default for hosted customers; 7 days for the "ephemeral" mode we recommend for high-sensitivity flows.
- Aggregated telemetry (non-text, e.g., QPS, latencies): 365 days in aggregated form; no raw text retained.
- Derived artifacts (embeddings, cached KV): 90 days default; configurable to retain indefinitely under contract.

If you need to represent this as a formal clause, you can reference: "Redwood will retain API payloads (prompts and model outputs) for up to 30 days by default, and will purge them on customer request within 72 hours, subject to legal hold or contractually agreed exceptions."
