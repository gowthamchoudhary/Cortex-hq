Hi Chris / Anika — quick technical note with a recommended routing and auth approach based on the constraints you shared. I kept this pragmatic for a phased rollout.

Summary recommendation (phased)\
Phase 1 (Hosted quickstart, minimal infra changes)
- SDK: use Redwood SDK v0.9.4 with short-lived API keys for backend services. Generate keys scoped to routes (read:clinician, read:analytics). Use server-side mTLS later for Private deployments.
- Routing policy (first-pass): route by request.metadata.tenant_id + request.metadata.user_role. Implement policy evaluation order: exact-route -> SLA override -> cost-threshold fallback. Example logic: if user_role == clinician and region == us-east, prefer low-latency route (model: redwood-nyx-6b-llm-cached). If cost budget exceeded for the minute, fallback to quantized-local-3b (see fallback chain).
- Fallback chain: redwood-nyx-6b-llm-cached (primary, hosted) -> redwood-nyx-3b-quant (hosted cheaper variant) -> local-quant-3b (customer-run lightweight LLM via Dedicated or Private) -> short-answer lamegrace static policy (structured KB lookup) for extreme degradation. Configure exponential backoff and circuit-breaker with 5s hard timeout.

Phase 2 (Private/Dedicated + stricter auth)
- mTLS + OIDC integration for service-to-service. Use KMS-integrated key rotation for long-lived secrets.
- Region routing: implement geo-preferred route with per-tenant override. For compliance tenants keep processing in the pinned-region only; Redwood's routing table supports route tags: region:us-east, region:us-west, privacy:high.

Embeddings & reranker pattern
- Two-stage retrieval: 1) Vector search (dense embeddings) as the candidate generator; 2) Cross-encoder reranker as a second-stage quality pass for top-10. Recommendation: compute passage embeddings with redwood-embed-4k (64-d float16) and host the ANN index in your infra (FAISS/HNSW). For reranking, we suggest using Redwood hosted cross-encoder only for top-k to control cost (we have a reranker endpoint that accepts score-only calls). If you must keep everything on-prem initially, we can provide a small cross-encoder step that runs in your Dedicated cluster.

Structured output & tool-calling
- Use tool-calling for canonical KB queries: define two tools: get_patient_timeline(patient_id) and search_guidelines(query, top_k). Tool output should be strict JSON schema to avoid hallucination. Use our SDK tools interface to register tools and attach service tokens with limited scopes.

Latency/cost policy knobs (config blueprint)
- route.priority: integer (higher = lower latency allowance)
- route.max_cost_per_minute: USD cents
- route.max_tokens_per_request: default 1024 (override for analytics)
- route.fallback_chain: ordered list of model ids
- route.timeout_ms: 500 for clinician fast-path, 2000 for analytics
- auto-batch.enabled: true for analytics routes, off for clinician websocket flows
