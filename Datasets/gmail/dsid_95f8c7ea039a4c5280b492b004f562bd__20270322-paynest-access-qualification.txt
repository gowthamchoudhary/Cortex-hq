Hi Tom — great to meet earlier. Recap + specific answers below, plus next steps. Attaching a short summary and our support access playbook for reference.

Quick answers (short):
- PII scope: By default Redwood does not persist user prompts/outputs for hosted customers beyond a short ephemeral cache used for batching; for Dedicated customers (reserved pools) we offer a configurable retention policy you control and can opt into zero-retention (no prompt/output storage) — see attachment redwood-data-handling-summary.pdf.
- Data residency: Yes — Dedicated and Private deployments can be pinned to a US region. For Hosted customers we run region-specific endpoints and can restrict routing to US-only for enterprise customers under an SLA.
- Support access / break-glass: Two modes — (1) Standard support: logs/metrics only (no payloads), accessed via RBAC-controlled console roles; (2) Break-glass: time-limited, recorded sessions that require two approvers (customer security contact + Redwood on-call manager) and are logged to an immutable audit trail. We provide a signed access request record and optional temporary key scoping.
- Audit logs: We retain API-level audit logs for 13 months (default for Dedicated) with options to extend; logs include timestamp, requester id, request path, model id, tokenized_size, and an access_reason field when break-glass is used. Example export attached in playbook.

Proposed next steps:

- If PayNest wants to proceed with Dedicated capacity, we can set retention to 0 days for prompt/output and configure region pinning; I suggest a short technical workshop with Marcus (runtime) and Monica (security) to validate break-glass flow against your internal controls.
- Please confirm the right security contact to authorize break-glass approvers — and if you have a procurement timeline.
