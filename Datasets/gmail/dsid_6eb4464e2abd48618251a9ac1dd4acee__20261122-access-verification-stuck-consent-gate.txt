Thanks for the ping. I pulled the proxy/SAML traces for the invite traffic — seeing a redirect loop with a 302 -> consent page -> 302 back to /auth -> 401. Two observations:

1) The redirect contains a missing "consent" query param on the /sso/redirect response. Coupa expects an IdP consent assertion in the redirect flow; if the tenant has a policy requiring explicit consent we see this loop.

2) There's evidence the downstream WAF (our cloud edge) is stripping the samesite cookie on second hop which causes the consent session to drop. That explains why incognito/mobile show same failure — the cookie never persists.

Workarounds/options:
- Vendor-side: If ProcureIT can accept the invite via a direct magic link (no SSO) we'll skip the SAML flow.
- Infra-side: We can whitelist Coupa SAML endpoints on the WAF to preserve the cookie and bypass cookie normalization.
- Temporary: Create a time-limited guest account for vendor to finish banking/W-9, then switch to SSO once mapping is confirmed.

I attached the raw SAML trace (coupa-saml-trace-20261120.log) — redacted a couple of headers. Janet, can you send your IdP issuer URL or the metadata XML? Also, what domain is ProcureIT using for SSO (e.g., procureit.okta.com)?
