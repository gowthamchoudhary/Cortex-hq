Hi Samantha —

Following up with the technical details Karthik mentioned. Below is a short primer and the sample webhook payload attached (metering-webhook-sample.json).

Overview:
- Metering endpoint: Redwood can call your /marketplace/consume endpoint with an event for each reported MeterDimension. Alternatively, Redwood can host the endpoint and translate internal usage to AWS meter IDs. For the hosted offering we usually host the publisher side and deliver signed events to buyer backends for reconciliation.
- Authentication: We sign webhook payloads with an HMAC-SHA256 header (X-Redwood-Signature) — verify using the shared secret we provision per-account.
- Entitlement mapping: Map your account ID (acme_org_id) to AWS customer entitlement_id at onboarding. We recommend storing both values in your entitlement table and accepting incoming meter events by entitlement_id.

Sample verification snippet (pseudo):
- Compute HMAC of payload using secret
- Compare to X-Redwood-Signature (constant-time compare)
- Reject if older than 5 minutes (prevent replay)

Retention & exports:
- Raw meter events: 12 months (extendable)
- Daily reconciliation exports: CSV and line-item JSON per AWS customer id
- Report fields: meter_id, timestamp_utc, quantity, entitlement_id, internal_request_id, signature
