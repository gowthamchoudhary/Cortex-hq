Stephanie (+ team) —

We had a couple of near-misses this week where an AE task fired from a PLG signal on an account that also has an active CSM motion (Dedicated customer w/ a self-serve workspace spun up by a new team). I want to lock down guardrails for the NA pilot so we don’t create a “two Redwoods” experience.

Proposed rules (v1) for signal-triggered outreach:

1) If Company has an active CSM owner (paid Dedicated/Private OR Enterprise hosted plan), CSM is primary. Sales does not send first-touch until CSM acknowledges or opts out.
   - In HubSpot: if “CSM Owner” is populated and “Customer Status = Active”, auto-create a CS task + internal note to CSM instead of AE/SDR task.

2) If Company is self-serve paid (card) with no CSM, AE/SDR can run playbook, but should check for open Support escalations first.
   - If there’s an open Sev2+ / ongoing reliability incident: suppress outbound and route to CS/Support.

3) For expansions (new team/workspace invites spike, new API keys, new region): we should loop in the existing CSM within 24 hours.
   - Goal is coordinated outreach (e.g., one email thread, not parallel pings).

4) “Compliance intent” signals (security FAQ, SOC2 doc views, VPC/private docs): treat as high-sensitivity.
   - CSM + SE should be tagged on the HubSpot note by default if there’s an existing customer relationship.

5) Customer preference: if customer has asked “no sales outreach” or we’ve marked them as “do not contact” for GTM, signals should not create tasks.

If you’re aligned, Isabelle can help translate into concrete HubSpot workflow rules. I can draft a short one-pager for CSMs: how to triage signal notes + what to do if Sales is already engaged.

Can we confirm:
- what property we’ll treat as canonical for “active customer” (Customer Status? Billing plan?)
- what the expected SLA is for a CSM “acknowledge/opt out” so Sales isn’t blocked indefinitely

Yes — here’s a concrete proposal for HubSpot logic (no promises until I confirm with David, but this is workable):

Canonical fields:
- Customer Status (enum): Prospect / Self-serve paid / Active customer / Churned
- CSM Owner (user)
- Primary Sales Owner (user)
- Open Support Escalation (boolean) — we can sync a daily flag from Support/Jira as MVP
- Do Not Contact (boolean)
- PLG Signal: Last Qualified At (datetime)
- PLG Signal: Last Qualified Type (string)
- PLG Signal: CS Acknowledged At (datetime)

Workflow:
1) On new Qualified Signal:
   a) If Do Not Contact = true => create internal note only (no task)
   b) Else if Open Support Escalation = true => task to CSM Owner (if exists) else to Support liaison queue (we can decide owner)
   c) Else if Customer Status = Active customer AND CSM Owner is known => create task for CSM Owner (“Review PLG expansion signal”), set PLG Signal: CS Acknowledged At blank, and add internal note tagging Sales Owner
   d) Else => create task for Primary Sales Owner (or round-robin if blank)

2) Escalation step:
- If (Customer Status = Active customer) and task not completed and PLG Signal: CS Acknowledged At still blank after 1 business day => create task for Primary Sales Owner with subject “CSM unresponsive — send coordinated note, cc CSM”

Ask: Jasmine, do you want CSMs to explicitly set CS Acknowledged At via a checkbox/button? HubSpot doesn’t do “button” great, but we can use a property update.

Also: Tyler — we should ensure Marketing suppresses any lifecycle email for 7 days once a sales task is created, otherwise we’ll keep stepping on each other.
