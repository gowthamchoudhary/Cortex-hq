Folks —

Quick read of the CSV and my recommended approach below. High-level: treat this as a memory-first deal with a cost-aware mid tier.

Proposal (short):
- Reserve mix: 55% H100 (memory-heavy pools), 30% A100 (general purpose), 15% L4 (high-concurrency, embedding/short-gen).
- Binning rules:
  - Long-context models (>= 4k tokens running full KV cache): H100 only — we need 80+GB device memory to avoid tiling and remote KV hits. Pin large checkpoints & enable 8-bit quant if model validated.
  - Mid-range generation (512-4096 tokens): A100 preferred — good throughput per dollar and larger batch headroom than L4. Use quantized FP16/INT8 where we have validation.
  - Embeddings & prompt-only APIs (<512 tokens, small batch latency-sensitive): L4 — very cheap per-token, minimal KV caching, great QPS.
- Fallback policy: slot-request routing by model tag + sequence-length heuristic: short requests -> L4; if L4 capacity saturated, route to A100 with strict token cap and lower max tokens; long-context always to H100; if H100 full, queue/backpressure with a fast-failover to A100 with degraded quality + explicit client signal.

Sizing heuristics (back-of-envelope):
- Using the provided QPS shape and assuming typical token-per-request: short-gen ~60 tokens, mid-gen ~220, long-gen ~2.8k tokens. Expected avg token/s ~= 1.2M tokens/s.
- Conservative concurrency headroom: assume 25% extra for burst and model warmups.
- Preliminary reserve counts (units):
  - H100: 18 GPUs (handles long-context at target p95 latency with room for 1.2x growth)
  - A100: 10 GPUs (handles mid-gen and overflow from L4)
  - L4: 8 GPUs (embeddings & short-gen)

Ops notes (for the playbook):
- KV cache & warm pool: pre-warm H100 slots for long-context flows; track warm-cache hit ratio by client-id.
- Quantization: validate 8-bit quality for the long-context models before pinning — saves 30-40% memory; document model/quant combos per sku.
- Autoscaling: prefer instant burst on A100/L4; H100 reserved and small burst window only.

I put the one-page summary in sku-reco-summary.pdf (attached). If we want formal cost numbers, Irene, can you run a reserve rate card + burst pricing calc?
