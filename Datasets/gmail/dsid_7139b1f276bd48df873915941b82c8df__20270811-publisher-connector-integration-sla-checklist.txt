Elena — thanks, appreciate the detail and the redline. Quick answers up front:
- Redistribution: we can support publisher-controlled gating. By default Redwood does not redistribute weights; we can bind access to Aurora-managed keys/ACLs or to Dedicated pools only.
- Embargo: 90-day embargo is workable; we'll add controls to prevent public catalog listing until a publisher toggle flips.
- Storage/KMS/HSM: Redwood Dedicated supports customer KMS keys (AWS KMS or customer-owned HSM). We'll include an integration checklist.
- Transfer integrity & retention: The S3 transfer spec looks good. We require a manifest.json with SHA256 checksums + object size. We hold raw uploads for 30 days in a quarantine bucket before moving to production storage.

Two operational notes before we call this pilot-ready:
1) Ingest SLA: for large checkpoints we recommend Bulk Ingest (asynchronous transfer job) — target SLA for manifest validation & quarantine validation is 48 hours for the pilot (can be tightened with reserved capacity).
2) Serving variant: publishers often want weights pinned to a non-public model id. We'll create a publisher-scoped model-id and a routing policy so only Aurora-authorized accounts can hit it.
