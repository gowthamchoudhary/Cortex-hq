Hi Anita — thanks for the trace and quick signal. We have a short mitigation playbook you can apply immediately; these are client-side and server-side options.

Customer mitigation (immediate, non-disruptive):
1) Reduce per-chunk token target to 12–20 tokens (client-side) — this reduces the runtime's need to re-batch at high variance.
2) Use exponential reconnect/backoff for streaming endpoints (initial 200ms, multiplier 1.5, max 5s).
3) If using SSE (text/event-stream), set a keepalive event every 8–10s as a heartbeat to avoid intermediate proxies closing connections.
4) As a temporary fallback, switch heavy user sessions to the poll endpoint (/v1/responses/poll) for 60–90s during peak bursts — poll has slightly higher latency but avoids token pacing anomalies.
