Irene / Maya / team — thanks for the notice. I reviewed the inventory and drafted initial redline guidance (attached: CB_subproc_redline_v1.docx). High level notes below — please treat as time-sensitive for consent staging:

1) Evidence before consent: We should request DataVault's SOC 2 Type II and a summary of encrypt-at-rest / key management controls. If they rely on a KMS that we need to review, ask for KMS architecture diagram and access controls.

2) Sub-subprocessors: MSA requires explicit flow-down for any downstream subcontractors. We should add a clause requiring CloudBridge to notify Redwood at least 30 days before onboarding any sub-subprocessor with a right-to-object window. The vendor's notice documents do not currently include that 30-day notification language.

3) Access to decrypted content: The inventory implies DataVault will not access decrypted customer content; confirm in writing. If they do have access, we should require narrower scoping or an exception only with Redwood's prior written consent.

4) DPA amendment: We will likely need a short DPA addendum referencing the new subprocessor and a representation that flow-down obligations (security, breach notification, deletion) are enforceable. If CloudBridge prefers DocuSign, we can execute an amendment that references the order form / DPA.

5) Evidence preservation: Request 12 months of logs for access to keys and administrative operations, with retention details (who holds logs, where stored).

I attached a marked-up MSA excerpt and a proposed 30-day notification clause in CB_subproc_redline_v1.docx. Once we receive SOC2 and the requested diagrams we can fast-track to DocuSign.
