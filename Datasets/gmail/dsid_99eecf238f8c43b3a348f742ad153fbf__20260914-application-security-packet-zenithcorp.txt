Rachel — thanks, looping in technical answers inline below (please see attachments for artifacts). I'm keeping answers concise; happy to expand on any point.

--- Question: SAST/DAST tooling and cadence ---
SAST: We run scheduled SAST scans on all production-bound components and container images via a CI gate (dependent code + infra-as-code). Frequency: nightly incremental scans + full scans on each release branch. Tooling: a combination of static analyzers (open-source + commercial plugins) with results ingested into our vulnerability tracker (Jira). Artifact: sast-dast-matrix.csv (attached) lists scanners, rule sets, and false-positive tuning.

DAST: We run DAST for web-facing endpoints weekly against staging environments that mirror production network policies. Full DAST runs occur before major releases and after significant authentication or session-management changes. We use authenticated crawling, credentialed scans, and a custom harness to reduce noisy results.

--- Question: Pen test summary ---
Most recent third-party pen test: May 2026 (redacted executive summary attached: pentest-summary-202605-redacted.pdf). Scope: platform control plane, hosted API endpoints, tenant isolation controls, and the web console. Findings: no critical unauthenticated RCEs discovered; one high-impact auth bypass (CWE-285 class) remediated within our SLA window (see patch SLA below). The full report remains under NDA; we provide an executive summary and remediation timeline for procurement reviews.

--- Question: SBOM generation and format ---
We generate SBOMs per build using SPDX 2.2 JSON output. The sbom-export-202608.json contains package-level identifiers and versions; we redact direct download URLs and license text for vendor distribution. We can provide more granular SBOMs under an NDA.

--- Question: Patch SLA and vulnerability triage ---
Severity mapping and target SLA (typical):
- Critical (exploitation likely, active exploit): remediation and customer-impact mitigation plan within 24 hours; full fix or compensating control in 7 calendar days.
- High: remediation plan within 72 hours; target fix within 14 calendar days with regression checks.
- Medium: prioritized in next sprint (30 days typical).
- Low: tracked for scheduled maintenance.
We operate a 24/7 security on-call rotation for triage. All high/critical findings receive an internal RCA and communication to affected customers when there is potential impact to tenant isolation or data confidentiality.

--- Question: 3rd-party dependencies and monitoring ---
We monitor for dependency CVEs via automated feeds (OSS advisory feeds + commercial feeds), correlate with our SBOM, and prioritize patches based on exposure and exploitability. Where vendor patching is required, we coordinate timelines and provide mitigations.
